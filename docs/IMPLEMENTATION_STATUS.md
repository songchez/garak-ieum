# 구현 상태

2026-11-03 (KST) · 가락이음 0.1.0 개발 프리뷰

이 문서는 현재 소스에 연결된 기능과 이번에 실행한 검증을 기록합니다. [상호작용 명세](INTERACTION_SPEC.md)와 [Logic 비교 명세](LOGIC_GAP.md)는 구현 목표도 포함하므로, 그 문서의 항목이 모두 완성됐다는 뜻은 아닙니다.

현재 문서는 기존 테마·공통 명령/MCP·모듈형 이펙트·단선율 피치 편집기에 이어 **음계 보정·실험적 포먼트 도구·전역 Space와 로고 메뉴**, **URL 기반 프로젝트 목록·국악 샘플 3종**, **인접 리전 경계·확대 그리드·비파괴 MIDI 트림·수동 루프·편집 패널 조절**을 포함합니다. 아래에는 현재 코드의 범위와 각 패스 당시의 실행 기록을 구분했습니다. 실제 Logic/Melodyne 앱과의 기능·음질 동등성이나 실기기 검증 완료를 뜻하지 않습니다.

## 피아노롤 방향키·마우스 이동 보완 (2026-11-03 KST)

확대 격자는 1/64음표까지 표시하지만 기본 편집 스냅은 1/16음표여서 음표가 화면상 네 칸씩 움직이던 문제를 수정합니다. 사용자 요청에 따라 키보드의 단계 이동과 마우스의 자유 편집을 분리했습니다.

- **방향키:** 선택한 음표는 수식키 없는 좌우 방향키로 현재 표시 격자 한 칸씩, 위아래로 반음씩 움직입니다. 드럼은 표시된 패드 한 행씩 이동합니다. 자유 배치한 음표의 미세한 오프셋과 다중 선택의 간격을 유지하며, 리전·음높이 경계에서 제한합니다. 선택이 없으면 이동하지 않습니다.
- **마우스:** 기본값은 자유 이동입니다. 음표 생성·이동·좌우 길이 편집이 격자와 경계 자석 스냅을 적용하지 않고 포인터의 가로 위치를 따릅니다. 명시적으로 스냅 값을 선택하면 해당 단위를 사용합니다. Cmd/Ctrl+G는 자유 이동과 마지막 스냅을 전환하며 최초 스냅은 1/16음표입니다.
- **단위 구분:** 좌우 방향키는 마우스 스냅과 무관하게 `musicalGrid.stepBeats`를 사용합니다. 확대하면 방향키도 세밀해집니다. Q/Shift+Q는 명시적인 퀀타이즈로 유지하고, 자유 이동 중에는 기존 1/16음표 기준을 사용합니다.
- **기존 조작:** Alt+방향키 편집, Alt+Shift 길이·옥타브, Shift+방향키 선택 확장, 입력 필드·IME·모달·컨트롤 방향키 보호를 유지합니다. 타임라인의 일반 방향키 선택 동작은 유지하며 도움말에서 적용 영역을 구분합니다.

검증: 전체 **46개 파일 / 764개 테스트**, `tsc -b --pretty false`, `vite build`, `git diff --check`를 통과했습니다. 자유 모드의 소수 박 위치 생성·이동·양끝 리사이즈, 확대별 한 칸 이동, 오프셋·다중 선택 간격 보존, 영역별 방향키 명령과 입력 보호를 회귀로 확인했습니다. 실제 브라우저의 포인터 조작 체감은 이번 환경에서 확인하지 못했습니다. 이번 변경으로 프로젝트 스키마는 바뀌지 않습니다.

## 리전 편집 사용성 패스 (2026-11-03 KST)

- **맞닿는 경계:** 타임라인 리전의 폭 `−2px`와 피아노롤 음표의 시작 `+1px`/폭 `−2px` 여백을 제거했습니다. `musicalSpan`으로 실제 시작·끝을 그리며 얇은 테두리로 구분합니다. 파형·MIDI 미리보기의 내부 테두리도 시간축을 압축하지 않게 맞췄습니다.
- **확대 그리드:** `musicalGrid`를 타임라인·피아노롤·눈금자에 공유합니다. 마디/박/세부 분할의 위계를 유지하며 확대 시 1/32·1/64 수준과 셋잇단 분할까지 드러납니다. 반복 CSS 격자와 보이는 범위의 최대 512개 눈금자 표시를 사용합니다. 실제 선택한 스냅 단위는 유지합니다.
- **경계 맞춤:** 이동·좌우 트림에서 가까운 리전 또는 같은 음높이의 음표 경계를 6px 안에서 맞추고 정렬선을 표시합니다. Alt 복사에서는 남아 있는 원본의 경계에도 맞춥니다. Snap Off·정밀 수정키의 no-snap은 경계 맞춤도 끕니다. 다중 선택의 간격과 세로 트랙 이동만 할 때의 원래 타이밍을 유지합니다.
- **원본 보존:** MIDI 왼쪽 트림과 분할은 `sourceOffsetBeats`를 사용합니다. 피아노롤의 보이는 구간 수정은 숨은 음표에 병합됩니다. 피치/벨로시티만 바꿀 때 숨은 앞뒤 길이도 유지합니다. 명시적인 시간 이동·경계 편집은 해당 경계를 변경하고, 합치기는 보이는 음표를 새 소스로 만듭니다. 이전 버전에서 이미 삭제한 음표를 복원하는 기능은 아닙니다.
- **파형 구간:** 타임라인/트림 미리보기/하단 오디오 편집기는 소스 오프셋·표시 길이를 사용합니다. 가까운 확대는 처리량 한도 안에서 실제 샘플을 읽습니다. 소스 끝의 빈 공간과 마지막 일부 루프를 늘려 그리지 않습니다.
- **수동 반복:** `loopLengthBeats`는 리전 시작부터의 반복 전체 길이입니다. 끝 손잡이·미리보기·부분 반복 재생·복사/이동·저장을 연결했습니다. L/인스펙터로 껐다 켜면 마지막 수동 범위를 기억하며, 손잡이를 원본 끝까지 접으면 해제합니다.

- **표시 범위:** 음표 4096개 한도로 트림 경계 분할이 불가능하면 해당 경계 음표는 읽기 전용입니다. 보이지 않는 음표 부분을 바꾸지 않으며, 내부 음표는 계속 편집할 수 있습니다. 다른 음표를 합쳐 공간을 확보하면 다시 경계를 분리합니다.

## 이전 피치 편집·디바이스 모듈화 (2026-11-02)

첫 단선율 피치 편집기는 원본 음원을 직접 덮어쓰지 않습니다. 분석과 음표별 이동 명세를 별도로 저장하고, 실제 렌더를 완료한 후 새 재생 자산을 프로젝트 Undo 한 단계로 반영합니다. 음표 범위 밖 샘플과 전체 프레임 수를 보존하며, 적용한 결과를 재생·일반 WAV 출력·`.garak` 복원이 함께 사용합니다.

- **모듈:** EQ·필터·컴프레서·드라이브·딜레이·리버브 각각의 메타데이터·DSP·잔향 계산. 카탈로그는 하나의 registry에서 가져옵니다.
- **편집:** 실제 분석 곡선과 음표 블록, 다중 선택, 반음/센트 이동, 가운데 분할과 동일 이동값의 인접 음표 합치기, 원본 복원.
- **보관:** 원본 ID/SHA-256·고정 YIN 분석·독립 음표 경계·센트 이동·렌더러 버전·별도 float WAV. 프로젝트 스키마 3, 구버전 1·2 마이그레이션.
- **작업 보호:** Worker 취소, 적용 전 원본/세션/revision 확인, 디코딩 중 취소 확인, 미적용 초안 안내와 브라우저 이탈 경고, 피치 작업 중 MCP 변경 차단.

## 공통 명령 계층과 MCP (2026-11-02)

`ProjectSession`이 UI와 MCP의 프로젝트·이력을 함께 소유합니다. 기존 UI의 450ms 입력 병합과 최대 50개 Undo, 녹음 대기·모니터링의 현재 라이브 상태 보존을 유지합니다. 외부 명령은 모든 항목을 먼저 검증해 한 번에 적용하고, 한 항목이 실패하면 전체를 적용하지 않습니다. 프로젝트 ID·revision과 작업 ID를 확인하며 생성된 트랙·리전은 일반 MIDI 편집 데이터입니다.

Node 서버는 loopback에서만 브리지를 열고, 허용한 앱 Origin·연결 키·탭 ID를 검증합니다. 브라우저가 실제 명령을 처리한 결과를 반환하며, 편집 적용과 IndexedDB 저장 완료를 별도로 보고합니다. 녹음·준비·파일 처리·다른 대화상자·진행 중 드래그/입력에서는 AI 쓰기를 차단합니다. 연결 UI는 로고 메뉴에 추가했고 48px 헤더를 유지합니다.

### 진입·적용·저장

기존 기와를 포함한 **48px 헤더**를 유지하고 로고 메뉴에 **설정…**, 하단 오디오 상태에 설정 버튼을 연결했습니다. `⌘,`/`Ctrl+,`는 이름·검색 같은 입력 필드와 일반 버튼에서도 사용할 수 있는 앱 명령입니다. 다른 모달이 열려 있으면 새 설정 창을 열지 않습니다. 설정 창은 키보드 포커스를 내부로 이동·순환시키며, 일반 작업 화면의 텍스트 선택 제한에서 입력·진단·오류 문구를 예외 처리합니다.

선택 변경은 초안입니다. 적용은 재생을 일시 정지하고, 필요한 활성 입력 변경을 준비한 뒤 후보 오디오 컨텍스트를 구성하고 입력을 확정합니다. 성공한 뒤에만 로컬 설정과 프로젝트 레이트를 반영합니다. 실패하면 준비 자원을 정리하고 기존 경로를 보존·복구합니다. 복구까지 실패하면 모니터링을 중지하고 오류를 알립니다. 설정이 `localStorage`에 저장되지 못한 경우에는 현재 세션에만 적용됐다고 알립니다.

취소·Escape·닫기는 미적용 초안만 버립니다. 이미 성공한 적용은 되돌리지 않습니다. 적용 중 중복 동작과 닫기를 막으며, 녹음·녹음 준비·파일 처리 중에는 적용을 차단합니다. 프로젝트 샘플레이트 변경은 한 번의 프로젝트 편집으로 commit합니다. 녹음·녹음 준비 중 레이트를 바꾸는 Undo/Redo도 차단하지만, 장치 설정 자체는 프로젝트 이력에 들어가지 않습니다.

### 장치·테스트·오류 처리

- 설정 창을 열거나 목록을 새로고침할 때 `enumerateDevices()`만 사용합니다. 마이크 권한은 명시적인 접근 허용·테스트·녹음·모니터링 조작에서 요청합니다. 활성 모니터링이 없는 상태에서 장치 초안이나 설정을 저장하려고 마이크를 강제로 열지 않습니다.
- 특정 입력은 `deviceId: { exact: id }`로 요청합니다. 사용할 수 없는 선택 장치를 다른 마이크로 조용히 대체하지 않습니다. 입력 종료·권한 오류는 알림으로 안내하고 모니터링 연결을 정리합니다. 활성 입력과 테스트 상태는 진단에서 확인합니다.
- 입력 테스트는 **현재 초안의 입력 조건**으로 레벨을 읽으며 스피커와 연결하지 않습니다. 테스트·장치 목록 확인의 임시 입력은 `AudioDeviceProbe`가 관리하고, 기존 녹음·모니터링의 `InputCapture`를 종료하지 않습니다. 닫기·취소 뒤 늦게 허용된 불필요한 입력도 정리합니다.
- 출력 테스트는 **현재 적용된 출력**에 짧은 테스트음을 재생합니다. 중지·창 닫기·출력 관련 초안 변경·적용·실제 출력 전환·오류에서 테스트만 취소합니다. 프로젝트의 공유 컨텍스트를 테스트 종료 때문에 닫지 않습니다.
- 출력 장치 API가 지원될 때만 선택을 활성화합니다. 별도의 `selectAudioOutput()`을 지원하면 사용자 버튼에서 권한과 장치를 선택합니다. 저장된 ID를 현재 연결 성공으로 취급하지 않습니다.
- 브라우저가 출력 변경/오류를 보고했을 때 특정 출력의 ID를 확인할 수 없거나 실제 출력이 달라지면 재생과 모니터링 출력을 중지합니다. **선택한 ID는 보존**하고 기본 출력으로 자동 전환하지 않습니다. 장치·권한을 확인해 같은 설정을 재적용하거나 사용자가 시스템 기본 출력을 직접 선택해야 합니다. 브라우저가 장치 정보를 제한한 경우에는 물리 분리라고 단정하지 않습니다.

### 요청값과 실제값·지원 경계

`latencyHint`는 낮은 지연·균형·재생 전력 효율의 요청입니다. 지원 시 `renderSizeHint`를 브라우저 기본/장치에 맞춤/32~1024 프레임 중 선택할 수 있지만 **하드웨어 I/O 버퍼를 제어하지 않습니다.** 실제 렌더 블록, 엔진 레이트, `baseLatency`·`outputLatency`를 따로 읽고, 값이 없거나 렌더 블록이 아직 확정되지 않았으면 확인되지 않았다고 표시합니다. 지연 표시는 출력 경로의 보고값이며 왕복 실측값이 아닙니다.

입력 채널 수는 장치 기본/1/2 요청이고 물리 Input 1/2 라우팅이 아닙니다. 에코 제거·노이즈 억제·자동 입력 레벨은 브라우저의 지원 여부에 따라 요청하며, 실제 값은 `MediaStreamTrack.getSettings()`로 표시합니다. 음악 녹음의 기본 요청은 이 처리들을 끔입니다. 미보고 값을 끔이나 0으로 추정하지 않습니다. 프로젝트/엔진 레이트를 물리 장치 클럭과 동일하다고 설명하지 않습니다.

녹음 위치 보정은 **-1000~1000ms 정수**를 새 녹음 시작 시 읽습니다. 양수는 뒤로, 음수는 앞으로 배치하며, 0 이전 구간은 원본을 재작성하지 않고 `offsetSeconds`로 제외합니다. 전체가 프로젝트 시작 이전에 놓이면 빈 리전을 만들지 않고 알립니다. 기존 리전은 바꾸지 않습니다. 자동 왕복 측정이나 입력·인코더 지연 보상 기능은 아닙니다.

녹음 원본은 `MediaRecorder`가 지원하는 WebM/MP4/Ogg 등의 코덱 경로이고 WAV 출력은 스테레오 PCM 16-bit입니다. 하드웨어 버퍼·프리앰프 게인·팬텀 파워·직접 모니터링·클럭 소스·물리 다중 I/O·플러그인 지연 보상·24/32-bit PCM 녹음/출력은 구현하지 않았습니다.

## 작업 화면의 텍스트 선택 (2026-11-02)

작업 화면의 일반 글자는 브라우저 텍스트 선택을 기본으로 막습니다. 헤더·메뉴·버튼·트랙/리전 라벨·편집기·믹서의 드래그가 글자 선택을 만들지 않도록 `user-select`와 WebKit 접두사를 적용합니다.

예외는 이름·검색·BPM 등 텍스트/숫자 입력, 텍스트 영역, 편집 가능한 내용, 복사할 오류·알림·단축키 안내·출처/라이선스입니다. 드래그로 값을 조절하는 인스펙터 필드는 직접 입력 상태에서만 텍스트 선택을 허용합니다.

복사 가능한 안내는 `data-selectable-text`와 키보드 포커스를 명시하고 입력 단축키 범위로 처리합니다. 오류 문구를 드래그해 선택한 뒤 Ctrl/⌘C를 눌렀을 때 리전·음표 복사 명령이 가로채지 않도록 합니다. 디바이스 랙의 포커스 이동도 해당 영역을 제외합니다. CSS 선택 정책을 사용하며 리전·음표 이동, 트림, 범위 선택, 노브/페이더의 포인터 제스처 처리에는 전역 차단을 추가하지 않습니다.

텍스트 선택 변경 당시(`5ef5df3`) `pnpm build`와 기존 `src/core/input.test.ts`가 통과했습니다. 이 기록은 현재 오디오 설정 추가 전의 결과입니다. 테스트는 단축키 판정·범위 계산을 확인하며 실제 브라우저 선택·클립보드를 검증한 것은 아닙니다. 브라우저에서 일반 라벨 드래그, 이름 편집·숫자 직접 입력, 인스펙터 값 드래그, 오류/출처 선택 후 복사는 추가 확인 대상입니다. 실제 화면 검증은 개발 서버 연결 제한으로 남아 있습니다.

## 상단 바 통합 (2026-11-02)

로고·프로젝트 이름과 재생·정지·녹음 컨트롤을 **한 줄로 합쳤습니다.** `Transport`를 `App.tsx`의 헤더 내부로 옮기고 독립 재생 바의 높이·배경·테두리·빈 공간 요소를 제거했습니다. 왼쪽 브랜드·프로젝트 정보, 가운데 재생·시간·BPM, 오른쪽 파일 작업을 배치합니다.

전체 높이는 기와 8px를 포함한 **48px**입니다. 원래 두 줄의 기본 CSS 합계 122px에서 74px, 첫 축소안의 82px에서 34px 더 줄어듭니다. 상단 로고 20px, 워드마크 높이 18px와 기존 기와 SVG·브랜드 자산·색상을 유지합니다.

주요 버튼은 높이 28px입니다. 좁은 창에서도 Undo/Redo와 핵심 재생 버튼, 프로젝트 이름·저장 상태 문구, 새 프로젝트·열기·저장·내보내기를 남깁니다. 파일 버튼 텍스트와 보조 표시를 폭별로 줄이되 상단 바를 두 줄로 감싸지 않습니다. 작업 중 알림 위치도 단일 헤더 높이로 계산합니다. 반응형 정책과 화면 확인 조건은 [브랜드 문서](BRAND.md#작업-화면의-상단-밀도)에 있습니다.

헤더 통합 당시(`6c72819`) `pnpm build`(TypeScript 검사 + Vite 프로덕션 빌드)와 diff 형식 검사를 통과했습니다. 검증 브라우저의 개발 서버 연결이 거부되거나 차단되어 실제 화면·클릭·반응형 실측은 남아 있습니다. 아래 이전 테스트 기록은 앞선 리전·오디오 패스의 결과이며 헤더나 새 오디오 설정의 화면 검증을 대신하지 않습니다.

## 이전 리전·피치 패스에서 보완한 내용

### 리전 표시

- 루프 반복 블록에 원본 제목과 MIDI 노트/오디오 파형 미리보기를 표시합니다. 반복마다 위·아래 노치를 표시하며, 마지막 부분 반복은 원래 미리보기 배율을 유지한 채 잘라 표시합니다.
- 반복 범위는 엔진과 같은 `clipOccurrences`를 사용합니다. 다음 리전은 뮤트 상태여도 반복의 경계이며, 다음 리전이 없으면 프로젝트 끝까지 반복합니다.
- 이동·복사·트림 중에는 임시 트랙 배치(`previewRegionTracks`)로 반복 범위를 계산합니다. 선택한 여러 리전과 이동 대상 트랙의 경계도 반영하며 프로젝트·Undo 이력에는 임시 배치를 저장하지 않습니다.
- 뮤트한 리전에는 작은 점과 회색 표시를 적용합니다. 트랙 뮤트·다른 트랙의 솔로·트랙 꺼짐도 원본과 반복 블록에 반영합니다. Canvas 파형에도 상태별 색을 명시적으로 전달합니다.
- 이름의 `(+12)`·`(-3)` 접미사는 리전 자체의 `transpose`만 보여줍니다. 트랙 이조까지 더해 인스펙터의 리전 값과 달라지던 표시를 수정했습니다.
- 반복 블록을 누르면 원본 리전에 키보드 포커스를 둡니다. 그 뒤 Delete 등은 타임라인 범위에서 처리됩니다. 기존 선택·수식키·드래그 처리 경로를 유지합니다.
- 반복 블록 드래그의 포인터 캡처도 원본 리전에 둡니다. 이동 중 마지막 반복 블록이 사라져도 제스처가 취소되지 않습니다.
- 다중 선택 왼쪽 트림은 `trimClipStarts`로 모든 리전을 한 번에 변경한 뒤 겹침 처리를 한 번 적용합니다. 같은 렌더 시점의 상태를 반복 덮어써 마지막 리전만 남던 경로를 수정하고, 한 번의 편집 이력으로 확정합니다.

관련 소스: `TimelineClip.tsx`, `TimelineClip.css`, `Timeline.tsx`, `core/regionDisplay.ts`.

### 피치 표기

인스펙터와 피아노롤의 건반·음표·툴팁·접근성 이름을 **MIDI 60 = C3**으로 통일했습니다. 전체 범위는 **C-2 = 0 ~ G8 = 127**이며 샤프는 `♯`로 표시합니다. 숫자 MIDI와 `#`/`♯`/`b`/`♭` 입력을 받습니다.

공통 함수는 `core/pitch.ts`입니다. 이전 피아노롤에서 C4로 보이던 MIDI 60이 C3로 표시됩니다. MIDI 숫자, 실제 소리의 음높이, 샘플 파일명과 매니페스트의 기준은 그대로입니다.

### 입력 모니터링·녹음 준비

`audio/InputCapture.ts`가 모니터링과 녹음의 입력 사용 상태를 관리합니다.

- I를 끄거나 녹음 준비를 취소한 뒤 늦게 허용된 마이크 스트림을 정리합니다.
- 모니터링과 녹음 준비가 겹치면 하나의 권한 요청·스트림을 공유하며, 한쪽을 껐다는 이유로 다른 쪽의 입력을 끊지 않습니다.
- 녹음 준비 중 중복 시작을 막고, Stop 또는 페이지 이탈로 취소한 준비가 늦은 권한 응답 때문에 다시 시작되지 않도록 합니다.
- 앱 해제 시 녹음기·모니터링 연결·스트림을 정리합니다. 오래된 비동기 응답은 새 요청의 상태를 덮어쓰지 않습니다.
- 권한 거부 후 새 시도를 허용합니다. 실제 마이크 지연·음질은 별도 장치 검증 대상입니다.

- 수동 루프 끝점, 작은 리전의 손잡이 구역, 정밀 스냅·축 제한, No Overlap의 주변 리전 변경 미리보기, 혼합 유형 Paste의 부분 누락·선택 복구를 다음 사용성 작업으로 정리했습니다.

기존 취소·포인터 캡처·자동 스크롤·그룹 이동과 뒤 오디오 리전 우선 재생은 구현돼 있습니다. 새 작업은 이 기반을 유지하며 위 차이를 해결합니다.
