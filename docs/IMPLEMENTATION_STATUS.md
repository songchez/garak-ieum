## 작업 화면의 텍스트 선택 (2026-11-02)

작업 화면의 일반 글자는 브라우저 텍스트 선택을 기본으로 막습니다. 헤더·메뉴·버튼·트랙/리전 라벨·편집기·믹서의 드래그가 글자 선택을 만들지 않도록 `user-select`와 WebKit 접두사를 적용합니다.

예외는 이름·검색·BPM 등 텍스트/숫자 입력, 텍스트 영역, 편집 가능한 내용, 복사할 오류·알림·단축키 안내·출처/라이선스입니다. 드래그로 값을 조절하는 인스펙터 필드는 직접 입력 상태에서만 텍스트 선택을 허용합니다.

복사 가능한 안내는 `data-selectable-text`와 키보드 포커스를 명시하고 입력 단축키 범위로 처리합니다. 오류 문구를 드래그해 선택한 뒤 Ctrl/⌘C를 눌렀을 때 리전·음표 복사 명령이 가로채지 않도록 합니다. 디바이스 랙의 포커스 이동도 해당 영역을 제외합니다. CSS 선택 정책을 사용하며 리전·음표 이동, 트림, 범위 선택, 노브/페이더의 포인터 제스처 처리에는 전역 차단을 추가하지 않습니다.

`pnpm build`와 기존 `src/core/input.test.ts`의 103개 테스트가 통과했습니다. 테스트는 단축키 판정·범위 계산을 확인하며 실제 브라우저 선택·클립보드를 검증한 것은 아닙니다. 브라우저에서 일반 라벨 드래그, 이름 편집·숫자 직접 입력, 인스펙터 값 드래그, 오류/출처 선택 후 복사는 추가 확인 대상입니다. 실제 화면 검증은 개발 서버 연결 제한으로 남아 있습니다.

## 상단 바 통합 (2026-11-02)

로고·프로젝트 이름과 재생·정지·녹음 컨트롤을 **한 줄로 합쳤습니다.** `Transport`를 `App.tsx`의 헤더 내부로 옮기고 독립 재생 바의 높이·배경·테두리·빈 공간 요소를 제거했습니다. 왼쪽 브랜드·프로젝트 정보, 가운데 재생·시간·BPM, 오른쪽 파일 작업을 배치합니다.

전체 높이는 기와 8px를 포함한 **48px**입니다. 원래 두 줄의 기본 CSS 합계 122px에서 74px, 첫 축소안의 82px에서 34px 더 줄어듭니다. 상단 로고 20px, 워드마크 높이 18px와 기존 기와 SVG·브랜드 자산·색상을 유지합니다.

주요 버튼은 높이 28px입니다. 좁은 창에서도 Undo/Redo와 핵심 재생 버튼, 프로젝트 이름·저장 상태 문구, 새 프로젝트·열기·저장·내보내기를 남깁니다. 파일 버튼 텍스트와 보조 표시를 폭별로 줄이되 상단 바를 두 줄로 감싸지 않습니다. 작업 중 알림 위치도 단일 헤더 높이로 계산합니다. 반응형 정책과 화면 확인 조건은 [브랜드 문서](BRAND.md#작업-화면의-상단-밀도)에 있습니다.

통합 후 `pnpm build`(TypeScript 검사 + Vite 프로덕션 빌드)와 diff 형식 검사를 통과했습니다. 검증 브라우저의 개발 서버 연결이 거부되거나 차단되어 실제 화면·클릭·반응형 실측은 남아 있습니다. 아래 306개 테스트 기록은 앞선 리전·오디오 패스의 결과이며 이번 헤더의 화면 검증을 대신하지 않습니다.

## 이번 패스에서 보완한 내용

### 리전 표시

- 루프 반복 블록에 원본 제목과 MIDI 노트/오디오 파형 미리보기를 표시합니다. 반복마다 위·아래 노치를 표시하며, 마지막 부분 반복은 원래 미리보기 배율을 유지한 채 잘라 표시합니다.
- 반복 범위는 엔진과 같은 `clipOccurrences`를 사용합니다. 다음 리전은 뮤트 상태여도 반복의 경계이며, 다음 리전이 없으면 프로젝트 끝까지 반복합니다.
- 이동·복사·트림 중에는 임시 트랙 배치(`previewRegionTracks`)로 반복 범위를 계산합니다. 선택한 여러 리전과 이동 대상 트랙의 경계도 반영하며 프로젝트·Undo 이력에는 임시 배치를 저장하지 않습니다.
- 뮤트한 리전에는 작은 점과 회색 표시를 적용합니다. 트랙 뮤트·다른 트랙의 솔로·트랙 꺼짐도 원본과 반복 블록에 반영합니다. Canvas 파형에도 상태별 색을 명시적으로 전달합니다.
- 이름의 `(+12)`·`(-3)` 접미사는 리전 자체의 `transpose`만 보여줍니다. 트랙 이조까지 더해 인스펙터의 리전 값과 달라지던 표시를 수정했습니다.
- 반복 블록을 누르면 원본 리전에 키보드 포커스를 둡니다. 그 뒤 Delete 등은 타임라인 범위에서 처리됩니다. 기존 선택·수식키·드래그 처리 경로를 유지합니다.
- 반복 블록 드래그의 포인터 캡처도 원본 리전에 둡니다. 이동 중 마지막 반복 블록이 사라져도 제스처가 취소되지 않습니다.
- 다중 선택 왼쪽 트림은 `trimClipStarts`로 모든 리전을 한 번에 변경한 뒤 겹침 처리를 한 번 적용합니다. 같은 렌더 시점의 상태를 반복 덮어써 마지막 리전만 남던 경로를 수정하고, 한 번의 편집 이력으로 확정합니다.

관련 소스: `TimelineClip.tsx`, `TimelineClip.css`, `Timeline.tsx`, `core/regionDisplay.ts`.

### 피치 표기

인스펙터와 피아노롤의 건반·음표·툴팁·접근성 이름을 **MIDI 60 = C3**으로 통일했습니다. 전체 범위는 **C-2 = 0 ~ G8 = 127**이며 샤프는 `♯`로 표시합니다. 숫자 MIDI와 `#`/`♯`/`b`/`♭` 입력을 받습니다.

공통 함수는 `core/pitch.ts`입니다. 이전 피아노롤에서 C4로 보이던 MIDI 60이 C3로 표시됩니다. MIDI 숫자, 실제 소리의 음높이, 샘플 파일명과 매니페스트의 기준은 그대로입니다.

### 입력 모니터링·녹음 준비

`audio/InputCapture.ts`가 모니터링과 녹음의 입력 사용 상태를 관리합니다.

- I를 끄거나 녹음 준비를 취소한 뒤 늦게 허용된 마이크 스트림을 정리합니다.
- 모니터링과 녹음 준비가 겹치면 하나의 권한 요청·스트림을 공유하며, 한쪽을 껐다는 이유로 다른 쪽의 입력을 끊지 않습니다.
- 녹음 준비 중 중복 시작을 막고, Stop 또는 페이지 이탈로 취소한 준비가 늦은 권한 응답 때문에 다시 시작되지 않도록 합니다.
- 앱 해제 시 녹음기·모니터링 연결·스트림을 정리합니다. 오래된 비동기 응답은 새 요청의 상태를 덮어쓰지 않습니다.
- 권한 거부 후 새 시도를 허용합니다. 실제 마이크 지연·음질은 별도 장치 검증 대상입니다.

## 장치에서 이어서 확인할 항목

개발 서버(`pnpm dev`)에서 데모 또는 별도 테스트 프로젝트로 확인합니다.

1. **리전 표시·트림**: MIDI 리전을 다른 리전과 간격을 두고 배치해 L을 켭니다. 반복 제목·음표·노치, 다음 리전 직전의 부분 반복, 프로젝트 끝 경계를 확인합니다. 오디오에서도 파형이 잘린 구간에서 압축되지 않는지 확인합니다. 마지막 반복 블록을 오른쪽으로 드래그해 그 블록이 사라진 뒤에도 이동을 계속할 수 있어야 합니다. 여러 리전의 왼쪽 트림은 모든 선택에 반영되고 Undo 한 번으로 함께 돌아가야 합니다.
2. **상태와 포커스**: 리전 뮤트, 트랙 M, 다른 트랙 S, 트랙 켬/끔을 바꾸며 원본과 반복 색을 확인합니다. 피아노롤을 클릭한 뒤 반복 블록을 선택해 Delete가 원본 리전에만 적용되는지 확인하고 Undo로 복원합니다.
3. **피치**: 인스펙터 키 제한과 피아노롤 MIDI 60이 모두 C3인지 확인합니다. 기존 프로젝트를 열었을 때 음 자체가 한 옥타브 바뀌지 않아야 합니다.
4. **퀀타이즈·스윙·루프 청취**: 그리드에서 조금 벗어난 음표로 퀀타이즈 끔/켬을 비교하고, Q-Swing 50과 66을 비교합니다. 다음 리전·사이클 경계에서 중복음·끊김이 있는지 듣습니다.
5. **입력 모니터링**: 헤드폰을 사용해 오디오 트랙 I의 켬/끔과 페이더·뮤트를 확인합니다. 권한 창 대기 중 I 끄기, 녹음 준비 중 Stop, 거부 후 재시도를 확인합니다. 모든 입력 사용을 끝내면 브라우저의 마이크 사용 표시도 종료되어야 합니다.
6. **플랫폼 입력**: macOS의 ⌃/⌘ 구분, Windows의 Alt+Shift 치환, 한글 IME·실제 트랙패드·수식키 드래그를 확인합니다.

## 리전 편집 사용성 감사 (2026-11-01)

`c3203092`의 소스를 Apple Mac용 설명서와 추가 대조했습니다. [벤치마크](REGION_EDITING_BENCHMARK.md)에 공식 규칙과 22개 실사용 시나리오, [코드 감사](REGION_EDITING_AUDIT.md)에 코드 근거·재현 조건을 기록했습니다. 이번 추가 조사는 문서 작업이며 기능 수정이나 새 화면·청음 검증 통과를 뜻하지 않습니다.

- MIDI 왼쪽 트림은 숨겨진 음표를 보존하지 않습니다. 비파괴 리전 구간 모델이 필요합니다.
- 오디오 파형은 현재 asset 전체 peaks를 그리므로 트림한 소스 offset/길이를 반영하지 않습니다. 이전의 마지막 루프 블록 잘라 표시와 구분되는 문제입니다.
- 현재 사각형 선택은 리전 전체 선택이며, 리전 일부를 편집하는 Logic Marquee 도구는 아닙니다.
- 수동 루프 끝점, 작은 리전의 손잡이 구역, 정밀 스냅·축 제한, No Overlap의 주변 리전 변경 미리보기, 혼합 유형 Paste의 부분 누락·선택 복구를 다음 사용성 작업으로 정리했습니다.

기존 취소·포인터 캡처·자동 스크롤·그룹 이동과 뒤 오디오 리전 우선 재생은 구현돼 있습니다. 새 작업은 이 기반을 유지하며 위 차이를 해결합니다.
