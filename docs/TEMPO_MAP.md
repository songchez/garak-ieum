# 템포 맵 (TEMPO_MAP)

곡 안에서 템포가 바뀌는 기능입니다. 프로젝트 스키마 14부터 `Project.tempoMap`으로 저장합니다.

## 1. 벤치마크

| 항목 | Logic Pro (Tempo 트랙) | Ableton Live (템포 오토메이션) | Cubase (Tempo Track) | 가락이음 |
|---|---|---|---|---|
| 위치 | 글로벌 트랙, 눈금자 아래 | 마스터 트랙의 Song Tempo 오토메이션 | 프로젝트 맨 위 Tempo Track | 글로벌 트랙 `템포` 행(G로 표시) |
| 포인트 만들기 | 클릭/더블클릭 | 오토메이션 점 클릭 | 연필 도구 | 빈 곳 더블클릭(그 위치·높이의 BPM), 헤더 `+` = 재생 위치 |
| 곡선 | 포인트마다 계단 또는 곡선(램프) | 점 사이 직선(점 사이 보간), 곡선 휘기 | Jump / Ramp | 포인트마다 `계단` / `램프` |
| 편집 | 드래그로 위치·BPM | 드래그 | 드래그 | 드래그(가로=위치, 세로=BPM, ⇧ 미세 위치, ⌥ 0.1 BPM), 우클릭·⌫ 삭제, R/메뉴로 계단↔램프 |
| LCD 템포 | 재생 위치의 템포, 편집하면 그 구간 포인트를 바꿈 | 현재 템포 표시 | Tempo 표시 | 헤더 BPM = 재생 위치의 템포, 편집하면 재생 위치 또는 그 앞의 포인트를 바꿈 |
| 오디오 | Flex 꺼진 리전은 절대 시간 유지, Flex 켜면 템포를 따름 | Warp 켠 클립만 템포를 따름 | Musical 모드 클립만 따름 | 워프 꺼짐 = 1배속(절대 시간), 워프 켬 = 리전 시작 위치의 템포로 렌더 |
| MIDI 파일 | 템포 이벤트를 템포 트랙으로 가져옴/내보냄 | 가져오기 시 초기 템포만 | 템포 트랙 가져옴/내보냄 | 템포 이벤트 → 템포 맵, 램프는 32분음표 계단으로 내보내고 다시 읽으면 램프로 복원 |

박자표 변경(Signature 트랙)은 [METER_MAP.md](METER_MAP.md)(스키마 18)에 있습니다. 박자는 4분음표를 마디로 묶을 뿐이라 템포 맵과 독립입니다.

## 2. 모델

```ts
interface TempoPoint { beat: number; bpm: number; curve: 'step' | 'ramp' }
Project.tempoMap?: TempoPoint[]   // 스키마 14
```

- 포인트는 박(4분음표) 위치 순으로 정렬하며, 첫 포인트는 항상 0박이고 `Project.bpm`과 같은 템포입니다. `Project.bpm`은 "0박의 템포"로 남아서 예전 코드·파일과 호환됩니다.
- `curve`는 **그 포인트 다음 구간**의 모양입니다. `step`은 다음 포인트까지 같은 템포, `ramp`는 다음 포인트의 템포까지 박 기준으로 직선 변화합니다. 마지막 포인트 뒤는 그 템포가 유지됩니다.
- 포인트가 하나뿐이면 맵을 저장하지 않습니다(`tempoMap` 없음 = 고정 템포). 템포 범위는 30–300 BPM입니다.
- 스키마 1–13 파일은 그대로 열리며 고정 템포입니다. 스키마 14 파일에서 첫 포인트가 0박/프로젝트 템포가 아니거나, 정렬·중복·곡선 값이 잘못되면 거부합니다.

## 3. 변환 모듈 하나

박 ↔ 시간 변환은 모두 [`src/core/tempoMap.ts`](../src/core/tempoMap.ts)의 `TempoMap`을 거칩니다. 네이티브는 같은 식을 [`native/include/garak/tempo.hpp`](../native/include/garak/tempo.hpp)로 옮겼습니다.

램프 구간 `bpm(b) = v0 + k·(b − b0)`의 시간은 정확한 적분으로 계산합니다.

- 박 → 초: `t = 60/k · ln(1 + k·Δb/v0)` (`log1p`)
- 초 → 박: `Δb = v0/k · (exp(k·t/60) − 1)` (`expm1`)
- 기울기가 0이면 일반 직선식입니다. 포인트마다 누적 초를 미리 계산하고 이진 탐색으로 구간을 찾습니다.

`tempoMapOf(project)`는 `tempoMap` 배열(프로젝트 스냅샷)마다 한 번만 컴파일해 캐시합니다. 클립 편집 함수(`splitClip`, `trimClipStart`, `joinClips`, 크로스페이드, `clipSeconds`, 녹음 배치 등)는 `Tempo = number | TempoMap`을 받으므로 고정 템포 숫자도 그대로 쓸 수 있습니다.

## 4. 어디에 쓰이는가

| 영역 | 동작 |
|---|---|
| Web Audio 재생 | `scheduleRange`가 모든 노트·오디오 시작/길이를 맵으로 계산. 스케줄러 구간 끝도 `beatAfter`로 구함 |
| 네이티브 재생 | UI가 타임라인을 컴파일할 때 노트·CC64·오디오 창·사이클·길이 프레임을 맵으로 계산(끝점마다 한 번 반올림). 타임라인에 `tempoMap`을 함께 보냄 |
| 오디오 리전 | 워프 꺼짐: 1배속 재생. 리전은 시작 박에서 시작해 끝 박에서 끝나고, 그 사이 실제 길이(초)는 맵이 정함. 분할·자르기 오프셋도 맵의 실제 초 |
| 워프 리전 | **리전 시작 위치의 템포**로 렌더합니다(`clipTempo`). 램프 안에서 리전 내부까지 다시 늘이지는 않습니다(구간별 렌더는 범위 밖). 리전을 다른 템포 구간으로 옮기면 그 템포로 다시 렌더 |
| 메트로놈 | 클릭 격자는 박 기준이라 그대로, 시각만 맵을 따름(웹 `scheduleSegment`, 네이티브 `metronome::Grid`). 카운트인은 재생 시작 위치의 템포로 고르게 |
| 재생 위치·시간 표시 | `positionAfter`(사이클은 실제 길이(초)로 감김), 헤더의 시:분:초, 네이티브 프레임 → 박 |
| 루프·내보내기 | 사이클 경계·내보내기 길이 모두 맵 기준. 웹 내보내기는 OfflineAudioContext를 템포가 바뀌는 지점마다 잠시 멈춰 동기 이펙트를 맞춤 |
| MIDI 녹음·캡처 | 타임스탬프 → 박(`heardTransportBeat`, `frameToBeat`, `compensatedBeat`), 정지 상태 캡처도 맵 |
| 동기 이펙트 | 딜레이(sync)·트레몰로(sync)는 재생 위치의 템포를 따름. 웹은 스케줄러가 0.05 BPM 이상 바뀌면 갱신, 네이티브는 블록마다 `setTempo` |
| VST3 | `ProcessContext`의 템포 = 블록 시작 위치의 템포, ppq/사이클 위치는 맵으로 계산 |
| MIDI 가져오기 | SMF 템포 이벤트 → 템포 맵(빈 프로젝트에 첫 파일일 때). 일정 간격으로 직선을 이루는 3개 이상의 계단은 램프 하나로 복원 |
| MIDI 내보내기 | 계단 = 템포 이벤트 하나. 램프 = 32분음표마다 계단, 각 계단은 그 구간의 정확한 평균 템포라 계단 경계 시각이 램프와 일치 |

## 5. 사용법

1. **G**(또는 트랙 영역 왼쪽 위 `G`)로 글로벌 트랙을 켭니다. `마커` 아래에 `템포` 행이 나옵니다.
2. 빈 곳을 더블클릭하면 그 위치(스냅)와 높이의 BPM으로 포인트가 생깁니다. 헤더 `+`는 재생 위치에 현재 템포로 만듭니다.
3. 포인트를 드래그해 위치와 BPM을 바꿉니다(⇧ = 1/16박 단위, ⌥ = 0.1 BPM 단위). 첫 포인트는 BPM만 바뀝니다. 클릭만 하면 그 위치로 이동합니다.
4. 포인트를 우클릭(또는 선택 후 R)해 `램프로 바꾸기`/`계단으로 바꾸기`, ⌫/Delete 또는 메뉴로 삭제합니다.
5. 헤더 BPM은 재생 위치의 템포를 보여 줍니다. 맵이 있을 때 값을 입력하면 재생 위치 또는 그 앞의 포인트가 바뀝니다.

모든 변경은 실행 취소 한 단계입니다(드래그는 놓을 때 한 번).
