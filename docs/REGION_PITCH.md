# 리전 피치 (오디오 리전 조옮김)

오디오 리전마다 피치를 반음·센트 단위로 옮기고, 그때 **템포를 유지할지(템포 유지)** 아니면
**테이프처럼 속도도 함께 바뀌게 할지(자연스럽게)** 고를 수 있습니다. 스키마 12에서 추가되었습니다.

## 1. 설계 원칙

(1) 반음과 미세 조정(센트)을 따로 둔다, (2) "템포 유지"와 "자연스럽게(속도 함께)"를 리전 단위로
고른다, (3) 자연스럽게 모드에서는 리전 길이가 비율만큼 변한다, (4) 원본은 비파괴로 보존한다.

## 2. 사용법

- **피치 배지**: 오디오 리전 이름 앞(W 템포 배지 옆)의 작은 배지. 조옮김된 리전에는 늘 `♪+3`
  (템포 유지) 또는 `~+3`(자연스럽게, 점선 테두리)으로 보이고, 조옮김이 없는 리전은 선택했을 때만
  `♪±0`으로 보입니다. 렌더링 중에는 배지가 깜빡입니다.
- 배지를 클릭하면 **리전 피치** 팝오버가 열립니다.
  - 반음: −/+ 버튼, −12/+12 버튼, 값 칸을 위아래로 드래그하거나 클릭해 입력(−24…+24).
  - 센트: 드래그/입력(−50…+50).
  - 모드: **템포 유지** / **자연스럽게**.
  - **포먼트 유지**: 템포 유지 모드에서만. 목소리의 음색(포먼트)이 피치를 따라 변하지 않게 합니다.
  - **초기화**: 0 반음 · 0 센트 · 템포 유지로 되돌립니다.
- **인스펙터**: 오디오 리전을 선택하면 리전 인스펙터에 같은 "피치" 칸이 있습니다(여러 리전 선택 시
  값이 다르면 `*` 표시).
- **우클릭 메뉴 → 피치 (+N)**: +1/−1 반음, +12/−12 반음, 템포 유지 / 자연스럽게, 피치 초기화.
- 여러 리전을 선택한 상태에서 바꾸면 선택한 모든 오디오 리전에 적용됩니다. 메뉴의 ±반음은 리전마다
  상대적으로, 팝오버의 값 입력은 모든 리전에 같은 값으로 들어갑니다.
- 모든 변경은 **실행 취소 한 단계**입니다(드래그는 한 번의 드래그가 한 단계). 렌더 완료로 오디오가
  바뀌는 것은 실행 취소 단계에 들어가지 않습니다.

## 3. 동작

| | 템포 유지 | 자연스럽게 |
| --- | --- | --- |
| 피치 | 2^(센트/1200) 배 | 2^(센트/1200) 배 |
| 속도 | 그대로 | 피치와 같은 비율 (rate = 2^(센트/1200)) |
| 리전 길이 / 루프 끝 | 그대로 | × 이전 rate / 새 rate (+12 → 절반, −12 → 두 배). 시작 위치는 그대로 |
| 소리 내용 | 같은 구간 | 같은 구간 (같은 원본 초를 더 빠르게/느리게) |
| 포먼트 유지 | 선택 가능 | 해당 없음(테이프처럼 함께 변함) |

- 페이드 길이, 리전 게인, 크로스페이드는 타임라인 초 단위 그대로입니다.
- 렌더는 오프라인입니다. 렌더가 끝날 때까지는 **이전 소리**(조옮김 전 또는 이전 설정의 렌더)로
  재생되며, 같은 원본·같은 설정의 리전들은 렌더 하나를 함께 씁니다(캐시). 원본 파일은 항상 보존됩니다.
- **워프와 함께**: 워프가 켜진 리전은 워프 비율과 조옮김을 **렌더 한 번**에 처리합니다. 프로젝트
  템포를 바꾸면 워프+피치 렌더를 다시 만듭니다. 워프를 켜거나 끌 때는 원본을 재생하다가 새 렌더로 바뀝니다.
- **WAV 내보내기**는 렌더된 오디오를 그대로 씁니다. 렌더링이 남아 있으면 "워프·리전 피치 렌더링이
  끝난 뒤 다시 내보내 주세요"라고 알리고 내보내지 않습니다.
- 웹과 데스크톱의 엔진 모두 렌더된 에셋을 일반 오디오처럼 재생하므로 두 환경의 결과가 같습니다.

## 4. 음표 피치 편집과의 관계

리전 피치와 음표 단위 피치 편집기(docs/PITCH_EDITOR.md)는 **함께 쓸 수 없습니다**(워프와 같은 규칙).

- 음표 피치 편집이 적용된 리전에는 피치 배지가 나타나지 않고, 인스펙터와 메뉴의 피치 항목이 비활성화되며
  "피치 편집을 초기화해 주세요"라는 안내가 보입니다.
- 리전 피치가 있는 리전을 선택하고 피치 편집기를 열면 "리전 피치를 초기화한 뒤 다시 열어 주세요"라는
  안내가 나오고, 적용 시에도 같은 이유로 거부됩니다.

이유: 피치 편집기는 원본과 같은 길이의 렌더를 전제로 음표 경계를 원본 초로 저장합니다. 그 위에 길이가
바뀌는 렌더(자연스럽게)나 워프를 얹으면 음표 경계와 렌더가 어긋나므로, 한쪽을 초기화한 뒤 쓰도록 했습니다.

## 5. 구현

- 데이터: `AudioClip.regionPitch?: { semitones, cents, mode: 'keep' | 'varispeed', formant?, originalAssetId, rendered? }`
  (`src/core/types.ts`). 없으면 0 반음 / 템포 유지. `rendered`는 현재 `assetId`에 실제로 들어 있는 조옮김
  (렌더러가 라이브 변경으로 설치). `offsetSeconds`는 워프처럼 현재 에셋의 초 단위입니다.
  자연스럽게 모드의 에셋 시간 비율은 `워프 비율 × 1/rate`이고, 렌더가 바뀔 때 `offsetSeconds`도 그 비율로 옮깁니다.
- 스키마 12 (`src/core/project.ts`): 11 이하 프로젝트는 그대로 열리고(조옮김 없음), 12 미만 파일에
  `regionPitch`가 있으면 거부합니다. 검증: 반음 정수 ±24, 센트 정수 ±50, 합계 ±24 반음, 모드, 렌더/에셋
  일관성(렌더 표시가 있으면 원본이 아닌 에셋, 없으면 원본), 워프와 같은 원본, 음표 피치 편집과 배타.
- 상태 처리: `src/devices/region-pitch/state.ts` (`setClipTranspose`, `transposeRate`, `assetScale`, 검증).
- 렌더 계획: `src/devices/audio-warp/renderPlan.ts`의 `RenderGroup`이 워프와 피치를 함께 기술합니다.
  `renderJob`: 템포 유지는 stretch = 워프 × p, 자연스럽게는 stretch = 워프, 그 다음 p 배 리샘플링
  (p = 2^(센트/1200)). 결과 길이 = 원본 × stretch / p.
- 렌더러: `src/devices/audio-warp/stretch.ts`의 `renderPcm` — 피치를 바꾸지 않는 Signalsmith Stretch(필요할
  때만)를 작은 링 버퍼로 흘려보내며 블랙먼 창 sinc 리샘플러(피치 편집기와 같은 커널)로 정확한 비율로
  리샘플링합니다. Signalsmith의 스펙트럼 직접 조옮김이 작은 이동에서 최대 10 센트 오차를 보였기 때문에
  (피치 편집기 측정) 이 방식을 택했습니다. 포먼트 유지는 Signalsmith 포먼트 이동(−반음)으로 리샘플링을
  상쇄합니다. 워커에서 실행(`client.renderInWorker`), `useWarpRenderer`가 캐시·정리·디바운스를 담당합니다.
- UI: `src/components/RegionPitchBadge.tsx`(배지, 팝오버, 인스펙터와 공유하는 컨트롤),
  `Timeline.tsx`의 리전 메뉴, `RegionInspector.tsx`, `App.tsx`의 `transposeClips`.

## 6. 측정 (브라우저, Web Audio, 440 Hz 2초 테스트 톤 → WAV 내보내기)

| 설정 | 측정 피치 | 소리 길이 |
| --- | --- | --- |
| 원본 | 440.000 Hz | 1.996 s |
| 템포 유지 +12 | 879.999 Hz | 1.993 s |
| 자연스럽게 +12 | 880.000 Hz | 0.996 s |
| 자연스럽게 −12 | 220.000 Hz | 3.996 s |
| 초기화 | 440.000 Hz | 1.996 s |

단위 테스트(`src/devices/region-pitch/*.test.ts`): 자연스럽게 ±반음 피치 오차 < 0.5 센트, 템포 유지
(+12, −5, +3.5, +0.5 반음) 및 워프 결합 렌더 오차 < 3 센트, 길이는 샘플 단위로 정확.

## 7. 남은 일

- 렌더 대기 중 파형은 이전 에셋 기준으로 그려집니다(길이는 즉시 바뀜).
- 렌더 진행률 표시는 배지 깜빡임과 인스펙터 문구뿐입니다.
- 실시간 varispeed(렌더 없이 재생 속도만 바꾸기)는 하지 않았습니다. 두 엔진의 오프셋·페이드·루프 계산을
  그대로 쓰기 위해 오프라인 리샘플 렌더로 통일했습니다.
