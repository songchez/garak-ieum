# 내장 기타 앰프

가락이음의 `guitar-rig` 디바이스는 입력 모니터링, 오디오 리전 재생, WAV 내보내기에 같은 신호 처리를 사용합니다. 별도 HTML이나 외부 플러그인을 띄우지 않고 기존 React 디바이스 랙, 프로젝트 상태, 실행 취소 기록, 오디오 엔진 안에서 동작합니다.

## 사용 방법

1. **트랙 추가 → 기타 → 생성**을 선택합니다. 기타 앰프가 연결된 오디오 트랙이 생깁니다. 기존 트랙에는 **디바이스 추가 → 기타 앰프**로 추가할 수 있습니다.
2. 디바이스 랙에서 기타 앰프 편집 화면을 엽니다.
3. 실제 기타를 연주하려면 오디오 인터페이스에 기타를 연결하고, 가락이음의 오디오 설정에서 입력·출력 장치를 선택합니다. 소프트웨어 모니터링과 트랙의 입력 모니터링을 켭니다. 트랙을 만들기만 해서는 마이크 권한을 요청하거나 입력을 켜지 않습니다.
4. 프리셋을 선택하거나 노브, 페달 스위치, 캐비닛·마이크 설정을 조절합니다. 입력 모니터링 중에는 헤드폰을 사용하고 인터페이스의 직접 모니터링과 이중으로 듣지 않도록 설정합니다.
5. 노브와 프리셋 설정은 프로젝트에 저장됩니다. 원본 녹음에는 이펙트를 덮어쓰지 않으므로 녹음 뒤에도 톤을 바꿀 수 있습니다. WAV 내보내기에는 현재 앰프 설정을 적용합니다.

## 신호 처리

디바이스 내부 순서는 **컴프 → 오버드라이브 → 앰프 → 캐비닛·마이크 → 코러스 → 딜레이**입니다. 각 모듈과 전체 디바이스를 각각 바이패스할 수 있습니다. UI의 페달 배치는 조작을 위한 묶음이며, 코러스와 딜레이는 앰프·캐비닛 처리 뒤에 위치합니다.

| 모듈 | 조절 항목 | 처리 방식 |
| --- | --- | --- |
| 컴프 | 서스테인, 어택(ms), 레벨(dB) | 미래 샘플을 기다리지 않는 인과적 엔벌로프 압축 |
| 오버드라이브 | 드라이브, 톤, 레벨 | 오버샘플링 비선형 처리와 톤 필터 |
| 앰프 | Clean / Crunch / Lead, 게인, 베이스, 미들, 트레블, 프레즌스, 마스터 | 프리앰프·톤·출력의 알고리즘 모델 |
| 캐비닛 | Compact / Open / Stack | 스피커 대역과 공진을 표현하는 필터 모델 |
| 마이크 | Dynamic / Ribbon / Condenser, 중앙–가장자리, 가까이–멀리 | 고역 지향성·저역 근접 효과 등을 표현하는 연속적인 필터 변화 |
| 코러스 | 속도, 깊이, 믹스 | 변조 지연 |
| 딜레이 | 시간(ms), 반복, 믹스 | 필터가 포함된 피드백 지연 |

캐비닛과 마이크는 **자체 알고리즘에 의한 음색 모델**입니다. 특정 제조사 장비의 회로 복각, 실측 임펄스 응답(IR), Neural Amp Modeler 캡처를 포함하지 않습니다. 마이크 위치·거리는 음색 조절값이며 실제 센티미터 측정치가 아닙니다. UI도 해당 방식으로 표시합니다.

## 프로젝트·자동화 통합

- 디바이스 ID는 `guitar-rig`입니다. 기존 `Device.params: Record<string, number>`에 29개의 수치형 설정을 저장합니다.
- 모든 기본값·범위·옵션은 [definition.ts](../src/devices/guitar-rig/definition.ts)에 정의합니다. UI, 프로젝트 검증, AI 명령 카탈로그가 같은 정의를 사용합니다.
- 기타 앰프의 29개 값은 기존 수치형 디바이스 구조로 저장합니다. 현재 프로젝트 스키마 7은 같은 디바이스 체인의 VST3 상태를 함께 보존하며 스키마 1–5를 자동 변환합니다. 새 스키마나 디바이스를 모르는 이전 앱에서는 해당 프로젝트를 열 수 없습니다.
- 자동 저장, `.garak` 파일, 트랙 복제, 전체 바이패스, 디바이스 이동·삭제와 실행 취소에 기존 프로젝트 경로를 사용합니다.
- AI 명령의 `effect.add`, `effect.setParam`, `effect.setEnabled`도 같은 범위 검증을 적용합니다.
- 프리셋 변경은 여러 파라미터를 하나의 프로젝트 편집으로 적용합니다. 노브 드래그는 기존 히스토리 제스처를 사용합니다.

## 오디오 엔진과 지연

데스크톱은 [네이티브 DSP](../native/src/dsp.cpp)의 기타 앰프를 같은 트랙 그래프에 넣습니다. ASIO/WASAPI/Core Audio 입력 모니터링, 녹음한 리전 재생, WAV 내보내기에 같은 C++ 모듈을 사용합니다. 녹음 파일에는 입력 원본을 보존하고, 재생·출력할 때 현재 앰프 설정을 적용합니다. 네이티브 호스트나 효과 처리가 실패하면 오류를 표시합니다.

브라우저 데모는 [effectPreparation.ts](../src/audio/effectPreparation.ts)로 Web Audio/Worklet 프로세서를 준비합니다. 브라우저의 기타 프로젝트에서는 미래 샘플을 기다리지 않는 마스터 컴프를 사용하며 장치 삭제·그래프 교체 시 워크릿과 메시지 포트를 정리합니다. 데스크톱의 마스터는 네이티브 그래프에서 처리합니다. 자체 DSP와 브라우저 내부 구현의 출력이 비트 단위로 같다는 뜻은 아닙니다.

엔진이 표시하는 드라이버의 지연 보고값과 기타 입력부터 헤드폰까지의 실측 왕복 지연은 다릅니다. 실제 연주감은 인터페이스·드라이버·버퍼·플러그인에 영향을 받으므로 장비를 연결한 루프백 측정과 청취 검증이 필요합니다. [네이티브 오디오 구조와 현재 검증 범위](NATIVE_AUDIO.md)

## 에셋 규격

원본을 바탕으로 같은 캔버스 비율과 중심점을 유지하는 앱 에셋을 사용합니다. 노브 캡만 회전하고 몸체·눈금·텍스트는 고정합니다.

| 종류 | 래스터 캔버스 | 비율 | 기준 표시 크기 |
| --- | --- | --- | --- |
| 앰프 | 1440 × 480 | 3:1 | 720 × 240 CSS px |
| 페달 몸체 | 360 × 600 | 3:5 | 180 × 300 CSS px |
| 캐비닛 | 768 × 512 | 3:2 | 384 × 256 CSS px |
| 노브 캡 | 128 × 128 | 1:1 | 44 × 44 CSS px |

노브 회전축은 캔버스의 `(64, 64)`이며, 캡 반경은 60px입니다. 모든 페달은 같은 크기와 노브 장착 좌표를 사용합니다. 라벨과 값은 이미지에 합성하지 않고 접근 가능한 HTML로 표시합니다. 이 일러스트는 오리지널 가상 장비이며 특정 하드웨어 제조사의 외관을 재현하지 않습니다.

## 검증 범위

`src/core/guitarRig.test.ts`는 전체 파라미터와 바이패스의 저장·복원, 원본 음원 바이트 보존, 잘못된 파라미터 거절, AI 명령과 실행 취소를 검사합니다. DSP와 오디오 엔진 테스트는 별도로 프로세서 상태·신호 처리·준비 실패·리소스 정리를 검사합니다.

```sh
pnpm test
pnpm build
pnpm mcp:build
pnpm desktop:compile
node scripts/guitar-rig-smoke.mjs
```

브라우저 검증 스크립트에는 Playwright Chromium이 필요합니다. `GARAK_CHROMIUM_EXECUTABLE`로 설치된 Chromium을 지정할 수 있습니다. 이 스크립트는 별도의 브라우저 컨텍스트와 가상 입력을 사용해 새 기타 트랙, 노브·프리셋 실행 취소, 모니터링, 저장 후 복원, 48/96kHz 처리, 마이크 설정에 따른 실제 출력 변화, WAV 생성을 확인합니다. UI와 DSP에 새 런타임 패키지를 추가하지 않았습니다.

자동 테스트는 실제 기타·오디오 인터페이스로 측정한 왕복 지연이나 청취 평가를 대신하지 않습니다.
