# 단축키

가락이음은 Logic Pro의 키 명령을 참고합니다. macOS의 `⌃`(Control)·`⌥`(Option)·`⇧`(Shift)·`⌘`(Command)를 구분하고, Windows·Linux에는 아래 표의 조합을 적용합니다. 등록된 80개 명령의 키와 범위는 [`src/core/input.ts`](../src/core/input.ts)의 `SHORTCUT_BINDINGS`·`SHORTCUT_TABLE`에서 대조했습니다. 피아노롤이 직접 처리하는 추가 키는 별도 표에 적었습니다.

이 문서의 재생·편집 단축키는 **`/projects/:id`의 편집기**에 적용합니다. 기본 **`/`의 프로젝트 선택 화면**에는 재생 엔진·편집 단축키가 없습니다. Tab/Shift+Tab으로 항목에 포커스를 옮기면 해당 항목이 선택됩니다. 항목의 **Space는 선택**, **Enter는 열기**에 사용합니다. 마우스로는 한 번 클릭해 선택하고 더블 클릭하거나 공통 하단 열기 버튼을 눌러 엽니다. 분류·빈 프로젝트·가져오기·상세 접기 등의 버튼은 일반 Enter/Space 동작을 사용합니다. 화면 이동 중의 진행 대화상자에도 편집기의 Space 재생 명령을 전달하지 않습니다.

- **연결됨**은 [`App.tsx`](../src/App.tsx)의 명령 처리 또는 [`PianoRoll.tsx`](../src/components/PianoRoll.tsx)의 키 처리에 동작이 연결되어 있다는 뜻입니다. 실기기 녹음·청음·모든 브라우저에서의 키 전달까지 검증했다는 뜻은 아닙니다. **알림만**인 메트로놈은 아직 소리를 내지 않습니다.
- **범위**는 현재 또는 마지막 활성 편집 영역입니다. 믹서·디바이스 랙은 `작업 공간` 명령을 상속합니다. 일반 버튼·드롭다운·슬라이더를 사용한 뒤에도 Undo/Redo·저장·녹음과 소속 편집기의 명령을 사용할 수 있습니다. 컨트롤의 Enter·기본 방향키 등은 유지하며, 텍스트/숫자 입력·IME·대화상자·복사 가능한 오류/출처는 입력을 우선합니다. 이름·검색·숫자 입력과 지정된 안내 문구는 텍스트 선택을 허용하며, 일반 UI 라벨은 선택을 막습니다. 오류/안내에서 Ctrl/⌘C는 선택한 글자의 기본 복사를 유지합니다. 접힌 편집기에는 편집 명령을 보내지 않고 타임라인으로 돌아갑니다.
- **Space 재생 명령**은 편집기의 일반 화면 전역에 적용합니다. 드롭다운·버튼·체크박스·라디오·슬라이더/노브·숫자 입력·팝오버/메뉴·body에서도 Space는 재생/일시 정지, Shift+Space는 선택 리전부터 재생입니다. 편집 가능한 텍스트 입력·textarea·contenteditable·IME 조합과 열린 모달은 해당 입력을 우선합니다. 버튼·메뉴는 Enter로 실행하며 일반 화면의 네이티브 체크박스·라디오에도 Enter 활성화를 제공합니다. 다른 편집 단축키의 범위는 그대로입니다.
- **설정 열기**는 앱 명령의 예외입니다. `⌘,`/`Ctrl+,`는 입력 필드·일반 버튼·복사 가능한 안내에도 적용되며, 다른 모달이 열린 동안에는 실행하지 않습니다. IME 조합·데드 키·AltGraph 보호와 반복 입력 제한은 유지합니다.
- 목표 동작과 남은 차이는 [상호작용 명세](INTERACTION_SPEC.md), 확인 범위와 미완성 항목은 [구현 상태](IMPLEMENTATION_STATUS.md)를 참고합니다.

## 키 판정 규칙

- `⌘`/`Ctrl` 계열의 공통 명령은 두 키 중 **정확히 하나**만 눌렸을 때 인정합니다. 각 명령에 지정된 Alt·Shift 조합도 정확히 일치해야 합니다. macOS에서 Control을 Command 대신 쓰는 호환 동작이 있지만, 아래 **macOS 전용 Control 명령이 같은 범위에서 먼저 적용**됩니다. 예를 들어 타임라인의 `⌃R`은 녹음 대기, `⌘R`은 리전 반복 붙이기이며 `⌃Z`는 포커스 트랙 확대, `⌘Z`는 실행 취소입니다.
- Windows·Linux에서는 Logic의 `⌃`+글자를 대체로 `Alt+Shift`+글자로 옮깁니다. 예외는 전체 가리기 해제(`Ctrl+Alt+H`)이며, macOS `⌃Z`에 대응하는 Windows 키는 없습니다. 해당 포커스 트랙 확대는 보기 메뉴에서 선택할 수 있습니다.
- 수식키 없는 글자 명령은 수식키가 있으면 실행하지 않습니다. 글자·구두점은 물리 키 위치(`event.code`)를 우선 사용하므로 한글 자판에서도 같은 위치로 동작합니다. 한글 조합 중 입력, 실제 `AltGr` 문자 입력, 데드 키는 보호합니다. Firefox/macOS가 Option을 AltGraph로 보고하는 경우는 구분합니다.
- 앱 전역 명령은 길게 누른 키의 자동 반복을 소비하되 재실행하지 않습니다. 피아노롤의 방향키 선택·이동·길이·음높이 조절은 반복 입력을 받습니다. 저장·삭제·복사·붙여넣기·퀀타이즈는 반복하지 않습니다.
- 재생용 Space는 [`transportShortcuts.ts`](../src/core/transportShortcuts.ts)의 `keydown` capture 단계에서 처리합니다. 한 번 누르는 동안 한 번만 실행하고, 소유한 반복 입력과 대응하는 `keyup`도 소비하여 기본 스크롤·컨트롤 재실행을 막습니다. 누르는 중 포커스나 수정키가 달라져도 대응하는 keyup까지 처리합니다. 텍스트 입력·IME·모달에 맡긴 Space는 재생 명령이 가로채지 않습니다.
- `Delete`와 `Backspace`는 선택 대상 삭제의 대체 키입니다. 피아노롤에서는 음표, 타임라인에서는 리전만 지우며 선택이 없다고 트랙을 삭제하지 않습니다. 트랙 삭제에는 별도의 `⌘⌫`/`Ctrl+Backspace`를 씁니다. `Ctrl+Y` 다시 실행은 Windows·Linux에서만 받습니다.
- 브라우저 예약 키는 앱까지 전달되지 않을 수 있습니다. 분할에는 `⌘T`/`Ctrl+T` 외에 `⌘E`/`Ctrl+E`도 제공합니다. 리전 반복 `⌘R`/`Ctrl+R`, Windows의 `Ctrl+D`, `Alt+←/→` 등도 표의 편집 범위에 포커스가 있어야 앱에서 처리합니다. 드래그 진행 중에는 해당 제스처가 편집을 우선 소유합니다.

## 재생·이동

| 동작 | macOS | Windows/Linux | 범위 | 상태 |
| --- | --- | --- | --- | --- |
| 재생 / 일시 정지 | `Space` | `Space` | 편집기 일반 화면 전역; 텍스트 입력·IME·열린 모달 제외 | 연결됨 |
| 선택 위치부터 재생 | `⇧Space` | `Shift+Space` | 편집기 일반 화면 전역; 텍스트 입력·IME·열린 모달 제외 | 연결됨 |
| 처음으로 이동 | `Home` / `↩` | `Home` / `Enter` | 타임라인·피아노롤·작업 공간 | 연결됨 · Enter는 피아노롤 제외 |
| 뒤로 감기 | `,` | `,` | 타임라인·작업 공간 | 연결됨 |
| 앞으로 감기 | `.` | `.` | 타임라인·작업 공간 | 연결됨 |
| 반복 구간(사이클) 켜기/끄기 | `C` | `C` | 타임라인·피아노롤·작업 공간 | 연결됨 |
| 녹음 | `R` | `R` | 타임라인·피아노롤·작업 공간 | 연결됨 |
| 메트로놈 켜기/끄기 | `K` | `K` | 타임라인·피아노롤·작업 공간 | 알림만 · 소리 미구현 |
| 선택 클립으로 반복 구간 지정 | `⌘U` | `Ctrl+U` | 타임라인 | 연결됨 |

`Space`는 현재 구현에서 재생과 **일시 정지**를 전환합니다. 첫 장치 초기화가 끝나기 전에 다시 누르면 대기 중 재생 요청도 취소합니다. 정지 버튼은 별도로 엔진을 정지합니다. `Shift+Space`는 선택한 **리전의 가장 이른 시작점**부터 재생하며, 피아노롤에서 선택한 개별 음표의 위치를 시작점으로 사용하지 않습니다. `,`·`.`은 이전·다음 마디 경계로 이동합니다. `Home`은 피아노롤에서도 받지만 처음으로 이동하는 `Enter`는 타임라인·작업 공간에서만 받습니다.

`R`은 마이크 오디오 녹음 시작·종료에 연결되어 있습니다. 녹음 대기 중인 활성 오디오 트랙 중 위쪽 트랙을 우선 사용하고, 없으면 포커스 오디오 트랙을 사용합니다. 소프트웨어 악기의 녹음 대기 표시가 외부 MIDI 녹음을 뜻하지는 않습니다. 입력 모니터링과 실제 녹음은 브라우저 권한·입력 장치에 따라 별도 확인이 필요합니다.

오디오 녹음 중 `Space`·재생 일시정지·정지 버튼·`R` 재클릭은 녹음도 종료해 리전을 확정합니다. 루프가 꺼진 프로젝트의 끝에서 재생이 종료되어도 같은 경로를 사용합니다. 입력 권한을 기다리는 중 `Space`나 정지로 취소하면, 늦게 권한을 허용해도 녹음이 다시 시작되지 않습니다. 녹음 준비·최종 데이터·디코딩 처리 중에는 `Shift+Space` 및 위치를 지정한 재생 시작을 보류합니다.

## 프로젝트·패널·보기

프로젝트 목록은 **상단 헤더의 폴더 버튼** 또는 **로고 메뉴 → 프로젝트 목록**으로 엽니다. 프로젝트 파일 가져오기는 목록의 가져오기 버튼과 로고 메뉴의 **프로젝트 파일 가져오기…**를 사용합니다. 목록 이동·새 프로젝트·파일 가져오기에 새 키 조합을 등록하지 않았습니다. `⌘S`/`Ctrl+S`는 편집 가능한 `.garak` 파일을 내려받는 명령이며, 프로젝트 ID별 자동 저장은 별도로 수행됩니다.

목록으로 돌아가거나 다른 프로젝트로 이동할 때는 현재 작업의 마지막 저장을 기다립니다. 녹음·파일 처리·드래그·미적용 피치 초안이 있거나 저장에 실패하면 이동을 멈추고 이유를 알립니다. 새 빈 프로젝트·샘플·가져온 파일은 새 ID로 저장한 뒤 열리며, 다른 기기에서 이어 작업할 때는 URL 대신 `.garak` 파일을 전달합니다.

`⌘G`/`Ctrl+G`는 **현재 편집기의 스냅**을 켜고 끕니다. 피아노롤에서는 자체 스냅 드롭다운도 같이 바뀌며, 다시 켤 때 마지막 단위를 복원합니다. 타임라인과 피아노롤의 단위는 독립적입니다. `I`·`Y`·`X`·`F`·`G`는 피아노롤 편집 범위에서는 실행하지 않습니다. `X`로 믹서를 닫으면 현재 구현은 하단 편집기로 돌아갑니다. 글로벌 트랙에는 현재 마커가 표시됩니다.

확대/축소 명령은 아래 [확대/축소](#확대축소) 절의 규칙대로 마지막 편집 포커스 영역에 적용합니다.

설정은 로고 메뉴의 **설정…**과 하단 오디오 상태 버튼에서도 엽니다. 설정 창의 Tab은 창 내부를 순환하고, Escape는 미적용 초안을 버리고 닫습니다. 적용 중에는 닫기를 막습니다. 설정 창에서의 Space·Delete 등이 편집기의 재생·리전 삭제 명령으로 전달되지 않습니다. 장치 설정은 프로젝트 Undo와 분리되며, 프로젝트 샘플레이트 변경만 Undo/Redo 대상입니다. 녹음·녹음 준비 중에는 레이트를 바꾸는 Undo/Redo를 차단하고 이유를 알립니다.

MIDI 좌우 트림은 원본 음표를 숨기는 비파괴 범위 편집입니다. 다시 늘리면 숨은 음표가 복원됩니다. 피아노롤에서 음표를 명시적으로 삭제하는 작업과 구분합니다. MIDI 합치기는 선택 리전의 현재 보이는 음표를 새로운 소스로 합칩니다. 과거 버전의 파괴적 트림으로 이미 지운 음표를 복원하는 기능은 아닙니다.

## 피아노롤

| 동작 | macOS | Windows/Linux | 범위 | 상태 |
| --- | --- | --- | --- | --- |
| 선택 음표 삭제 | `⌦` / `⌫` | `Delete` / `Backspace` | 피아노롤 | 연결됨 |

| 선택 음표를 반음 올리기 / 내리기 | `↑` / `↓` | `↑` / `↓` | 피아노롤 | 연결됨 · 드럼은 인접 패드 행 |

아래 명령은 `PianoRoll`이 직접 처리하므로 전역 `SHORTCUT_TABLE`에 별도 행이 없습니다.

| 동작 | macOS | Windows/Linux | 범위 | 상태 |
| --- | --- | --- | --- | --- |
| 선택 음표 복제 | `⌘D` | `Ctrl+D` | 피아노롤 | 연결됨 |
| 방향키 선택 확장 | `⇧`+방향키 | `Shift`+방향키 | 피아노롤 | 연결됨 |
| 시작 위치와 길이 퀀타이즈 | `⇧Q` | `Shift+Q` | 피아노롤 | 연결됨 |

일반 방향키는 **선택한 음표 편집**입니다. `←`/`→`는 현재 화면에 표시된 최소 격자 한 칸, `↑`/`↓`는 반음(드럼은 인접 패드 행)씩 이동합니다. 좌우 이동 단위는 확대 수준을 따르며 마우스 스냅 값과 분리합니다. 격자 사이에 놓인 음표의 미세한 위치 차이와 다중 선택의 상대 간격을 유지하고, 리전·MIDI 음높이 범위 밖으로 나가지 않게 제한합니다. 선택한 음표가 없으면 이동하지 않습니다. `⌥`/`Alt`+방향키도 같은 편집을 수행합니다. `Shift`+방향키는 기존 선택 확장, `⌥⇧←/→`/`Alt+Shift+←/→`는 한 격자씩 길이 조절입니다.

마우스 생성·이동·양쪽 길이 조절의 기본값은 **자유 이동**입니다. 가로 위치와 길이가 포인터를 연속적으로 따르며 격자나 인접 음표 경계로 끌려가지 않습니다. 필요한 경우 피아노롤의 마우스 스냅 메뉴에서 음표 단위를 직접 선택할 수 있습니다. `⌘G`/`Ctrl+G`는 자유 이동과 마지막으로 사용한 스냅을 전환하며, 처음 켤 때는 1/16음표를 사용합니다. 마우스 스냅을 켜도 좌우 방향키는 보이는 격자 한 칸을 사용합니다.

`Q`는 시작 위치, `Shift+Q`는 시작 위치와 길이를 선택한 피아노롤 스냅 단위에 맞춥니다. 선택이 없으면 해당 리전의 모든 음표에 적용하며, 자유 이동 중에는 1/16음표를 퀀타이즈 단위로 사용합니다. 텍스트·숫자 입력·IME·모달과 드롭다운·슬라이더 등의 기본 방향키 동작은 계속 보호합니다.

인스펙터·피아노롤의 음이름은 **MIDI 60 = C3**, 전체 범위는 **C-2–G8**입니다. 화면 표기만 통일했으며 저장된 MIDI 값, 실제 재생 음높이, 샘플 파일명은 바꾸지 않습니다.

## 오디오 피치 편집기

아래 표는 피치 편집기에 포커스가 있을 때 적용하며, 전역 `SHORTCUT_TABLE`과 구분한 로컬 명령입니다. 숫자 입력 필드는 숫자 편집 키를 사용하고 Enter로 입력을 확정하며, Space/Shift+Space는 일반 화면의 재생 명령을 따릅니다. 실제 조작 검증 상태는 [피치 편집 안내](PITCH_EDITOR.md)를 따릅니다.

| 동작 | macOS | Windows/Linux |
| --- | --- | --- |
| 다중 음표 선택 토글 | `⌘`+클릭 또는 `⌃`+클릭 | `Ctrl`+클릭 |
| 음표 범위 선택 | `⇧`+클릭 | `Shift`+클릭 |
| 반음 이동 | 위아래 드래그 / `↑`·`↓` | 위아래 드래그 / `↑`·`↓` |
| 10 cents 이동 | `⇧↑`·`⇧↓` | `Shift+↑`·`Shift+↓` |
| 1 cent 이동 | `⌥↑`·`⌥↓` | `Alt+↑`·`Alt+↓` |
| 센트 정밀 드래그 | `⌥`+위아래 드래그 | `Alt`+위아래 드래그 |
| 이전/다음 음표 선택 | `←`·`→` | `←`·`→` |
| 보이는 음표 모두 선택 | `⌘A` | `Ctrl+A` |
| 선택 음표 피치 초기화 | `⌫`·`⌦` 또는 더블 클릭 | `Backspace`·`Delete` 또는 더블 클릭 |
| 초안 Undo / Redo | `⌘Z` / `⇧⌘Z` | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 드래그/작업 취소, 선택 해제 | `Esc` | `Esc` |

초안 Undo/Redo가 없으면 같은 명령이 프로젝트 이력으로 전달됩니다. Space는 호스트가 현재 적용된 소리의 재생을 처리합니다. 프로젝트 파일 저장 명령은 미적용 초안이 있으면 먼저 적용/변경 취소를 안내합니다. 피치 편집기의 Delete는 선택 음표, 더블 클릭은 해당 음표의 피치 이동만 초기화하며 포먼트 값은 유지합니다. 타임라인 리전을 삭제하지 않습니다.

음계 보정과 포먼트 설정에는 전용 글자 단축키가 없습니다. Tab으로 컨트롤에 이동하고 선택 음표 보정·피치 초기화·포먼트 초기화 등의 버튼을 Enter로 실행합니다. 일반 화면의 포먼트 보존·신뢰도 제외 체크박스도 Enter로 전환합니다. 이 컨트롤들에 포커스가 있어도 Space/Shift+Space는 재생 명령입니다.

음정 중심 보정은 반음계·장음계·자연 단음계와 기준음, 0–100% 강도, 신뢰도 75% 미만 제외 옵션을 사용합니다. 설정만 바꾸어서는 음표를 이동하지 않으며 **선택 음표 보정**을 눌러야 현재 화면 안의 선택 음표에 적용합니다. 도구옵션은 같은 프로젝트 ID에서 리전·탭을 바꾸어도 현재 세션에 유지하며 프로젝트 파일이나 Undo에는 포함하지 않습니다. 포먼트 보존은 기본 꺼짐의 실험 기능이고 음표별 이동값은 ±1200 ct입니다. 피치와 보존 설정을 합친 내부 포먼트 보정량이 한도를 넘으면 **편집 적용**을 비활성화하고 안내합니다.

## 확대/축소

키 포커스는 마지막으로 클릭한 어레인지먼트·피아노롤·믹서·디바이스 랙이 가지며, 아직 없으면 어레인지먼트에 적용합니다. 입력 필드·슬라이더·노브에 포커스가 있으면 그 컨트롤이 방향키를 사용합니다. 각 영역의 가로·세로 확대/축소·맞춤 버튼도 같은 영역을 조작하고 포커스를 유지합니다. 영역 배율은 브라우저 `localStorage`의 `garak-ieum:zoom`에 기억합니다.

| 입력 | macOS | Windows/Linux | 동작 |
| --- | --- | --- | --- |
| 가로 확대 / 축소 | `⌘→` / `⌘←` | `Ctrl+→` / `Ctrl+←` | 한 번에 1.25배 |
| 세로 확대 / 축소 | `⌘↓` / `⌘↑` | `Ctrl+↓` / `Ctrl+↑` | 한 번에 1.2배 (`⌘↓`가 더 크게) |
| 맞춰 보기 | `Z` | `Z` | 영역별 맞춤 |
| 포인터 기준 가로 확대/축소 | `⌘`+휠, 트랙패드 핀치 | `Ctrl`+휠, 트랙패드 핀치 | 포인터 아래 위치를 고정 |
| 포인터 기준 세로 확대/축소 | `⇧⌘`+휠 또는 `⌥`+휠 | `Ctrl+Shift`+휠 또는 `Alt`+휠 | 포인터 아래 트랙·음높이를 고정 |
| 스크롤 | 휠 / `⇧`+휠 | 휠 / `Shift`+휠 | 세로 / 가로 스크롤 (브라우저 기본) |

| 영역 | 가로 | 세로 | `Z` |
| --- | --- | --- | --- |
| 어레인지먼트 | 박자 폭 4–200 px | 전체 기준 높이 36–160 px, 개별 트랙에는 별도 높이 배율 적용 | 선택 리전에 맞춤, 다시 누르면 프로젝트 전체; 트랙 수에 따라 기준 높이도 조절 |
| 피아노롤 | 박자 폭 12–240 px (초기에는 리전 길이에 자동 맞춤) | 건반 높이 8–40 px | 리전 전체 가로 맞춤 + 사용한 음높이 범위 세로 맞춤 |
| 믹서 | 채널 폭 64–160 px | 페이더 높이 80–220 px | 모든 채널이 보이는 폭, 패널 높이에 맞는 페이더 |
| 디바이스 랙 | 카드 배율 0.75–1.5배 (가로·세로 키 모두 1.1배 단위) | — | 기본 크기(1배) |

트랙 헤더는 높이 44 px 미만에서 이름·M/S 중심, 72 px 이상에서 볼륨, 96 px 이상에서 팬을 표시하며 헤더 구성 설정도 적용합니다. 헤더 오른쪽 아래 모서리를 드래그하면 해당 트랙 높이, `⌘`/`Ctrl`+드래그하면 전체 기준 높이를 조절합니다. 같은 모서리의 `Shift` 클릭은 해당 트랙 높이 배율을, `Shift+⌘`/`Shift+Ctrl` 클릭은 모든 개별 배율을 초기화합니다.

## 하단 편집기 크기

편집기 위 경계를 드래그해 높이를 바꾸고, 경계를 더블 클릭하면 기본 높이로 돌아갑니다. 경계에 Tab 포커스를 두고 `↑`/`↓`는 24px, `Shift+↑`/`Shift+↓`는 64px 조절, `Home`은 최소 높이, `End`는 최대화, `Enter`는 접기/펼치기입니다. 툴바의 최대화·접기 버튼도 같은 동작을 제공합니다. 편집기 탭이나 리전 더블 클릭으로 다시 엽니다.

피아노롤·오디오·믹서·디바이스·피치의 마지막 높이를 `garak-ieum:editor-panel`에 각각 저장합니다. 접는 동안 컴포넌트는 유지되어 피치 초안과 편집기 선택을 잃지 않습니다. 이 크기 변경은 프로젝트 Undo와 분리합니다.

피아노롤은 늘어난 패널 높이를 채우고, 하단 벨로시티·안내 바는 패널 아래에 붙습니다. 내부 음표 캔버스만 남은 높이를 사용해 스크롤하며, 기존 300px 높이 상한은 편집 패널 안에서 적용하지 않습니다.

## 드래그 수식키

타임라인 리전과 피아노롤 음표는 실제 박자 경계까지 표시해 인접 객체 사이에 인위적인 2px 여백을 두지 않습니다. 확대하면 마디·박·세부 분할선과 눈금자가 함께 자세해집니다(최대 확대에서 1/32·1/64 음표 단위, 셋잇단 스냅은 셋잇단 분할). 표시 격자가 세밀해져도 직접 선택한 마우스 스냅 단위는 유지합니다. 피아노롤의 기본 마우스 모드는 자유 이동이며, 스냅 메뉴에서 `1/64`까지 직접 선택할 수 있습니다. 피아노롤의 좌우 방향키는 이 메뉴와 별개로 표시 격자 한 칸을 따릅니다.

스냅이 켜져 있으면 리전은 목적지 레인의 인접 경계, 음표는 같은 음높이의 인접 경계에서 **6px 이내**로 가까워질 때 정확히 맞닿습니다. 정렬선을 표시하며 다중 선택의 상대 간격을 유지합니다. Snap Off 또는 아래의 스냅 무시 수정키는 경계 자석 스냅도 끕니다.

타임라인 리전과 피아노롤 음표 드래그는 [`dragModifiers()`](../src/core/input.ts)에 연결되어 있습니다. 수정키를 드래그 중에 다시 읽습니다. 아래 표는 **편집 객체 드래그** 규칙이며, 트랙 버튼·높이·선택 조작의 수정키는 별도로 적용합니다.

| 동작 | macOS | Windows/Linux | 현재 처리 |
| --- | --- | --- | --- |
| 복사하며 이동 | `⌥`+드래그 | `Alt`+드래그 | 리전·음표 본문 이동에 적용; 가장자리 트림과 구분 |
| 세밀하게 이동 | `⌃`+드래그 | `Ctrl`+드래그 | 현재 스냅 간격의 1/4 |
| 스냅 무시 | `⌃⇧`+드래그 | `Ctrl+Shift`+드래그 | 스냅을 풀고 축 고정은 적용하지 않음 |
| 한 방향으로 고정 | `⇧`+드래그 | `Shift`+드래그 | 가로 또는 세로 이동만 적용 |

macOS의 Control+클릭은 브라우저 상황 메뉴로 전달될 수 있으므로 세밀 이동·스냅 무시는 드래그를 시작한 뒤 Control을 눌러 사용합니다. 타임라인은 스냅 메뉴에서 절대값·상대값을 선택하며 피아노롤은 원래 타이밍 오프셋을 유지하는 상대 이동을 사용합니다. `⌘` 자체는 이 객체 드래그의 복제·스냅 수정키가 아닙니다.

MIDI 리전의 `Alt+Shift` alias는 아직 지원하지 않습니다. 현재 구현은 해당 조합을 일반 복사와 축 고정으로 처리하므로, alias 예약 조합을 거부하도록 정한 상호작용 명세와 차이가 남아 있습니다.

## 트랙 버튼의 수정키


| 조작 | macOS | Windows/Linux | 현재 처리 |
| --- | --- | --- | --- |
| M 또는 S 배타 적용 | `⌥`+클릭 | `Alt`+클릭 | 해당 트랙만 뮤트 또는 솔로 |
| M 일괄 전환 | `⌘`+클릭 | `Ctrl`+클릭 | 클릭한 트랙과 같은 뮤트 상태인 트랙들을 반전 |
| S 또는 켬/끔 전체 전환 | `⌘`+클릭 | `Ctrl`+클릭 | 모든 트랙을 클릭한 버튼의 새 상태로 설정 |
| Solo Safe | S에 `⌃`+클릭 | S에 `Alt+Shift`+클릭 | 다른 트랙의 솔로 때문에 제외되지 않도록 설정 |
| R 배타 녹음 대기 | `⌥`+클릭 | `Alt`+클릭 | 해당 트랙만 대기; 이미 대기 중이면 모두 해제 |
| 여러 트랙의 같은 버튼 전환 | 수정키 없이 누른 채 드래그 | 동일 | 지나가는 같은 종류의 버튼에 처음 정한 상태 적용 |

헤더 우클릭 메뉴 또는 `⌥T`/`Alt+T`에서 버튼·컨트롤·표시 항목을 설정할 수 있으며 구성은 `localStorage`에 보관합니다. 96색 팔레트는 `⌥C`/`Alt+C` 또는 트랙 색상 메뉴로 엽니다.
