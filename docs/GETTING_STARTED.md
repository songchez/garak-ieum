# 가락이음 시작하기

[← 제품 소개로 돌아가기](../README.md)

설치부터 첫 편곡, 피치 편집, 프로젝트 보관까지 이어지는 사용 안내입니다. 현재 버전은 **0.1.0 개발 프리뷰**입니다. 기능별 자세한 사용법은 [피치 편집](PITCH_EDITOR.md), [단축키](SHORTCUTS.md), [AI 연결](MCP.md), [구현 상태](IMPLEMENTATION_STATUS.md)에서 확인하실 수 있습니다.

## 1. 설치하고 실행하기

### 준비할 환경

- **Node.js 24.x 권장**, 또는 Node.js 22.12 이상인 22.x 환경을 준비합니다.
- 의존성 설치에는 **pnpm 11.25.0**을 사용합니다.
- Web Audio와 IndexedDB를 지원하는 데스크톱 브라우저에서 작업합니다.
- 마이크 녹음과 피치 원본 해시 확인에는 **HTTPS 또는 localhost** 환경이 필요합니다.

저장소를 처음 받으신다면 다음 명령으로 작업 폴더를 만듭니다.

```bash
git clone https://github.com/songchez/garak-ieum.git
cd garak-ieum
```

이미 소스를 받으셨다면 해당 프로젝트 폴더에서 아래 명령을 실행하세요.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

설치가 성공하면 터미널에 표시된 **Local 주소**를 브라우저에서 엽니다. 기본 포트가 사용 중이면 Vite가 다른 포트를 사용할 수 있으므로 실제 출력 주소를 확인하세요. 새 포트는 별도의 브라우저 저장 공간을 사용합니다.

### Windows PowerShell에서 pnpm을 찾지 못할 때

프로젝트 폴더에서 고정된 pnpm 버전을 직접 실행할 수 있습니다.

```powershell
npx.cmd --yes pnpm@11.25.0 install --frozen-lockfile
npx.cmd --yes pnpm@11.25.0 dev
```

`npm i`에서 `Unsupported URL Type "workspace:"`가 발생하거나, 설치 중단 뒤 `lucide-react`를 찾지 못하면 실행 중인 서버를 **Ctrl+C로 멈추고 위 설치를 완료한 뒤** 다시 시작하세요. 의존성과 잠금 파일은 pnpm으로 관리합니다. 설치 후에는 `npm run dev`처럼 스크립트를 실행할 수도 있지만, 의존성 설치에는 저장소의 pnpm 설정을 사용하세요.

## 2. 첫 프로젝트 만들기

1. 기본 주소 **`/`**에서 **내 프로젝트** 또는 **샘플 프로젝트**를 고릅니다. 타일을 클릭하거나 Space를 누르면 선택하고, Enter·더블 클릭·하단 열기 버튼으로 엽니다. Tab으로 타일에 포커스를 옮겨도 해당 항목이 선택됩니다.
2. 빈 편곡으로 시작하려면 **새 빈 프로젝트**를 누릅니다. 새 작업과 샘플은 저장을 완료한 뒤 고유한 **`/projects/:id`** 주소로 열립니다.
3. 왼쪽 **라이브러리(Y)**에서 악기를 미리듣고 선택 트랙의 악기를 바꿉니다. 라이브러리의 **+ 트랙**은 새 악기 트랙을 추가합니다. 헤더의 **+** 또는 **⌥⌘N / Ctrl+Alt+N**으로 새 트랙 창을 열 수도 있습니다.
4. 악기 트랙의 빈 타임라인을 더블 클릭해 MIDI 리전을 만듭니다. 리전을 선택하고 피아노롤에서 음표를 추가한 뒤, 드래그로 위치·길이·벨로시티를 다듬습니다.
5. **오디오 가져오기**나 타임라인 파일 드롭으로 음원을 넣습니다. 지원 코덱은 브라우저에 따라 달라집니다. **인스펙터(I)**에서 리전·트랙 설정을, **믹서(X)**와 디바이스 랙에서 볼륨·팬·효과를 조절합니다.
6. **재생** 버튼이나 **Space**로 들어봅니다. 브라우저 오디오는 재생·미리듣기·설정 적용 같은 사용자 동작에서 시작합니다. 편곡을 보관할 때는 **프로젝트 파일 저장**, 들을 수 있는 결과물을 만들 때는 **내보내기**를 사용하세요.

상단 **폴더 버튼** 또는 **로고 메뉴 → 프로젝트 목록**으로 목록에 돌아갈 수 있습니다. 선택한 항목의 **상세 정보**는 편곡과 저장 정보를 읽는 영역이며, 오디오 장치나 템포를 편집하는 설정 창은 아닙니다.

### 샘플 편곡으로 시작하기

| 프로젝트 | 장르 | 구성 |
| --- | --- | --- |
| **마당의 결** | 국악 붐뱁 | 92 BPM · 40마디 · 10트랙 |
| **검은 물결** | 국악 트랩 | 144 BPM · 48마디 · 11트랙 |
| **달빛 행렬** | 퓨전 국악 | 118 BPM · 40마디 · 11트랙 |

가야금·대금·해금·사물 타악과 드럼·베이스가 들어 있는 오리지널 MIDI 편곡입니다. 샘플을 열 때마다 독립된 새 작업이 만들어지므로 트랙과 음표를 자유롭게 바꿔보세요. 참고곡의 녹음·선율·가사는 포함하지 않았습니다. 악기 역할과 곡별 구성은 [샘플 프로젝트 안내](SAMPLE_PROJECTS.md)에 정리했습니다.

## 3. 오디오를 음표처럼 피치 편집하기

1. 녹음하거나 가져온 **오디오 리전**을 선택합니다.
2. 디바이스 랙의 오디오 소스 카드에서 **피치 편집 열기**를 누르거나, 하단 **피치 편집** 탭을 엽니다.
3. **음표 분석**을 눌러 음표와 피치 곡선을 확인합니다.
4. 음표를 선택해 위아래로 드래그하거나 **cents** 값을 입력합니다. `+100`은 한 반음 위, `−25`는 25센트 아래입니다. 여러 음표를 선택해 함께 움직이거나 분할·합치기를 사용할 수 있습니다.
5. 음계에 맞추려면 기준음·음계·보정 강도를 정하고 **선택 음표 보정**을 누릅니다. 반음계·장음계·자연 단음계와 0~100% 강도를 지원하며, 설정만 바꿔서는 음표가 움직이지 않습니다.
6. **편집 적용** 후 DAW에서 재생해 확인합니다. 적용 결과는 프로젝트 저장과 WAV 출력에 반영되며 Undo/Redo와 **원본 복원**을 사용할 수 있습니다.

현재 대상은 **원본 파일 전체가 60초 이하인 단선율 보컬·독주**, 모노 또는 스테레오입니다. 피치는 음표별 원본 대비 **±12반음**까지 옮길 수 있습니다. 긴 원본을 리전에서 짧게 트림해도 원본 길이 제한은 그대로입니다.

**포먼트 보존·이동은 실험 기능**입니다. 보존은 기본으로 꺼져 있고, 음표별 포먼트 이동은 ±1,200센트 범위입니다. 보존을 켰을 때 피치와 포먼트 이동값의 내부 보정 차이도 ±1,200센트 안이어야 합니다. 적용 후 원본과 비교해 음색·음량을 확인하세요.

분석과 편집만 한 **미적용 초안은 현재 세션에만 남으며 자동 저장이나 `.garak`에 포함되지 않습니다.** 적용 전 재생은 마지막으로 적용된 소리, 적용 이력이 없으면 원본을 재생합니다. 분석만 보관하려는 경우도 **편집 적용**이 필요합니다. 세부 조작, 제한, 초안·원본 관계는 [피치 편집 안내](PITCH_EDITOR.md)를 참고하세요.

## 4. 마이크와 오디오 인터페이스 설정하기

**로고 메뉴 → 설정…**, 하단 **오디오 상태 버튼**, **⌘, / Ctrl+,**로 설정 창을 엽니다.

1. **오디오 장치**에서 입력을 고릅니다. 필요하면 **마이크 접근 허용·장치 확인**으로 권한을 부여하세요. 출력 장치 선택은 브라우저가 지원할 때 제공됩니다. 설정 창을 여는 것만으로 마이크가 켜지지는 않습니다.
2. **녹음·모니터링 → 입력 테스트 시작**으로 레벨을 확인합니다. 입력 테스트는 소리를 출력하지 않습니다. 실제 입력을 듣고 싶다면 **소프트웨어 모니터링**을 적용한 뒤 오디오 트랙의 **I**를 켜고 헤드폰으로 확인하세요.
3. **프로젝트 오디오**에서 샘플레이트를 고릅니다. 기본값은 **48kHz**이며 44.1·48·88.2·96·176.4·192kHz를 지원 범위에서 요청할 수 있습니다.
4. **적용** 또는 **완료**로 변경을 확정합니다. 적용은 재생을 일시 정지하고 장치와 엔진을 준비합니다. 취소·Escape·닫기는 미적용 설정을 버립니다. 녹음·파일 처리 중에는 적용할 수 없습니다.
5. **출력 테스트**와 **상태·진단**에서 실제 입력·출력 상태를 확인합니다. 출력 연결이나 권한을 잃으면 연결을 확인한 뒤 다시 적용하거나 **시스템 기본 출력**을 선택하세요.

녹음할 오디오 트랙을 선택하거나 **R**로 녹음 대기한 뒤 상단 녹음 버튼을 누릅니다. 다시 누르면 녹음을 마치고 오디오 리전을 추가합니다. 현재는 한 입력 스트림을 녹음하며, 여러 오디오 트랙이 대기 중이면 가장 위 트랙을 대상으로 합니다.

장치 설정은 이 브라우저에, 프로젝트 샘플레이트는 프로젝트에 저장됩니다. **녹음 위치 보정**은 새 녹음에 적용하는 −1,000~+1,000ms 수동 정렬이며 양수는 뒤로, 음수는 앞으로 옮깁니다. 하드웨어 버퍼·프리앰프 게인·팬텀 파워·클럭·직접 모니터링은 오디오 인터페이스나 운영체제에서 설정하세요. 브라우저에 요청한 값과 실제 상태의 차이는 [오디오 설정 안내](AUDIO_SETTINGS_BENCHMARK.md)에서 확인하실 수 있습니다.

| 실행 취소 / 다시 실행 | `⌘Z` / `⇧⌘Z` | `Ctrl+Z` / `Ctrl+Shift+Z` 또는 `Ctrl+Y` |
| 프로젝트 파일 저장 | `⌘S` | `Ctrl+S` |

| 복사 / 잘라내기 / 붙여넣기 | `⌘C` / `⌘X` / `⌘V` | `Ctrl+C` / `Ctrl+X` / `Ctrl+V` |
| 선택 삭제 | `⌫` 또는 `⌦` | `Backspace` 또는 `Delete` |

편집기의 **Space와 Shift+Space는 일반 버튼·드롭다운·숫자 입력에 포커스가 있어도 재생 명령**으로 동작합니다. 이름·검색·textarea·IME 조합·열린 모달에서는 해당 입력이 우선합니다. 다른 편집 단축키는 타임라인·피아노롤 등 정해진 편집 영역에 포커스를 두고 사용하세요. 일반 버튼·메뉴는 Enter로 실행할 수 있습니다.

프로젝트 선택 화면에서는 Space가 타일 선택, Enter가 열기입니다. 피치 편집기의 Delete/Backspace는 선택 음표의 피치 초기화입니다. 브라우저 예약 키가 전달되지 않을 수 있어 분할은 `⌘T / Ctrl+T` 대신 위 표의 `⌘E / Ctrl+E`를 사용할 수 있습니다. 전체 키맵과 마우스 수정키는 [단축키 문서](SHORTCUTS.md)에 있습니다.

## 6. 저장하고 다른 기기로 옮기기

### 자동 저장과 프로젝트 주소

편집 데이터와 가져온 원본 오디오는 **이 브라우저의 IndexedDB에 프로젝트 ID별로** 저장됩니다. 편집이 잠시 멈추면 자동 저장하며, `/projects/:id`를 다시 열면 해당 저장본을 복원합니다. 목록 이동이나 다른 작업 열기 전에도 마지막 편집을 저장합니다.

저장 실패, 녹음·파일 처리·드래그, 미적용 피치 초안 등으로 이동할 수 없으면 현재 화면에서 이유를 안내합니다. 안내를 확인하고 해당 작업을 마친 뒤 이동하세요. 없는 ID나 손상된 저장본은 오류를 표시하며 다른 프로젝트로 바꾸어 열지 않습니다.

**프로젝트 주소만 다른 브라우저나 기기로 보내면 데이터는 전달되지 않습니다.** 저장 공간은 프로토콜·호스트·포트별로 나뉩니다. `localhost`와 `127.0.0.1`, 다른 개발 포트, 배포 도메인은 각각 별도 작업실입니다.

### `.garak`으로 보관하기

- **프로젝트 파일 저장** 또는 **⌘S / Ctrl+S**로 편집 가능한 `.garak` 파일을 내려받습니다.
- 다른 기기에서는 프로젝트 선택 화면의 **.garak 불러오기** 또는 **로고 메뉴 → 프로젝트 파일 가져오기…**를 사용합니다.
- 가져온 파일은 새 프로젝트 ID로 저장합니다. 같은 파일을 여러 번 가져와도 기존 작업을 덮어쓰지 않습니다.
- 파일에는 편곡·디바이스 설정·가져온 원본 오디오, 적용된 피치 분석·편집·렌더 결과가 포함됩니다. 미적용 피치 초안과 이 컴퓨터의 장치 설정은 포함되지 않습니다.

브라우저 데이터 삭제나 저장 공간 부족에 대비해 중요한 작업은 `.garak`으로 별도 보관하세요. 프로젝트별 과거 버전 백업이나 클라우드 동기화는 현재 제공하지 않습니다. 이전 `.noct` 번들도 같은 형식으로 가져올 수 있습니다. 저장 구조와 호환성은 [아키텍처 문서](ARCHITECTURE.md)에 있습니다.

### WAV로 내보내기

**내보내기**는 전체 편곡을 **스테레오 PCM 16-bit WAV**로 렌더링합니다. 프로젝트 샘플레이트와 적용된 피치 편집을 사용하며, 재생 사이클 설정과 관계없이 전체 프로젝트를 한 번 출력합니다. 잔향을 포함한 렌더 길이는 **최대 15분**입니다.

다시 편집할 작업은 `.garak`, 듣거나 전달할 오디오는 WAV로 보관하세요. 원본 음원과 렌더 결과는 메모리에서 처리하므로 큰 파일이나 긴 작업은 기기의 메모리 사용량을 함께 확인해 주세요.

## 7. AI와 연결하기

같은 컴퓨터에서 실행하는 **로컬 stdio MCP 호스트**와 브라우저 작업실을 연결할 수 있습니다. 현재는 **7개 도구·19개 편집 명령**으로 상태 조회, MIDI 초안 생성, 트랙·리전·믹싱·이펙트 편집을 지원합니다.

```bash
pnpm mcp:build
node dist-mcp/mcp/token.js
```

생성한 연결 키로 MCP 호스트에 `dist-mcp/mcp/server.js`를 등록하고, 앱의 **로고 → AI 연결**에서 같은 키를 입력합니다. 키는 공개 이슈나 소스에 올리지 마세요. **AI 편집 허용**을 끄면 조회와 미리 보기만 가능합니다. 적용한 변경 묶음은 프로젝트 Undo 한 번으로 되돌릴 수 있습니다.

현재 연결은 `localhost` 또는 `127.0.0.1`의 **5173 / 4173 포트**에서만 허용합니다. 배포 사이트의 공개 HTTP MCP, 재생·녹음·피치 분석 명령, 작곡 코드 실행은 후속 범위입니다. Windows 실행 예시, 호스트 등록, 포트 설정, 연결 문제 해결은 [MCP 연결 안내](MCP.md)를 따라 주세요.

## 8. 문제가 생겼을 때

| 상황 | 확인할 내용 |
| --- | --- |
| `Unsupported URL Type "workspace:"` | 개발 서버를 멈추고 pnpm 11.25.0으로 설치하세요. Windows 명령은 위 설치 절차를 사용합니다. |
| `Failed to resolve import "lucide-react"` | 의존성 설치가 끝났는지 확인하고 `pnpm install --frozen-lockfile` 성공 후 서버를 다시 시작하세요. |
| 처음 열었는데 소리가 나지 않음 | 재생 버튼으로 오디오를 시작하고 트랙 뮤트·솔로·볼륨과 오디오 설정의 실제 출력을 확인하세요. |
| 마이크 목록이나 입력이 보이지 않음 | HTTPS/localhost, 브라우저의 마이크 권한, 선택한 장치 연결을 확인하고 설정에서 장치를 다시 확인하세요. |
| 프로젝트 목록이 비어 있음 | 원래 사용한 브라우저·호스트·포트인지 확인하세요. 별도로 보관한 `.garak` 파일이 있다면 가져올 수 있습니다. |
| 프로젝트를 열거나 목록으로 이동할 수 없음 | 저장 오류, 진행 중인 녹음·파일 처리, 미적용 피치 초안 안내를 확인하세요. 초안은 적용하거나 변경 취소 후 이동합니다. |
| 피치 편집을 했는데 원래 소리가 남음 | **편집 적용**이 완료됐는지 확인하세요. 초안만 바꾸면 마지막 적용 결과가 재생됩니다. |
| AI 연결 실패 | 허용 주소·포트, 호스트와 앱의 연결 키, 서버 중복 실행 여부를 [MCP 안내](MCP.md)에서 확인하세요. |

문제를 보고할 때는 재현 순서, 운영체제·브라우저 버전, 화면의 오류 문구를 남겨 주세요. 연결 키와 개인 음원은 제외하고, 공유 가능한 짧은 재현 프로젝트가 있으면 도움이 됩니다.

## 9. 개발과 검증

저장소 루트에서 다음 명령을 실행합니다. 현재 의존성 버전과 스크립트는 [package.json](../package.json)에 있습니다.

```bash
pnpm test
pnpm build
pnpm preview
```

`test`는 Vitest를, `build`는 TypeScript 검사와 Vite 빌드를 실행합니다. 배포 파일은 `dist/`에 만들어지며 `preview`로 확인할 수 있습니다. MCP 소스를 바꾼 뒤에는 `pnpm mcp:build`를 다시 실행하고 MCP 호스트의 서버를 재시작하세요.

자동 테스트는 편집 계산, 프로젝트·오디오 보관, 변환·출력, 키보드 처리, 명령 보호 등을 검증합니다. `fake-indexeddb`는 저장소 테스트에서 사용하는 개발 의존성입니다. 실제 브라우저 렌더링·조작, 오디오 출력·마이크 지연·청음은 별도의 확인 대상입니다. 수행한 검증과 남은 확인은 [구현 상태](IMPLEMENTATION_STATUS.md), 배포 설정은 [배포 안내](DEPLOYMENT.md)를 확인하세요.

## 10. 현재 범위와 다음 단계

- **편집:** 내부 MIDI 편집과 오디오 리전 편집을 제공합니다. 외부 MIDI 장치·MIDI 파일 입출력, 오토메이션, 템포 맵, 메트로놈·카운트인, 타임 스트레칭은 후속 작업입니다. `K`는 메트로놈 미지원 안내를 표시합니다.
- **피치:** 단선율 편집을 제공합니다. 다성음 분리, 타이밍·드리프트·비브라토 개별 보정, 실시간 마이크 피치 보정은 후속 작업입니다.
- **녹음·플러그인:** 동시 다중 입력 녹음·테이크 컴핑·자동 지연 보상·24/32-bit 원본 PCM 녹음과 외부 VST/AU/CLAP 호스트는 아직 제공하지 않습니다.
- **성능·보관:** 현재 웹 엔진은 메인 스레드 선행 예약과 메모리 내 오디오 처리를 사용합니다. 수백 트랙·장시간 작업의 성능 기준은 아직 공개하지 않았으며, 계정·클라우드 동기화·협업·설치형 오프라인 앱은 후속 범위입니다.

1.0의 작업 보존·편집·재생 품질과 2.0의 네이티브 호스트 계획은 [로드맵](ROADMAP.md)에 구분했습니다. 앱 코드와 오리지널 MIDI 편곡은 [MIT](../LICENSE), 아이콘·글꼴·샘플은 [각 자산의 라이선스](../THIRD_PARTY_NOTICES.md)를 따릅니다.
