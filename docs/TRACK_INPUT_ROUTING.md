# 트랙 입력 라우팅 (트랙 출력 녹음 · 리샘플링)

오디오 트랙의 입력으로 하드웨어 입력 대신 **다른 트랙의 신호**나 **마스터 믹스**를 고를 수 있습니다.
신스(악기 트랙)가 MIDI로 연주하는 소리를 오디오로 녹음하거나, 시김새를 거친 소리를 굳히거나,
마스터 전체를 다시 녹음(리샘플링)할 때 씁니다.

- 데이터: `Track.inputRoute` (프로젝트 스키마 11, `src/core/types.ts`)
- 순수 로직: `src/core/trackRouting.ts` (되먹임 검사, 마스터 피드 제외, 처리 순서, 삭제/복제 처리, 라벨)
- 통합 Rust 엔진(데스크톱·웹 공통, 0.3.2 기본): `rust/garak-engine/src/routes.rs`(`prepareRoutes` 포팅: 처리 레벨, 루프 끊기,
  마스터 피드, pre/post-FX·post-fader 탭). 녹음은 데스크톱 `garak_rs_engine_route_input`, 웹 `tap_output`. [RUST_ENGINE](RUST_ENGINE.md)
- 웹 Web Audio 대체 경로: `src/audio/graph.ts` (`connectRoutes`, `setRouteMonitoring`), `src/audio/RouteRecording.ts`,
  `src/audio/routeRecorder.worklet.ts`, `src/audio/WebAudioEngine.ts`
- 네이티브 셸과 이전 C++ 경로(`GARAK_RUST_ENGINE=0`): `native/include/garak/engine.hpp` (`TrackRoute`, `RecordingTake::routed`),
  `native/src/engine.cpp` (`prepareRoutes`, 레벨별 처리, 탭 버퍼), `native/src/protocol.hpp` (`route` 필드),
  `native/src/host.cpp` (테이크별 보정값), `src/audio/native/timeline.ts`
- UI: `src/components/InputSelect.tsx` (입력 목록 + `TapSelect`), `TrackInspector.tsx`, `TrackHeader.tsx`

## 1. 다른 DAW 비교

| DAW | 트랙을 입력으로 | 탭(가져오는 지점) | 마스터 녹음 | 되먹임 처리 |
| --- | --- | --- | --- | --- |
| **Ableton Live** | 오디오 트랙 "Audio From"에서 다른 트랙/리턴/그룹 선택 | 두 번째 선택 상자: **Pre FX / Post FX / Post Mixer** (트랙을 고르면 기본은 Post FX) | **Resampling**: 마스터 출력을 녹음. 녹음하는 트랙 자신의 출력은 입력에 섞이지 않음 | 루프가 되는 경로는 목록에서 고를 수 없음 |
| **Logic Pro** | 원본 트랙 출력(또는 센드)을 **버스**로 보내고, 녹음 트랙의 입력을 그 버스로 지정 | 센드 Pre/Post Fader, 출력은 Post Pan | 스테레오 아웃을 버스로 보내 녹음하거나 바운스 | 버스 배선을 사용자가 관리 |
| **Bitwig Studio** | 오디오 트랙 입력 목록에 다른 트랙·마스터가 바로 나옴 | 트랙 출력(포스트) 중심, 필요하면 Audio Receiver 장치로 체인 안 지점 선택 | 마스터를 입력으로 선택 | 순환되는 경로 차단 |
| **REAPER** | 받는 쪽 트랙에 **Receive** 추가, 또는 녹음 모드 "Record: output" | Pre-FX / Post-FX(Pre-Fader) / Post-Fader(Post-Pan) | 마스터 출력을 Receive로 받거나 렌더 | 기본은 되먹임 금지(설정으로만 허용) |

가락이음은 Ableton의 모델을 따릅니다. 오디오 트랙의 입력 선택 상자 하나에서 하드웨어 입력과 함께
트랙과 마스터를 고르고, 탭은 별도의 작은 선택 상자로 고릅니다. 기본 탭은 Ableton처럼 **시김새 후(Post FX)** 입니다.

## 2. 사용법

1. 녹음할 **오디오 트랙**을 선택합니다 (악기 트랙은 오디오 입력이 없으므로 받는 쪽이 될 수 없습니다).
2. 인스펙터의 **입력** 목록(또는 트랙 헤더가 충분히 클 때 헤더의 입력 목록)에서
   - `트랙 (내부 녹음)` 묶음의 트랙 이름(악기 트랙은 "(악기)" 표시) 또는
   - `마스터 (리샘플링)`
   을 고릅니다. 선택하면 표시가 `← 피아노 (시김새 후)`처럼 바뀝니다.
3. 트랙 입력일 때 인스펙터의 **탭**에서 `시김새 전 / 시김새 후 / 페이더 후`를 고릅니다.
   - 시김새 전: 악기(또는 오디오 리전) 출력 그대로, 이펙트 전
   - 시김새 후: 시김새 체인을 지난 소리, 팬·페이더 전 (기본값)
   - 페이더 후: 트랙이 실제로 내보내는 소리 (팬·볼륨·뮤트·솔로 반영)
4. 녹음 활성화(R) 후 녹음합니다. 모니터 `켬/자동/끔`은 하드웨어 입력과 똑같이 동작합니다.
   여러 트랙을 동시에 녹음할 수 있고, 하드웨어 입력 트랙과 섞어서 녹음해도 됩니다.
5. 하드웨어 입력으로 되돌리려면 같은 목록에서 `기본 입력`이나 채널을 고릅니다
   (이전 하드웨어 입력 설정은 그대로 보존되어 있습니다).

입력 변경은 **실행 취소/다시 실행** 한 단계로 기록됩니다 ("트랙 입력 변경"). 녹음 중에는 바꿀 수 없습니다.
트랙 헤더가 작아 입력 상자가 보이지 않을 때도 라우팅된 트랙은 이름 아래에 `← 피아노 (시김새 후)`를 보여 줍니다.

## 3. 규칙

### 되먹임(피드백) 방지
- 트랙은 자기 자신을 입력으로 쓸 수 없습니다.
- A가 (직접 또는 여러 단계를 거쳐) B의 신호를 받고 있으면 B는 A를 입력으로 고를 수 없습니다.
  목록에서 해당 트랙은 `— 되먹임 루프`로 표시되고 비활성화되며, 마우스를 올리면 이유가 나옵니다.
  자동화 등 다른 경로로 요청되면 같은 이유를 알림으로 보여 주고 바꾸지 않습니다.
- **마스터(리샘플링)**: 리샘플링 트랙 자신과, 그 트랙의 신호를 (단계적으로) 받는 트랙들은 리샘플링 입력에 쓰이는
  마스터 피드에서 빠집니다 (Ableton과 같은 방식). 이 트랙들도 평소처럼 마스터 출력으로는 들립니다.
- 손으로 고친 파일 등으로 저장된 루프는 불러올 때 첫 번째 트랙의 입력을 `없음`으로 바꿔 끊습니다.
  두 엔진도 같은 규칙으로 한 번 더 확인합니다.

### 삭제 · 이름 변경 · 복제
- 라우팅은 트랙 **ID**로 저장하므로 원본 트랙 이름을 바꿔도 그대로 유지됩니다.
- 원본 트랙을 삭제하면 그 트랙을 받던 입력은 같은 실행 취소 단계에서 `없음`이 되고 알림이 뜹니다
  (`'베이스 녹음' 트랙은 입력 트랙이 사라져 입력이 '없음'이 되었습니다`). `없음` 상태에서는 무음이 녹음되며
  인스펙터에 경고가 표시됩니다. 실행 취소하면 원본과 라우팅이 함께 돌아옵니다.
- 트랙 복제(설정만 / 설정+내용)는 입력 라우팅을 그대로 복사합니다. 원본과 받는 트랙을 **함께** 복제하면
  복사본끼리 이어집니다 (복사한 받는 트랙이 복사한 원본을 받음). 원본만 복제하면 기존 받는 트랙은 그대로입니다.

### 저장 형식 (스키마 11)
```jsonc
"inputRoute": { "kind": "track", "trackId": "…", "tap": "preFx" | "postFx" | "postFader" }
"inputRoute": { "kind": "master" }
"inputRoute": { "kind": "none" }     // 원본이 삭제됨
```
오디오 트랙에만 허용되며, 스키마 10 이하 파일에 있으면 거부합니다. 존재하지 않는 트랙을 가리키면 불러올 때
`none`으로 바꿉니다. `input`(하드웨어 입력)은 그대로 보존되고, `inputRoute`가 있으면 그것이 우선합니다.

## 4. 엔진 구현과 정렬(타이밍)

내부 경로에는 AD/DA 변환기가 없으므로 **하드웨어 지연 보정(녹음 위치 보정, 드라이버 지연)을 적용하지 않습니다.**
녹음된 샘플은 원본이 같은 타임라인 위치에서 재생하는 샘플과 정렬됩니다.

### 웹 엔진 (Web Audio)
- 그래프: 트랙마다 `input`(시김새 전) → 시김새 체인 → `postFx`(시김새 후, 새 단위 게인) → 팬 → `fader`(페이더 후).
  받는 트랙마다 `RouteGraph { input, monitor }`를 만들고, 원본 탭 노드를 `input`에 연결합니다.
  `input → monitor(게인 0/1) → 트랙 input` 이므로 모니터 게이트는 열고 닫기만 하고, 녹음은 게이트와 상관없이
  `input`에서 받습니다.
- 마스터 피드: 제외되지 않은 트랙들의 페이더 후 신호 합 → `resampleVolume`(마스터 볼륨) → 리샘플링 트랙.
  마스터 컴프레서(6 ms 룩어헤드) **앞**에서 받습니다. 그래서 실시간 리샘플링에는 마스터 다이내믹스가 들어가지
  않으며, 컴프레서 룩어헤드만큼 밀리지도 않습니다.
- 라우팅·탭이 바뀌면 `trackLayoutKey`가 달라져 그래프를 다시 만듭니다. 연결은 정리(reconcile)된 라우팅으로만
  만들기 때문에 Web Audio 순환이 생기지 않습니다.
- 녹음: 받는 트랙마다 `AudioWorkletNode('garak-route-recorder')` 하나가 `RouteGraph.input`을 받습니다.
  모든 테이크에 같은 시작 컨텍스트 프레임을 보내고, 워클릿은 실제 첫 샘플의 `currentFrame`을 돌려줍니다.
  Web Audio는 예약된 소스를 정확한 컨텍스트 시간에 재생하고 같은 렌더 퀀텀 안에서 그래프를 처리하므로,
  `프로젝트 프레임 = (anchorBeat × 박 길이 + 첫 프레임/샘플레이트 − anchorTime) × 샘플레이트`로 정확히 놓입니다.
  재생 중 그래프가 교체되어도(탐색, 샘플 로딩) 녹음 노드는 새 그래프의 같은 입력에 다시 연결됩니다.
  결과는 16비트 스테레오 WAV이며 MediaRecorder(오푸스 압축, 1트랙 제한)를 쓰지 않으므로 라우팅된 트랙은
  **개수 제한 없이 동시에** 녹음됩니다. 하드웨어 입력 트랙은 브라우저에서 계속 1개까지이며, 두 종류를
  한 번에 녹음하면 `combineTakeCaptures`로 하나의 녹음 패스(한 번의 실행 취소)가 됩니다.
- 라우팅 트랙만 녹음·모니터할 때는 마이크 권한을 요청하지 않습니다. 소프트웨어 모니터링 설정(변환기 지연 관련)
  과도 무관하게 내부 입력은 모니터됩니다.

### 네이티브 엔진 (C++)
- 프로토콜: 트랙 JSON에 `route` 필드 (`{kind:"track",trackId,tap} | {kind:"master"} | {kind:"none"}`).
  TS가 이미 루프·누락을 `none`으로 정리해서 보내고, `prepare()`가 다시 검사합니다.
- `prepareRoutes()` (제어 스레드): ID → 그래프 인덱스, 루프와 없는 원본은 `None`(무음), 마스터 피드 표시,
  **처리 레벨** 계산(원본이 받는 트랙보다 앞 레벨), 필요한 트랙에만 탭 버퍼(`preTap`, `postTap`)와
  `routeInput`을 `maxBlock × 2` 크기로 미리 할당합니다. 오디오 스레드에서는 할당하지 않습니다(테스트가 확인).
- 멀티코어: 라우팅이 없으면 레벨이 하나라서 기존 단일 fork 경로와 비트 단위로 같습니다. 라우팅이 있으면
  레벨마다 워커 풀을 한 번씩 돌려, 원본 트랙의 블록이 끝난 뒤 받는 트랙이 같은 블록의 탭을 읽습니다.
  리샘플링 레벨 직전에 마스터 피드(마스터 게인 스무딩 포함, 마스터 프로세서 전)를 계산합니다.
- render-ahead(ASIO-Guard식 미리 렌더)는 받는 트랙과 시김새 전/후 탭이 있는 원본 트랙에는 쓰지 않습니다.
  (페이더 후 탭과 마스터 피드는 미리 렌더된 링의 출력으로도 정확합니다.)
- 녹음 캡처는 트랙 렌더 **뒤**에 같은 콜백 프레임으로 기록됩니다. 라우팅 테이크는 스테레오로, 그 트랙의
  `routeInput`을 그대로 씁니다. 그래서 모든 테이크는 같은 raw 시작 프레임을 공유합니다.
- **정확한 정렬**: 엔진의 지연 보정(PDC) 때문에 시김새 후/페이더 후/마스터 탭은 그래프 지연(`latencyFrames`, 가장
  큰 트랙 플러그인 지연)만큼 늦게 나옵니다. 호스트는 라우팅 테이크의 `compensationFrames`를
  - 시김새 전: `0`
  - 시김새 후 · 페이더 후 · 마스터: `latencyFrames`
  로 보고하고(변환기 입력/출력 지연은 더하지 않음), `startFrame = rawStartFrame − compensationFrames`로 놓습니다.
  하드웨어 테이크는 기존대로 변환기 지연 + 그래프 지연을 뺍니다. `NativeRecordings`는 테이크마다 다른
  보정값을 허용하되 raw 시작 프레임은 같아야 합니다.
- 장치 입력이 필요 없는 경우: 라우팅 트랙만 녹음(`prepareRecording(false)`)하거나 모니터할 때는 입력 장치를
  열지 않고, 호스트의 `record.start`/`monitor.set`도 입력 채널을 요구하지 않습니다.

## 5. 남은 일
- MIDI 녹음, 그리고 트랙을 오프라인으로 굳히는 제자리 바운스/얼리기는 별도 기능입니다([BOUNCE_FREEZE_STEMS.md](BOUNCE_FREEZE_STEMS.md)).
- 실시간 리샘플링은 마스터 프로세서(웹: 컴프레서, 네이티브: `dsp::Master`) **앞** 신호입니다.
  최종 마스터 처리까지 포함한 녹음은 내보내기(WAV)를 쓰세요.
- 네이티브 저지연 모니터링에서 원본 트랙 자체가 하드웨어 입력을 모니터하며 재생 중이면 그 트랙은 PDC를 건너뛰므로,
  그 순간의 시김새 후/페이더 후 탭은 보고한 보정값보다 덜 늦습니다(원본 트랙 플러그인 지연만큼).
- 리턴 트랙(docs/SENDS_RETURNS.md)은 v1에서 입력 목록에 나오지 않습니다(센드와 라우팅이 루프를 만들 수 없도록). 그룹 트랙은 아직 없습니다.
