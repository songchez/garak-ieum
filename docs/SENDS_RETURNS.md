# 센드 · 리턴 트랙 (Aux 버스)

여러 트랙이 **하나의 리버브·딜레이를 함께** 쓰도록, 트랙마다 신호 일부를 **리턴 트랙**으로 보내는 기능입니다.
리턴 트랙은 받은 소리에 자기 시김새 체인을 걸고, 볼륨·팬·뮤트·솔로를 거쳐 마스터로 내보냅니다.

- 데이터: `Track.kind = 'return'`, `Track.sends` (프로젝트 스키마 15, `src/core/types.ts`)
- 순수 로직: `src/core/sends.ts` (만들기, 센드 편집, 삭제·복제 처리, 리턴 문자 A/B/…), `src/core/playback.ts`
  (`audibleTrackIds` 솔로 규칙), `src/core/trackRouting.ts` (처리 레벨·마스터 피드에 리턴 반영)
- 웹 엔진: `src/audio/graph.ts` (`connectSends`, `updateGraph`, `renderTailSeconds`)
- 네이티브 엔진: `native/include/garak/engine.hpp` (`TrackSend`, `TrackTimeline::isReturn`, `senderLatencyFrames`),
  `native/src/engine.cpp` (`prepareRoutes`의 센드 해석, `fillReturnInput`, 리턴 PDC), `native/src/protocol.hpp`
  (`return`, `sends` 필드), `native/src/host.cpp` (라우팅 테이크 보정값), `src/audio/native/timeline.ts`
- UI: `src/components/ChannelStrip.tsx` (센드 구역), `src/components/SendKnob.tsx`, `Mixer.tsx`, `Timeline.tsx`
  (메뉴·리턴 레인), `TrackHeader.tsx` (리턴 문자 배지), `TrackInspector.tsx`

## 1. 다른 DAW 비교

| DAW | 리턴(버스) | 센드 | 프리/포스트 | 솔로 | 지연 보정 |
| --- | --- | --- | --- | --- | --- |
| **Ableton Live** | Return Track A, B…(새 세트에 Reverb·Delay 두 개) | 트랙마다 리턴 수만큼 노브, 기본 −∞ | 리턴별 Pre/Post 토글 (기본 Post) | 솔로해도 리턴은 들림 (Solo in Place) | 리턴 경로 포함 전체 PDC |
| **Logic Pro** | Aux 채널 (Bus 1…로 입력) | 채널 스트립 Sends 슬롯, 노브 | 슬롯마다 Pre/Post/Post Pan | 트랙을 솔로하면 그 트랙이 보내는 Aux도 함께 솔로, Aux를 솔로하면 보내는 트랙도 솔로 | 전체 PDC |
| **Cubase** | FX Channel (인서트를 가진 리턴) | 채널 Sends 8개 | 센드마다 Pre/Post | FX 채널은 솔로 디피트 가능 | 전체 PDC |

가락이음은 **Ableton의 모양**(트랙처럼 보이는 리턴, 리턴마다 작은 노브 하나, A/B 문자)에 **Logic의 솔로 규칙**을
더합니다. 센드는 리턴 하나당 하나이며 기본은 포스트 페이더입니다.

## 2. 사용법

1. 트랙 헤더(또는 레인·빈 영역)를 우클릭해 **리턴 트랙 추가**를 고르면 빈 리턴이 생깁니다.
   **리버브 리턴 추가**는 Ableton처럼 두 개를 한 번에 만듭니다: `대청 Hall`(리버브)과 `메아리 Echo`(딜레이),
   둘 다 **100% 웻**(양 100%, 원음 0%)이라 리턴 페이더가 곧 웻 레벨입니다. 새 프로젝트에는 리턴이 없습니다.
2. 리턴은 타임라인에 낮은 높이의 트랙으로 나타납니다(리전 없음, 빗금 레인, 헤더에 `A`·`B` 배지). 믹서에도 채널로 보입니다.
3. 각 오디오·악기 트랙의 채널 스트립(인스펙터, 믹서)에 **센드** 구역이 생깁니다. 리턴마다 작은 노브 하나:
   - 위아래로 드래그해 레벨 조절 (Shift: 미세), 휠·방향키도 됩니다. 한 번의 드래그가 실행 취소 한 단계입니다.
   - **더블 클릭** 또는 Alt/⌥클릭: −∞로 초기화.
   - 노브 아래 **Post / Pre** 버튼으로 페이더 후(기본) / 페이더 전을 바꿉니다.
4. 리턴 트랙에 라이브러리의 시김새를 끌어다 놓거나 채널 스트립의 `+`로 시김새를 추가합니다(일반 트랙과 같음).
5. 리턴은 볼륨·팬·뮤트·솔로·켬/끔을 가집니다. 녹음 버튼·입력·모니터·센드는 없습니다.

### 규칙
- **레벨**: 0 = 끔(−∞), 1 = 0 dB, 최대 2 = +6 dB(트랙 볼륨과 같은 선형 게인). 노브는 0 dB가 4분의 3 지점입니다.
- **포스트 페이더**: 팬·페이더·뮤트·솔로를 지난 소리. **프리 페이더**: 시김새 체인 뒤, 팬·페이더 앞 소리.
  프리 센드도 트랙이 뮤트되었거나(솔로 때문에) 들리지 않으면 멈춥니다(Logic·Ableton 동작).
- **솔로**: 트랙을 솔로해도 리턴은 들립니다(새 리턴은 솔로 세이프). 솔로 세이프를 끈 리턴은 솔로된 트랙이
  그 리턴으로 보낼 때(레벨 > 0)만 들립니다. 리턴을 솔로하면 그 리턴으로 보내는 트랙들도 함께 들립니다.
- **되먹임 방지**: 리턴은 센드를 가질 수 없고(자기 자신에게도), 다른 트랙의 입력(내부 녹음)으로도 고를 수 없습니다.
  그래서 센드와 입력 라우팅이 어떤 조합으로도 루프를 만들지 못합니다. 손으로 고친 파일에서 리턴의 센드는 거부하고,
  없는 트랙이나 리턴이 아닌 트랙을 가리키는 센드는 불러올 때 지웁니다.
- **삭제·복제**: 리턴을 지우면 그 리턴으로 가던 센드도 같은 실행 취소 단계에서 사라집니다. 트랙 복제(설정만 /
  설정+내용)는 센드를 그대로 복사합니다. 보내는 트랙과 리턴을 **함께** 복제하면 복사본끼리 이어집니다
  (입력 라우팅과 같은 규칙).
- **입력 라우팅·리샘플링**: 마스터 리샘플링은 리턴 출력도 듣습니다. 리샘플링 트랙(과 그 하류)이 보내는 리턴은
  리샘플링 피드에서 빠집니다(자기 소리를 다시 녹음하지 않도록).
- **내보내기**: WAV 내보내기·바운스는 리턴을 포함합니다. 꼬리 길이는 리턴 이펙트 꼬리 + 보내는 트랙의 꼬리입니다.

### 저장 형식 (스키마 15)
```jsonc
{ "kind": "return", "name": "A 리버브", "devices": [ … ], "soloSafe": true, "clips": [] }
{ "kind": "audio", "sends": [{ "returnId": "…", "level": 0.5 }, { "returnId": "…", "level": 0.25, "pre": true }] }
```
스키마 14는 템포 맵(docs/TEMPO_MAP.md), 이 기능의 필드는 15부터입니다. 14 이하 파일에 리턴이나
센드가 있으면 거부합니다. 리턴의 템포 동기 딜레이·트레몰로는 일반 트랙처럼 재생 위치의 템포(템포 맵)를 따릅니다. 리버브와 딜레이에는 `dry`(원음, 기본 1 = 예전과 비트 단위로 같음) 파라미터가 생겼습니다.

## 3. 엔진 구현

### 웹 엔진 (Web Audio)
- 리턴도 일반 트랙과 같은 채널(`input → 시김새 → postFx → 팬 → fader → 미터 → 합`)입니다.
- `connectSends`: 센드마다 `GainNode` 하나. 포스트는 `fader`에서, 프리는 `postFx`에서 받아 리턴의 `input`으로.
  레벨은 `updateGraph`가 파라미터로 바꾸므로 노브를 돌려도 그래프를 다시 만들지 않습니다. 센드 대상·프리/포스트가
  바뀌면 `trackLayoutKey`가 달라져 다시 만듭니다. 프리 센드 게인은 트랙이 들리지 않을 때 0입니다.
- 실시간 재생과 `OfflineAudioContext` 내보내기가 같은 그래프를 쓰므로 내보내기에 리턴이 그대로 들어갑니다.

### 네이티브 엔진 (C++)
- 프로토콜: 트랙 JSON에 `return: true`, `sends: [{ returnId, gain, pre }]`. TS가 이미 없는 리턴을 지워 보내고,
  `prepare()`가 다시 해석합니다(없는 리턴은 무음, 리턴의 센드나 리전은 거부).
- `prepareRoutes()`(제어 스레드): 센드 하나당 리턴 쪽에 `Feed{sender, pre, gain}`를 만들고, 필요한 탭 버퍼
  (프리 = `postTap`, 포스트 = `faderTap`)와 리턴 입력 버퍼를 `maxBlock × 2`로 미리 할당합니다. 리턴의 처리 레벨은
  보내는 트랙들보다 하나 위이므로, 멀티코어에서도 같은 블록에서 보내는 트랙이 모두 끝난 뒤 리턴이 처리됩니다.
  같은 레벨의 리턴끼리는 병렬로 돌며, 센드 게인 스무딩 상태는 리턴 작업만 쓰므로 공유가 없습니다.
- 오디오 스레드는 할당하지 않습니다(테스트가 모든 콜백에서 확인). 센드·리턴 트랙은 미리 렌더(ASIO-Guard식)에서
  빠집니다(같은 블록의 탭을 읽기 때문).
- **지연 보정(PDC)**: 리턴이 아닌 트랙들의 최대 플러그인 지연을 S, 센드를 받는 리턴들의 최대 지연을 L이라 하면
  - 보내는 트랙: 기존처럼 `S − 자기 지연`만큼 늦춘 뒤 탭(프리·포스트 센드, 시김새 후/페이더 후 라우팅 탭)을 뜨고,
    출력만 **L만큼 더** 늦춥니다(`outputDelay`).
  - 리턴: `L − 자기 지연`만큼 늦춥니다.
  - 그래서 마스터에서 원음과 리턴 소리가 S + L에 정확히 맞습니다. `latencyFrames = S + L`, `senderLatencyFrames = S`.
    지연 있는 리턴이 없으면 L = 0이고 예전과 같습니다.
  - 라우팅 테이크 보정: 시김새 전 0, 시김새 후·페이더 후 **S**(`senderLatencyFrames`), 마스터 리샘플링 **S + L**.
- **꼬리**: 리턴의 꼬리 = 자기 이펙트 꼬리 + 보내는 트랙들의 최대 꼬리. 일시정지·소스가 끝난 뒤에도 리턴 이펙트는
  계속 울리고, 오프라인 내보내기 길이에도 반영됩니다.

### 검증
- `native/tests/engine_test.cpp` `sendReturns`: 프리/포스트 × 뮤트 × 단일/워커 2개에서 센드 게인이 정확한지,
  리턴 인서트가 프레임마다 정확히 한 번 처리되는지(카운팅 플러그인), 페이더 0에서 프리만 남는지, 5프레임 지연
  트랙 + 13프레임 지연 리턴에서 임펄스가 원음·리턴 모두 정확히 +18 프레임에 한 번 나오는지, 페이더 후 라우팅
  테이크가 정확히 +5(`senderLatencyFrames`)인지, 워커 스레드와 비트 단위로 같은지, 리턴의 센드 거부, 없는 리턴·
  리턴을 가리키는 라우트가 무음인지, 100% 웻 에코 리턴이 원음을 통과시키지 않고 소스가 멈춘 뒤에도 울리는지.

## 4. 남은 일 (v1 밖)
- 리턴에서 다른 리턴으로 보내기(리턴의 센드), 리턴을 내부 녹음 입력으로 고르기.
- 사이드체인. (센드 레벨 오토메이션은 docs/AUTOMATION.md의 `send` 대상으로 들어갔습니다.)
- MCP에서 센드 편집(지금은 읽기 전용: 트랙 요약의 `kind: 'return'`, `sends`).
- 저지연 모니터링 중인 보내는 트랙은 PDC를 건너뛰므로 그 순간의 센드는 보고한 정렬보다 덜 늦습니다(기존 라우팅과 같은 제약).
