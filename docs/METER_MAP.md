# 박자 변경 (METER_MAP)

곡 안에서 박자표가 바뀌는 기능입니다(예: 4/4 → 3/4 → 7/8). 프로젝트 스키마 18부터 `Project.meterMap`으로 저장합니다. 템포 맵([TEMPO_MAP.md](TEMPO_MAP.md))과 나란히 동작합니다.

## 1. 벤치마크

| 항목 | Logic Pro (Signature 트랙) | Ableton Live (박자 마커) | 가락이음 |
|---|---|---|---|
| 위치 | 글로벌 트랙, 템포 트랙 근처 | 눈금자 위 박자 마커 | 글로벌 트랙 `박자` 행(템포 행 아래, G로 표시) |
| 만들기 | 클릭 → 박자 입력 | 우클릭 → Insert Time Signature Change | 빈 곳 더블클릭 / 우클릭 `N마디에 박자 변경 추가…` / 헤더 `+`(재생 위치 다음 마디) → 분자·분모 팝오버 |
| 위치 단위 | 마디 경계 | 마디 경계 | 마디 경계(마디 번호로 저장) |
| 편집 | 더블클릭으로 값, 드래그로 위치 | 마커 드래그 | 표시 더블클릭(또는 Enter) = 팝오버, 드래그 = 마디 단위 이동, 우클릭·⌫ = 삭제 |
| 마디 번호 | 박자 변경을 따라 다시 매김 | 같음 | 같음 |
| 메트로놈 | 마디마다 첫 박 강세 | 같음 | 같음, 겹박자(6/8 등)는 점4분음표 묶음 강세 유지 |
| MIDI 파일 | FF 58 가져옴/내보냄 | 가져옴 | 가져옴/내보냄 |

## 2. 모델

```ts
interface MeterEvent { bar: number; numerator: number; denominator: 2 | 4 | 8 | 16 }
Project.meterMap?: MeterEvent[]   // 스키마 18
```

- `bar`는 **0부터 세는 마디 번호**입니다(화면에는 `bar + 1`). 박자는 마디 경계에서만 바뀌므로 위치를 박(beat)이 아니라 마디로 저장합니다. 앞쪽 박자를 바꿔도 뒤의 박자 변경은 항상 마디 경계에 남습니다.
- 첫 이벤트는 항상 0마디이고 `Project.timeSignature`와 같습니다. `timeSignature`/`beatsPerBar`는 "1마디의 박자"로 남아서 예전 코드·파일과 호환됩니다.
- 박자는 다음 이벤트까지 이어지고, 마지막 이벤트 뒤로는 끝까지 유지됩니다. 같은 박자를 반복하는 이벤트는 허용합니다(아무것도 바꾸지 않음).
- 박자 변경은 음표를 옮기거나 늘이지 않습니다. 음표·클립·루프 위치는 4분음표 박 단위 그대로이고, 마디로 묶는 방식만 바뀝니다.
- **마이그레이션**: 스키마 1–17 파일은 그대로 열리며 1마디에 박자 이벤트 하나(`timeSignature`)가 생깁니다. 스키마 18 파일은 저장할 때 항상 `meterMap`을 씁니다. 이전 스키마 파일에 `meterMap`이 들어 있으면 무시합니다(스키마 14 전의 템포 맵과 같은 규칙). 스키마 18 파일에서 정렬·중복·첫 이벤트(0마디가 아니거나 `timeSignature`와 다름)·박자 값이 잘못되면 거부합니다.
- 스키마 번호는 `src/core/types.ts`의 `PROJECT_SCHEMA_VERSION`과 `src/core/project.ts`의 `METER_MAP_SCHEMA` 두 곳만 고치면 됩니다.
- **호환성**: 스키마 18로 저장한 프로젝트는 이전 버전 앱에서 열 수 없습니다.

## 3. 변환 모듈 하나

마디 ↔ 박 변환은 모두 [`src/core/meterMap.ts`](../src/core/meterMap.ts)의 `MeterMap`(`meterMapOf(project)`, 프로젝트 스냅샷마다 캐시)을 거칩니다. 박 ↔ 초는 템포 맵 담당이고 둘은 독립입니다(템포는 4분음표 기준, 박자는 4분음표를 마디로 묶을 뿐). 마디 → 초는 `tempoMapOf(p).secondsAt(meterMapOf(p).beatAtBar(bar))`입니다.

- 각 이벤트의 시작 박 = 앞 이벤트 시작 박 + (마디 차이) × 앞 박자의 마디 길이(분자 × 4 / 분모 4분음표).
- `barAt(beat)`, `beatAtBar(bar)`, `position(beat)`(LCD의 마디.박.틱, 박은 그 마디의 분모 단위), `barStart`/`nextBarStart`/`previousBarStart`/`ceilBarStart`/`nearestBarStart`, `snap(beat, step)`(격자는 박자 변경마다 그 마디선에서 다시 시작).
- 네이티브는 [`native/include/garak/meter.hpp`](../native/include/garak/meter.hpp)가 같은 마디 걷기를 합니다. UI가 보내는 `beat`는 마디에서 다시 계산해 다르면 타임라인을 거부합니다.

## 4. 어디에 쓰이는가

| 영역 | 동작 |
|---|---|
| 눈금자·격자 | `meterRulerMarks`/`meterGridStyle`: 박자마다 따로 격자를 만들고, 마디 번호는 이어서 매김. 박자가 하나면 예전 반복 레이어 그대로 |
| 스냅 | 마디 스냅(및 스마트 스냅의 마디 단위)은 각 박자의 마디 길이로, 더 잘게는 박자 변경 지점에서 격자가 다시 시작. 마커 드래그·사이클·재생 위치 스냅도 같음 |
| 재생 위치 표시 | 헤더 LCD 마디.박.틱이 박자 변경을 따름 |
| 이동·루프 | 이전/다음 마디(되감기·빨리감기), 선택으로 루프 지정, 프로젝트 길이 늘이기, 새 패턴(2마디), 가져오기 위치(재생 위치의 마디 시작) |
| 메트로놈(웹) | `meterClicksInRange`: 각 박자의 펄스가 그 첫 마디선에서 다시 시작해 마디마다 첫 박 강세, 겹박자 묶음 유지. 시각은 템포 맵을 따름. 카운트인은 재생 시작 위치의 박자와 템포로 |
| 메트로놈(네이티브) | 타임라인 `meterMap`(박자가 바뀔 때만) → `metronome::meterClicks`. 박자가 하나면 예전 `metronome::clicks` 그대로. 카운트인도 시작 위치의 박자 |
| VST3 | `ProcessContext` 박자표 = 블록 시작 위치의 박자, `barPositionMusic` = 박자 맵의 마디선 |
| MIDI 내보내기 | 박자 변경마다 FF 58 하나(마디선 틱). 클릭 간격(MIDI clock)은 박 단위, 겹박자는 점4분음표 |
| MIDI 가져오기 | 빈 프로젝트의 첫 MIDI 파일이면 FF 58 변경 → 박자 맵. 마디 경계가 아닌 변경은 다음 마디선으로 옮기고 경고, 같은 박자 반복은 버림 |
| 피아노 롤 | 클립 시작 위치의 박자로 격자를 그림(클립 안에서 박자가 바뀌는 경우는 아직 한 박자) |
| MCP | `get_state`의 `project.meterMap`(읽기 전용, `{ bar, beat, numerator, denominator }`), 단위 설명에 마디 번호 주의 |

## 5. 사용법

1. **G**로 글로벌 트랙을 켭니다. `마커`, `템포` 아래에 `박자` 행이 나옵니다.
2. 빈 곳을 더블클릭하면 가장 가까운 마디의 박자 팝오버가 열립니다. 분자(1–32)·분모(2·4·8·16)를 고르거나 프리셋(2/4, 3/4, 4/4, 5/4, 6/8, 7/8, 9/8, 12/8)을 누릅니다. Esc = 취소.
3. 박자 표시를 드래그하면 마디 단위로 옮겨집니다(앞뒤 박자 변경을 넘지 않음). 클릭만 하면 그 위치로 이동합니다.
4. 표시를 더블클릭(또는 Enter)하면 값을 고치고, 우클릭 메뉴나 ⌫/Delete로 지웁니다. 1마디의 박자는 지울 수 없고 헤더 SIGNATURE와 같습니다.

모든 변경은 실행 취소 한 단계입니다(드래그는 놓을 때 한 번).

## 7. 남은 일

- 클립 안에서 박자가 바뀔 때 피아노 롤 격자, MIDI 녹음의 마디 맞춤(`takeSpan`)은 아직 1마디(또는 클립 시작) 박자 하나를 씁니다.
- 퀀타이즈 격자는 박(4분음표) 기준이라 박자 변경과 무관합니다(7/8 뒤의 4분음표 격자가 반 박 어긋날 수 있음).
- 헤더 SIGNATURE는 1마디 박자를 고칩니다(Logic처럼 재생 위치의 박자를 고치지는 않음).
- MCP 명령으로 박자 변경을 만들거나 고치는 기능.
