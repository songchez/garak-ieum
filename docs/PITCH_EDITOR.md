# 피치 편집 사용 안내

이 문서는 현재 구현된 **단선율 피치 편집 디바이스**를 설명합니다. 녹음하거나 가져온 보컬·독주 오디오를 음표와 피치 곡선으로 분석하고, 음표별 음높이·음정 중심 보정·실험적 포먼트 처리를 적용할 수 있습니다. 장기 벤치마크와 개발 범위는 [피치 디바이스 설계](./PITCH_DEVICE_DESIGN.md)를 참고하세요. 설계 문서에 있는 기능이 모두 구현된 상태는 아닙니다.

## 1. 지원 범위

| 항목 | 현재 범위 |
|---|---|
| 편집 대상 | 선택한 오디오 리전의 단선율 보컬·독주 |
| 원본 길이 | 원본 오디오 파일 전체가 60초 이내 |
| 채널 | 모노 또는 스테레오, 1~2채널 |
| 샘플레이트 | 디코딩된 오디오 기준 8,000~192,000 Hz |
| 피치 검출 범위 | 기본주파수 약 55~1,600 Hz인 단선율 |
| 피치 이동 | 원본 대비 음표별 −12~+12반음, 즉 −1,200~+1,200 cents |
| 음정 중심 보정 | 선택 음표를 반음계·장음계·자연 단음계의 가장 가까운 음으로 0~100% 선형 보정 |
| 포먼트 | 추정 포먼트 보존(실험, 기본 OFF), 음표별 ±1,200 cents 이동; 피치와의 내부 보정 차이도 ±1,200 cents 이내 |
| 음표 편집 | 다중 선택, 피치 이동, 가운데 분할, 조건에 맞는 인접 음표 합치기, 피치 초기화 |
| 결과 확인 | 편집 적용 후 DAW 재생 및 WAV 출력 |

60초 제한은 타임라인에서 보이는 리전의 길이가 아니라 **원본 파일 전체 길이**에 적용됩니다. 긴 파일의 일부분을 트림하는 것만으로는 분석할 수 없습니다. 필요한 구간을 짧은 오디오 파일로 준비하여 가져오세요.

스테레오는 같은 단선율의 두 채널을 처리하는 입력 형식입니다. 두 보컬이나 화음의 음표를 각각 분리해서 편집하는 기능을 뜻하지 않습니다. 지원 범위 안의 소리도 녹음 상태, 배음, 비브라토, 잡음에 따라 음표 검출과 변환 결과가 달라질 수 있습니다. 렌더러의 정밀도와 음질은 계속 개선 중이므로, 적용한 결과는 실제로 재생해 확인하세요.

## 2. 시작하기

1. 오디오 파일을 가져오거나 녹음을 마친 뒤, 편집할 **오디오 리전**을 선택합니다.
2. 디바이스 랙의 오디오 소스 카드에서 **피치 편집 열기**를 누릅니다. 하단의 **피치** 탭에서도 같은 편집 공간을 열 수 있습니다. 오디오 리전을 선택하지 않으면 소스 카드의 진입 버튼이 비활성화됩니다.
3. **음표 분석**을 누릅니다. 원본 파일을 분석하며, 진행률과 취소 버튼이 표시됩니다. 편집 격자에는 선택 리전에 해당하는 원본 구간이 나타납니다.
4. 음표 블롭을 선택하고 위아래로 움직이거나, 오른쪽의 **원본에서 이동 / cents**에 값을 입력합니다. 예를 들어 `+100`은 원본보다 한 반음 높게, `−25`는 원본보다 25센트 낮게 이동시킵니다.
5. **편집 적용**을 누릅니다. 렌더링이 끝나고 상태가 **프로젝트에 적용됨**으로 바뀌면 DAW의 재생 버튼이나 Space로 소리를 확인합니다.
6. 결과를 보관하려면 프로젝트 파일 저장 또는 **Ctrl/⌘ S**로 `.garak` 파일을 저장합니다. WAV로 출력하면 적용된 피치 결과가 사용됩니다.

분석만 해도 **미적용 변경** 상태가 됩니다. 피치를 움직이지 않았더라도 분석과 음표 경계를 보관하려면 **편집 적용**을 눌러야 합니다. 피치·포먼트 이동값이 모두 0이면 원본 소리를 유지하면서 분석·편집 정보를 프로젝트에 저장합니다. 포먼트 보존 설정만 켜고 두 이동값을 모두 0으로 둔 경우에도 오디오는 변경하지 않습니다.

미적용 상태에서 DAW를 재생하면 마지막으로 적용한 소리가 나옵니다. 아직 한 번도 적용하지 않았다면 원본이 재생됩니다. 초안을 바꿀 때마다 자동으로 재합성하거나, 별도 미리듣기 엔진으로 들려주는 기능은 현재 제공하지 않습니다.

## 3. 화면 읽기

가로축은 선택 리전의 원본 구간에 해당하는 시간, 세로축은 음높이입니다. 블롭은 분석된 음표 구간을 나타냅니다. 블롭 안의 음이름은 이동값을 반영하며, 가락이음의 다른 편집기와 같은 **MIDI 60 = C3** 표기를 사용합니다.

원본 피치 곡선과 편집 피치 곡선을 구분하여 표시합니다. 편집 곡선은 원본 분석 곡선에 입력한 이동값을 더한 시각화입니다. 렌더링된 소리를 다시 분석하여 정확도를 확인한 그래프는 아닙니다. 한 음표의 cents 값을 바꾸는 것은 그 음표 구간의 피치를 이동시키는 동작이며, 드리프트나 비브라토를 각각 제거하는 도구는 아닙니다.

검출 신뢰도가 낮은 음표에는 점선과 `?` 표시가 나타납니다. 오른쪽의 신뢰도 값은 분석기의 참고 지표이며, 정답 확률이나 음질 보증을 뜻하지 않습니다. 예상과 다른 음표가 보이면 원본을 확인하고, 필요에 따라 분할·합치기를 사용하세요.

포먼트를 이동한 음표에는 `F` 표시가 나타납니다. 피치만 옮긴 음표와 포먼트만 바꾼 음표를 모두 변경 개수에 포함합니다.

**가로 확대** 슬라이더와 전체 리전에 맞춤 버튼으로 표시 범위를 조절할 수 있습니다. 넓어진 격자는 가로로, 음역은 세로로 스크롤합니다.

## 4. 선택과 피치 조작

다음 편집 키는 피치 격자나 음표에 포커스가 있을 때 적용됩니다. 숫자 입력란에서는 숫자 편집과 선택 동작을 우선합니다. **Space는 숫자 입력·드롭다운·버튼에 포커스가 있어도 DAW 재생/일시 정지**입니다. 텍스트 이름 입력·IME 조합·모달에서는 해당 입력을 우선합니다. macOS에서는 `⌘`와 `⌥`, Windows에서는 `Ctrl`과 `Alt`를 사용하세요.

| 조작 | 동작 |
|---|---|
| 음표 클릭 | 음표 선택 |
| Ctrl/⌘ + 클릭 | 음표를 선택에 추가하거나 선택에서 제외 |
| Shift + 클릭 | 기존 선택을 기준으로 연속된 음표 범위 선택 |
| Ctrl/⌘ A | 현재 리전에서 편집 가능한 음표 전체 선택 |
| 위아래 드래그 | 선택 음표의 피치를 반음 단위로 이동 |
| Alt/⌥ + 위아래 드래그 | 선택 음표의 피치를 센트 단위로 이동 |
| ↑ / ↓ | 선택 음표를 100센트 올리기 / 내리기 |
| Shift + ↑ / ↓ | 선택 음표를 10센트 올리기 / 내리기 |
| Alt/⌥ + ↑ / ↓ | 선택 음표를 1센트 올리기 / 내리기 |
| ← / → | 이전 / 다음 음표 선택 |
| −반음 / +반음 버튼 | 선택 음표를 한 반음 내리기 / 올리기 |
| cents 입력 후 Enter 또는 입력란 밖 클릭 | 선택 음표의 원본 대비 이동값 확정 |
| 피치 초기화, Delete 또는 Backspace | 선택 음표의 피치 이동값을 0으로 복원 |
| 음표 더블클릭 | 해당 음표의 피치 이동값을 0으로 복원 |
| Escape | 진행 중인 드래그·분석·렌더 취소, 그 외에는 음표 선택 해제 |
| Space | DAW 재생 / 일시 정지; 일반 화면의 컨트롤 포커스와 무관 |

여러 음표를 선택하여 cents 값을 직접 입력하면 모든 선택 음표가 **각자 원본 대비 같은 이동값**을 갖습니다. 드래그·화살표·반음 버튼은 각 음표의 현재 이동값에 증감값을 더합니다. 이동 한도에 도달한 음표는 한도에서 멈춥니다. 숫자를 입력하는 동안 다른 음표를 클릭해도 입력값은 입력을 시작했을 때의 선택에 적용됩니다.

피치 편집기 안의 Delete·Backspace는 음표 피치 초기화입니다. 타임라인의 리전을 삭제하지 않습니다. 숫자 입력 중 Escape는 입력값을 취소하고 입력란에서 포커스를 뺍니다.

### 음표 분할·합치기

- **분할:** 음표 하나를 선택하여 가운데에서 두 구간으로 나눕니다. 두 구간 모두 기존 피치·포먼트 이동값을 이어받으며, 이후 서로 다른 값으로 편집할 수 있습니다. 나눈 각 구간이 25ms 이상이 되어야 하므로 너무 짧은 음표에서는 버튼이 비활성화됩니다. 임의 위치의 경계 드래그 도구는 아직 없습니다.
- **합치기:** 연속하여 선택한 인접 음표들을 하나로 합칩니다. 선택 음표의 피치 이동값과 포먼트 이동값이 각각 같고, 음표 사이 간격이 50ms 이내일 때 사용할 수 있습니다. 다른 이동값을 가진 음표나 떨어진 음표를 합치는 동작은 지원하지 않습니다.

분할·합치기는 **피치를 편집할 구간**을 정하는 동작입니다. 녹음된 음의 시작 시각이나 길이를 늘이거나 줄이지 않습니다.

리전 시작·끝 경계를 가로지르는 검출 음표는 편집 초안에서 경계에 맞춰 나누어 표시합니다. 따라서 현재 리전에 보이는 부분을 독립적으로 이동시킬 수 있습니다. 기준 분석과 원본 오디오는 유지됩니다.

문서당 4,096개 음표 한도 때문에 경계 분할을 할 수 없으면 해당 경계 음표는 보기만 가능합니다. 보이지 않는 원본 구간까지 함께 바꾸는 것을 막기 위한 제한입니다. 리전 범위를 넓히거나 다른 음표들을 합쳐 공간을 확보하면 편집할 수 있습니다. 내부 음표는 계속 편집할 수 있습니다.

### 음정 중심을 음계에 맞추기

1. 보정할 음표를 선택합니다. 선택이 없을 때 전체 음표에 자동 적용하지 않습니다.
2. 오른쪽에서 **기준음**, **음계**(반음계·장음계·자연 단음계), **보정 강도**(0~100%)를 정합니다.
3. 필요하면 기본 ON인 **신뢰도 75% 미만 제외**를 끕니다. 이 수치는 검출 참고 점수이며 정답 확률이 아닙니다.
4. **선택 음표 보정**을 누릅니다. 현재 수동 이동값까지 반영한 중심음에서 가장 가까운 음계 음을 찾습니다. 정확히 중간이면 낮은 음을 선택합니다.
5. 초안의 위치를 확인하고 **편집 적용**을 눌러 소리에 반영합니다.

강도는 남아 있는 중심 오차에 곱하는 선형 비율입니다. 예를 들어 목표보다 40센트 낮은 음표에 50%를 실행하면 20센트 올라갑니다. 50%를 다시 실행하면 남은 20센트의 절반인 10센트가 더 올라갑니다. 0%는 변경하지 않으며, 누적 ±1,200센트 한도 때문에 목표에 닿지 못한 음표는 개수를 알려 줍니다. 한 번의 보정은 로컬 Undo 한 단계입니다.

기준음·음계·강도 설정만 바꾸어서는 음표나 소리가 변하지 않습니다. 이 도구 설정은 프로젝트 ID별 세션 메모리에 보존하여 같은 프로젝트의 리전·탭을 다시 열 때 복원합니다. `.garak`·자동 저장·Undo에는 포함하지 않으며 새 프로젝트는 기본 설정을 사용합니다. 음표마다 일정한 이동값을 더하므로 원본 분석 곡선과 비브라토 형태를 직접 평탄화하지 않습니다.

이 동작은 [Celemony의 음정 중심 보정 워크플로](https://helpcenter.celemony.com/M5/doc/melodyneStudio5/en/M5tour_MacroPitch?env=dawsWithAra)를 참고했습니다. Melodyne의 강도 매크로는 낮은 강도에서 큰 음정 오차를 우선 처리하며, 선택이 없을 때의 범위와 수동 편집 음표 처리도 다릅니다. 현재 구현은 명시적인 선택과 선형 비율을 사용하며 동일한 매크로 알고리즘이나 실시간 미리듣기를 제공하지 않습니다.

### 포먼트 보존과 이동 — 실험 기능

**포먼트 보존 (실험)**은 새 분석에서 기본 OFF입니다. ON이면 피치를 옮길 때 원래의 스펙트럼 포락선에 가깝게 음색을 보정하도록 요청합니다. 선택 음표의 **포먼트 이동**은 피치 값과 별도로 ±1,200센트 안에서 입력하며, **포먼트 초기화**는 그 이동값만 0으로 되돌립니다.

| 설정 | 포먼트 이동의 기준 |
|---|---|
| 보존 ON | 원래 스펙트럼 포락선을 기준으로 입력한 만큼 이동을 요청 |
| 보존 OFF | 피치 이동을 따라 변한 포락선에 추가로 입력한 만큼 이동을 요청 |

내부에서 `포먼트 이동 − (보존 ON이면 피치 이동, OFF이면 0)`만큼 먼저 포락선을 보정합니다. 이 차이도 ±1,200센트 안이어야 적용할 수 있습니다. 예를 들어 피치 +1,200, 포먼트 −1,200, 보존 ON은 내부 −2,400센트가 되어 적용을 막습니다. 포먼트 이동을 줄이거나 보존을 끄면 다시 적용할 수 있습니다. 입력·초안 편집은 계속 가능하므로 값을 조정하거나 Undo할 수 있습니다.

이 처리는 추정 방식이며 소스에 따라 음색과 음량이 달라집니다. 합성 모음 시험에서도 보존 오차가 남았으므로 실험 기능으로 표시합니다. 포먼트를 ±600센트보다 크게 옮기거나 보존 ON에서 피치를 ±600센트보다 크게 옮기면 별도 안내를 표시합니다. 제한 안의 요청도 완전한 보존이나 동일한 청감을 보장하지 않습니다.

검증한 182개 허용 렌더에서 강한 배음으로 추정한 기본주파수 최대 오차는 약 0.01142센트였지만, 63개 사례에 포락선·레벨 품질 표시가 남았습니다. 소스 peak 0.65에 대해 출력 peak는 최대 1.16725, RMS 증가량은 최대 약 1.32544 dB였습니다. 렌더러는 이를 몰래 정규화하거나 잘라내지 않으므로 트랙·마스터 게인과 실제 출력을 확인해야 합니다. 이 수치는 합성 시험의 측정이며 자연 보컬 청음 결과가 아닙니다. [전체 측정값](assets/pitch-formant-metrics.json)과 [재현 방법](../scripts/pitch-poc/README.md#formant-experiment)을 제공합니다.

## 5. 원본·분석·초안·적용 결과의 관계

| 데이터 | 역할 | 언제 바뀌는가 |
|---|---|---|
| 원본 오디오 | 분석과 재합성의 기준이 되는 파일과 PCM | 피치 편집으로 덮어쓰지 않음 |
| 기준 분석 | 검출 음표, 연속 피치 곡선, 신뢰도, 분석 샘플레이트·길이 | 사용자가 분석·다시 분석을 실행할 때 새로 생성 |
| 편집 문서 | 원본 식별자·해시, 기준 분석, 분할·합친 구간, 음표별 피치·포먼트 cents 이동값, 보존 설정, 렌더러 식별자 | 초안 편집 및 적용 시 갱신 |
| 미적용 초안 | 마지막 적용 상태 이후의 분석·편집과 로컬 Undo/Redo | 편집기에서 작업하는 동안 세션 메모리에 보관 |
| 적용된 렌더 | 원본에 편집 문서를 반영한 재생용 오디오 | 편집 적용이 성공한 뒤 선택 리전에 연결 |

렌더링은 매번 보관된 원본과 편집 문서를 기준으로 실행합니다. 이미 변환한 오디오를 다시 원본처럼 사용하여 변경을 누적하지 않습니다. 같은 원본을 사용하는 다른 리전의 오디오도 덮어쓰지 않습니다.

원본 파일의 SHA-256 해시를 분석과 적용 시 확인합니다. 저장된 문서와 원본이 다르거나, 필요한 원본을 찾을 수 없으면 적용을 중단합니다. 해시 계산에는 HTTPS 또는 localhost와 같이 브라우저의 보안 기능을 사용할 수 있는 환경이 필요합니다.

분석·렌더 중에는 편집 컨트롤이 잠기고 취소할 수 있습니다. 취소하거나 실패하면 마지막으로 적용된 오디오를 유지합니다. 작업 중 리전이나 프로젝트의 기준 상태가 바뀌어도 오래된 결과를 현재 프로젝트에 붙이지 않습니다.

### 다시 분석

**다시 분석**은 보관된 원본으로 새 분석 초안을 만듭니다. 기존의 수동 분할·합치기와 피치·포먼트 이동값을 새 분석에 자동으로 옮기지 않으며, 포먼트 보존도 새 분석의 기본 OFF로 시작합니다. 새 초안을 적용하기 전까지 기존의 적용된 소리는 유지되며, **변경 취소**를 누르면 마지막 적용 상태로 돌아갑니다. 미적용 초안이 있을 때는 먼저 적용하거나 취소해야 다시 분석할 수 있습니다.

### 원본 복원과 변경 취소

| 버튼 | 동작 |
|---|---|
| 변경 취소 | 현재 리전의 미적용 초안을 버리고 마지막 적용 상태로 돌아감. 적용 이력이 없으면 분석 전 상태로 돌아감 |
| 피치 초기화 | 선택한 음표의 이동값만 0으로 변경. 분석과 음표 구간은 유지하며, 소리에 반영하려면 적용 필요 |
| 포먼트 초기화 | 선택 음표의 포먼트 이동값만 0으로 변경. 보존 설정과 피치 이동은 유지 |
| 원본 복원 | 선택 리전의 적용된 피치 문서를 해제하고 원본 오디오를 다시 연결. 적용된 편집이 있을 때 사용 가능 |

## 6. 실행 취소와 다시 실행

**적용 전에는 편집기 안의 로컬 이력**을 사용합니다. 피치 편집기에 포커스를 두고 **Ctrl/⌘ Z**로 음표 이동·분할·합치기 등을 되돌리고, **Shift + Ctrl/⌘ Z**로 다시 실행할 수 있습니다. 한 번의 드래그는 한 번의 되돌리기 단위입니다.

**편집 적용이 성공하면 DAW의 프로젝트 이력에 한 단계로 기록**됩니다. 적용에 쓰인 분석·편집 문서와 재생 오디오를 함께 되돌릴 수 있으며, 해당 초안의 로컬 이력은 비워집니다. **원본 복원**도 DAW 이력에 기록되므로 실행 취소로 적용된 피치 편집을 다시 가져올 수 있습니다.

편집기에 실행할 로컬 Undo/Redo가 없으면 같은 단축키가 DAW의 프로젝트 이력으로 전달됩니다. DAW의 되돌리기로 이미 적용된 피치 문서 자체가 달라지면 초안의 기준 충돌을 알리고 초기화합니다. 리전 위치·트림·길이·BPM 변경은 원본 초 단위 편집을 보존하고 새 표시 범위를 계산합니다.

## 7. 세션 초안과 `.garak` 저장

프로젝트 스키마는 **3**, 그 안의 피치 편집 문서는 **2**입니다. 이전 피치 문서 v1을 열면 보존 OFF·빈 포먼트 이동값을 추가해 v2로 읽되, 원본과 기존 적용 렌더를 그대로 사용합니다. 새 버전으로 열었다는 이유만으로 기존 소리를 다시 렌더링하지 않습니다. 새 v2의 두 이동값·보존 설정도 Undo/Redo와 저장·복원에 포함됩니다.

다른 리전을 선택하거나 다른 하단 탭으로 이동해도, 동일 프로젝트에서 기준 리전이 그대로라면 미적용 초안·선택·로컬 Undo/Redo를 세션 메모리에 보관합니다. 다시 돌아오면 초안을 복원합니다. 여러 리전에 초안이 남아 있을 수 있습니다.

**세션 초안은 `.garak` 파일이나 브라우저 자동 저장에 포함되지 않습니다.** 새로고침이나 브라우저 종료 후 복구되는 영구 저장이 아닙니다. 이름·타임라인 위치·게인·리전 트림·길이·프로젝트 BPM 변경에서도 같은 원본과 적용 기준이면 초안을 유지합니다. 트림과 BPM은 표시 범위에 반영하고 음표 편집의 원본 시간 좌표를 보존합니다. 원본 교체·리전 삭제·프로젝트 전환은 해당 초안을 정리하며, 이미 적용된 피치 문서를 바꾸는 Undo/Redo는 기준 충돌을 알려 초안을 초기화합니다.

미적용 초안이나 진행 중인 분석·렌더가 있으면 프로젝트 파일 저장·WAV 출력·새 프로젝트·프로젝트 열기 동작을 멈추고 피치 편집기로 안내합니다. 초안이 있는 리전을 **편집 적용**하거나 **변경 취소**한 뒤 진행하세요. 다른 리전에도 초안이 있으면 그 초안도 처리해야 합니다. 브라우저를 떠날 때에도 저장되지 않은 작업에 대한 확인을 요청하지만, 초안이 자동으로 영구 보관되는 것은 아닙니다.

적용 후 `.garak`에는 다음 항목이 함께 저장됩니다.

- 원본 오디오와 현재 리전이 재생하는 적용 오디오 자산.
- 원본 식별자·해시와 렌더러 식별자.
- 편집의 기준이 된 분석 음표·피치 곡선.
- 분할·합친 음표 구간과 음표별 cents 이동값.
- 피치 편집을 참조하는 리전 및 프로젝트 상태.

파일을 다시 열면 저장한 분석·편집을 기준으로 작업을 이어가며, 저장한 적용 오디오로 재생합니다. 피치를 움직이지 않은 적용은 원본 오디오를 재사용할 수 있습니다. `.garak`는 편집을 이어가기 위한 프로젝트 파일이고, WAV 출력은 현재 적용 결과가 포함된 오디오 파일입니다.

## 8. 현재 제공하지 않는 기능

다음 항목은 이번 구현의 지원 범위에 포함되지 않습니다.

- 음표의 시작·끝 시각 이동, 길이 변경, 타임 스트레치, 오디오 타이밍 퀀타이즈.
- 피치 드리프트·모듈레이션·전이를 각각 조정하는 정밀 도구. 포먼트 처리는 앞서 설명한 실험적 추정 방식까지 지원합니다.
- 피아노·기타 화음 등 다성 오디오의 개별 음 분리와 편집, 완성 믹스의 악기 분리.
- 라이브 마이크 입력의 실시간 피치 보정·모니터링, 적용 전 초안의 실시간 미리듣기.
- 곡 전체의 키·코드 자동 검출, 코드 변화에 따른 보정, 음계를 따르는 드래그 격자, Audio-to-MIDI. 명시적으로 선택한 음표의 중심 보정만 지원합니다.
- 음표별 게인·치찰음·호흡·배음 편집과 여러 리전의 동시 피치 편집.
- 외부 ARA 연동, VST/AU/CLAP 플러그인 호스팅.
- MCP를 통한 피치 분석·음표 편집·렌더 명령.

센트 입력 단위는 조작의 해상도이며, 렌더 결과의 측정 정확도를 보증하지 않습니다. 분석·렌더 정확도와 청감 품질은 별도로 검증하고 개선해야 합니다. 이번 구현을 Melodyne 전체 기능이나 동일 음질의 완성으로 소개하지 않습니다.

## 9. 개발 구조

피치 편집은 [`src/devices/pitch-editor/`](../src/devices/pitch-editor/) 안에서 모델, 분석, 렌더, Worker 클라이언트, 전용 UI를 나눈 **리전 처리 모듈**입니다. 기존 실시간 인서트처럼 트랙의 효과 순서 사이에 끼우는 방식이 아니라, 오디오 소스 영역에서 선택 리전의 편집기를 엽니다.

분석과 음표 구간의 시간은 원본 오디오의 초 단위를 사용합니다. 프로젝트 박자·BPM으로부터 리전이 보여 주는 원본 범위를 계산하며, 현재 피치 편집은 오디오의 길이나 프로젝트 배치를 바꾸지 않습니다. 적용된 결과는 기존 리전 게인·페이드, 트랙 효과 및 믹서 경로를 통해 재생됩니다.

이번 모듈화에는 기존 여섯 효과(EQ·필터·컴프레서·드라이브·딜레이·리버브)의 정의와 DSP를 분리하는 작업도 포함됩니다. 신스 악기 합성은 아직 중앙 오디오 엔진에 있으므로, 모든 디바이스가 독립 모듈화되었다고 보지는 않습니다. 모듈 경계는 [아키텍처](./ARCHITECTURE.md), 현재 외부 제어 범위는 [MCP 안내](./MCP.md)를 참고하세요.

## 10. 실제 브라우저에서 확인할 흐름

자동 검사와 별개로 다음 실제 조작·청음 확인이 남아 있습니다.

1. `node scripts/pitch-poc/run.mjs --out /tmp/garak-pitch-poc`로 생성한 `motif-original.wav` 또는 60초 이내 보컬·독주를 가져오고, 피치 편집을 열어 분석합니다.
2. 한 음표를 반음·센트 단위로 이동한 후 적용합니다. DAW에서 재생하고 원본 복원/Undo/Redo로 비교합니다.
3. 기준음·음계·강도를 바꾸어도 음표는 유지되는지, 선택 보정 한 번이 Undo 한 단계인지, 신뢰도 제외가 선택 밖 음표를 바꾸지 않는지 확인합니다. 초안을 만든 채 믹서 탭과 다른 리전으로 이동한 뒤 돌아와 도구 설정과 초안이 복원되는지도 확인합니다.
4. 분석·렌더 중 취소, 리전 변경, 다른 탭 이동을 해보고 늦게 도착한 결과가 적용되지 않는지 확인합니다.
5. 적용 상태를 `.garak`로 저장하고 새로 연 뒤 원본·편집 음표·소리를 확인합니다. 프로젝트 레이트가 다른 환경에서도 길이가 유지되는지 확인합니다.
6. WAV를 출력하여 DAW 재생과 비교하고, 자연 보컬의 자음·어택·비브라토·음표 경계에서 음질을 평가합니다.
7. 같은 원본에 포먼트 보존 OFF/ON과 포먼트만 ±200센트 이동을 각각 적용하고 음색·음량·자음 손상을 비교합니다. 금지 조합은 적용을 막고 값을 줄이면 풀리는지 확인합니다.
8. 드롭다운·노브·숫자 입력·메뉴에 포커스를 둔 채 Space/Shift+Space와 길게 누르기를 확인합니다. 이름 입력은 공백을 입력하고, 설정 모달 안의 Space는 그 컨트롤을 작동시켜야 합니다.

자동 실험의 원본·편집본은 위 명령의 출력 폴더에 `motif-original.wav`·`motif-edited.wav`로 생성합니다. [측정 결과](assets/pitch-editor-metrics.json)는 저장소에 함께 제공합니다. 실험 재현 명령은 [DSP POC](../scripts/pitch-poc/README.md)에 있습니다. 이 파일은 합성 시험 음원이며 실제 사용자 녹음을 업로드해 만든 결과가 아닙니다.
