# 가락이음 로드맵

**0.3.3까지의 개발 프리뷰를 기준으로 씁니다.** 앞부분은 지금까지 실제로 만든 것, 뒷부분은 다음 방향과 완료 기준입니다. 다음 방향은 개발 순서의 판단이지 출시 일정의 약속이 아닙니다. 현재 사용할 수 있는 기능은 [README](../README.md), 실행 구조는 [아키텍처](ARCHITECTURE.md), 소스에 연결된 기능과 검증 기록은 [구현 상태](IMPLEMENTATION_STATUS.md)를 따릅니다.

엔진 결정은 끝났습니다. 자체 통합 Rust 엔진 하나를 두 호스트가 함께 쓰고, openDAW나 다른 외부 DAW 엔진은 통합하지 않았습니다. 데스크톱의 C++는 장치 I/O·전송·VST3 호스트 노드·녹음·render-ahead 링을 맡는 얇은 셸입니다. [RUST_ENGINE](RUST_ENGINE.md)

이전 로드맵의 "2.0 로컬 네이티브 플러그인" 단계는 데스크톱 앱으로 먼저 들어왔습니다. VST3 악기·인서트, 원래 플러그인 창, 상태 저장, 플러그인 지연 보상, 같은 그래프의 오프라인 렌더가 동작합니다. 남은 것은 타사 제품 호환성과 격리입니다(아래 E).

## 버전 방향

| 단계 | 목표 | 현재 상태 |
| --- | --- | --- |
| 0.3.x | 하나의 엔진 위에서 기능·안정성 다듬기 | 진행 중 |
| 1.0 | 일상적인 곡 작업에 쓸 데스크톱 앱 + 같은 엔진의 웹 편집기 | 개발 중 |
| 이후 | 플러그인 형식 확장, 협업·클라우드 같은 서비스 기능 | 검토 단계 |

1.0의 기준은 기능 수가 아니라 신뢰입니다. 작업을 잃지 않고, 들리는 소리와 내보낸 파일이 같으며, 지원한다고 표시한 기능이 실제 장치에서 동작해야 합니다.

## 다음 방향

### A. 작업 보존과 복구

- 0.3.3의 자동 저장 스케줄러(최대 대기 5초, 닫기·숨기기·Ctrl+S 즉시 저장)를 실제 사용 패턴(긴 세션, 큰 오디오, 저장 공간 부족)에서 검증.
- 브라우저 종료·손상 파일·중단된 쓰기의 복구 흐름과, 복구할 수 있는 것과 없는 것의 구분.
- 큰 `.garak` 파일의 base64·JSON 메모리 부담, 원본 음원 장기 보존과 형식 이전 정책.
- 편집 이력의 경계를 모든 조작에 일관되게(제스처 한 번 = 실행 취소 한 번).

**완료 기준:** 오디오를 포함한 프로젝트를 저장하고 앱이나 브라우저를 다시 연 뒤 리전·음표·믹서·시김새·플러그인 상태가 복원되는 것을 지원 환경에서 확인합니다. 저장 실패를 성공으로 표시하지 않습니다.

### B. 편집

- 리전 일부를 고르는 Marquee 편집, 타임라인에서 직접 그리는 페이드·크로스페이드.
- 오디오 워프 마커·구간별 시간 늘이기, 첫 박 자동 정렬, 오디오 리전 퀀타이즈.
- E/P 편집기 단축키, 명령 검색·사용자 키맵, 다중 리전 피아노롤.
- 믹서 그룹·VCA, 버스 폴더 같은 라우팅 확장(센드·리턴·트랙 라우트는 있음).

**완료 기준:** 편집 화면의 변화가 실시간 재생과 내보내기에 같은 의미로 반영되고, 지원하지 않는 기능을 활성화된 것처럼 보여 주지 않습니다.

### C. 녹음과 장치

- 입력·출력 지연 자동 측정과 녹음 위치 보정의 정확도 검증(지금은 드라이버 보고 지연과 수동 ms 정렬).
- 물리 다중 입력 동시 녹음과 긴 녹음의 디스크 기반 저장 경로.
- 실제 인터페이스·드라이버 조합의 연결 변경·절전·재연결 동작 기록.

**완료 기준:** 알려진 기준 신호로 녹음 배치 오차를 측정해 조건과 함께 기록합니다. 샘플 단위 정렬을 측정으로 보이기 전에는 보장한다고 쓰지 않습니다.

### D. 엔진·성능

- 장시간 재생 소크 테스트(엔진 계획의 G4)와 실제 장치 스트레스 검증.
- 디스크 기반 자산 스트리밍: 0.3.3에서 메인 스레드 사본은 없앴지만, 엔진은 여전히 자산 PCM을 메모리에 둡니다.
- IEUM WAVE 테이블 메모리를 엔진의 512 MB 예산 계산에 넣기.
- render-ahead 중인 트랙의 분석 탭: 지금은 콜백이 렌더한 마지막 블록을 보여 줍니다.
- 트랙 수·동시 음성·시김새 조합별 CPU·메모리 벤치마크 공개. 측정 전에는 특정 트랙 수 지원을 보장하지 않습니다.

**완료 기준:** 브라우저·CPU·운영체제·샘플레이트·트랙 수를 명시한 측정을 공개하고, 끊김과 편집 반응을 함께 기록합니다.

### E. 플러그인

- 타사 VST3 제품별 호환성 검증과 알려진 문제 목록, 문제 플러그인 격리(지금은 호스트 프로세스 하나가 엔진과 플러그인을 함께 실행).
- 사이드체인 입력, 플러그인 MIDI 출력 라우팅, 멀티 출력 악기.
- CLAP·AU는 형식마다 따로 설계하고 검증합니다. VST3 지원이 다른 형식 지원을 뜻하지 않습니다.

**완료 기준:** OS별 실제 악기·이펙트 조합을 기록하고, 플러그인 하나의 실패가 어디까지 영향을 주는지 명시하며 상태 복원과 안내를 구현합니다.

### F. 피치 편집·AI·코드 작곡

- 피치 편집기: 실제 보컬·독주 청음 검증, 포먼트 처리 품질, 드리프트·비브라토·타이밍 편집, 피치 MCP 명령. 다성 분리는 별도 연구입니다. [PITCH_EDITOR](PITCH_EDITOR.md)
- MCP: UI에 있는 편집 명령을 차례로 노출하고, 범위 렌더와 객관적인 오디오 측정을 결과에 붙입니다. [MCP](MCP.md)
- 코드 작곡: [비교 실험](COMPOSITION_LANGUAGE_POC.md)을 바탕으로 유한 패턴 → 음표 이벤트 → 트랙·리전 → 한 번의 실행 취소 경로. 앱 안 코드 실행기는 아직 넣지 않았습니다.

**완료 기준:** 자연어 요청의 대상·범위를 실제 상태와 대조하고 한 번의 실행 취소로 되돌립니다. 자동 테스트 통과를 청음 검증으로 대신하지 않습니다.

### G. 배포와 재현성

- 지원 브라우저·운영체제와 실제로 확인한 조합의 목록.
- 고정 의존성·잠금 파일로 개발·테스트·배포 빌드 재현, 골든 레퍼런스 패리티를 CI(MSVC·macOS arm64)에서 유지.
- 키보드·접근성·다양한 화면 폭의 편집 경로 점검, 버전별 변경 기록과 알려진 문제 정리.

## 이후 검토할 서비스 기능

클라우드 프로젝트 보관, 기기 간 동기화, 공유·협업, 원격 렌더링은 현재 제품 기능이 아니며 별도 설계 대상입니다. 정적 웹 페이지를 배포하는 것과 오디오 엔진을 서버에서 실행하는 것을 구분합니다. 사용자 PC에 설치된 상용 가상악기가 서버나 다른 사용자의 브라우저에서 실행된다고 가정하지 않습니다. 현재 우선순위는 로컬 작업의 보존·편집·재생 품질입니다.
