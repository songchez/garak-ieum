# MIDI 파일 가져오기

프로젝트를 연 뒤 **가락이음 메뉴 → 오디오·MIDI 가져오기…**를 선택하거나, 오른쪽 파일 브라우저의 **오디오·MIDI 가져오기** 버튼을 사용합니다. `.mid`, `.midi`, `.smf` 파일을 타임라인에 직접 놓을 수도 있습니다. MIDI는 오디오 디코더를 거치지 않고 편집 가능한 음표와 MIDI 리전으로 들어옵니다.

## 트랙과 배치

- 여러 MIDI 트랙·채널은 각각의 악기 트랙으로 분리되며 원본의 상대적인 박 위치를 유지합니다.
- 단일 파트 파일을 기존 악기 레인에 놓으면 해당 악기와 음색을 유지합니다. 이음웨이브의 사용자 파형·변조 설정도 유지됩니다.
- 빈 영역에 놓거나 파일 선택으로 가져오면 새 트랙을 만듭니다. 일반 채널은 기본 건반, MIDI 채널 10은 기본 드럼 음색을 사용합니다. General MIDI의 모든 음색을 재현하는 기능은 아니며, 악기 지정이 있는 파일은 안내를 표시합니다.
- 레인에서 마우스 오른쪽 버튼을 누른 뒤 **MIDI 파일 가져오기…**를 선택할 수도 있습니다. 드롭 위치는 현재 마디 시작으로 맞춥니다.
- 여러 파일을 한 번에 가져오면 전체 편집을 준비한 뒤 적용합니다. 파일 하나라도 읽지 못하면 그 묶음의 트랙·음원은 추가하지 않습니다. 가져오기 한 번은 실행 취소 한 번으로 되돌릴 수 있습니다.

## 템포와 박자

이미 작업 중인 프로젝트와 오디오·MIDI를 함께 가져오는 경우에는 현재 프로젝트의 템포·박자를 유지합니다. 음표는 MIDI 파일에 기록된 4분음표 박 위치로 배치되어 프로젝트 템포에 맞춰 재생됩니다.

트랙과 마커가 전혀 없는 새 프로젝트의 시작 위치에 MIDI 파일 하나만 가져오면 초기 템포와 박자를 적용합니다. 앱이 지원하지 않는 템포·박자는 기존 값을 유지하고 이유를 표시합니다. 곡 중간의 템포·박자 변경은 아직 자동화로 가져오지 않으며, 변경이 있는 파일에는 안내를 표시합니다.

## 지원 범위

| 항목 | 동작 |
| --- | --- |
| Standard MIDI File | Type 0 / Type 1, PPQ 박자 기반 타이밍 |
| 음표 | 음높이, 시작, 길이, velocity, velocity 0 Note On의 Note Off 처리 |
| 반복·겹친 음표 | 같은 음높이도 개별 음표로 가져오며 종료는 먼저 시작한 음에 대응 |
| 서스테인 | CC64 페달을 음표 길이에 반영 |
| 노트 종료 컨트롤 | All Sound Off / All Notes Off / Reset Controllers 처리 |
| 트랙 정보 | 이름, 채널 분리, MIDI 포트 간 구분, 초기 프로그램 정보 |
| Running status | 정상적인 SMF channel-message running status 지원 |
| Type 2 / SMPTE | 지원하지 않는 이유와 Type 0/1 PPQ로 다시 저장하는 방법 안내 |
| 피치 벤드·애프터터치·대부분의 CC·SysEx | 자동화·장치 음색으로 가져오지 않으며 해당 데이터가 있으면 안내 |

종료 이벤트가 빠진 음표는 해당 트랙 끝에서 마무리하고 안내합니다. 반면 헤더·청크·가변 길이 데이터가 잘렸거나 트랙 종료 구성이 잘못된 파일은 오류로 처리하여 기존 작업을 보존합니다.

파일당 한도는 **16 MiB, 256개 출력 파트, 100,000개 Note On, 500,000개 이벤트, 24,000개의 4분음표 박**입니다. 프로젝트 전체 트랙 한도는 256개입니다. 한도를 넘는 파일은 구간이나 트랙을 나누어 가져옵니다.

## 구현과 검증

`src/core/midiImport.ts`가 바이너리를 읽고, `src/core/mediaImport.ts`가 프로젝트 변경 전체를 준비합니다. App의 파일 선택과 Timeline의 드롭이 동일한 경로를 사용합니다. 파서는 파일 읽기 외부 작업이나 오디오 장치 시작을 하지 않습니다.

```sh
pnpm exec vitest run src/core/midiImport.test.ts src/core/mediaImport.test.ts
```

테스트는 실제 인코딩된 SMF 바이트로 형식 0/1, running status, 겹친 음, 서스테인, 채널·포트 분리, 메타데이터, 손상된 청크와 길이 한도를 검사합니다. 프로젝트 계획 검사는 기존 WAVE 음색 보존, 트랙 분리, 템포·박자 유지, 혼합 파일 가져오기와 Undo/Redo를 확인합니다.
