# 가락이 머무는 집 — 다운로드 랜딩 기획

2026-11-03 · **기획안 / 미구현 / 미공개**

이 문서는 가락이음 설치 파일을 받을 수 있는 랜딩의 방향과 제작 범위를 정리합니다. 사이트 구현, 새 시각·음원 자산 제작, 공개 Release 게시, 다운로드 주소 확정은 아직 수행하지 않았습니다. 다음 제작 작업에서 이 문서를 기준으로 이어갑니다.

현재 진행 중인 GPL 전환의 대상 버전은 0.1.1입니다. 이는 **랜딩에서 제공할 공개 릴리스의 버전·파일명·용량·URL을 확정했다는 뜻이 아닙니다.** 화면에 표시할 배포 정보는 실제 공개 파일과 검증 결과가 준비된 뒤 메타데이터로 반영합니다. 코드·자산·대응 소스 제공 범위는 [라이선스와 소스 배포](LICENSING.md)를 따릅니다.

## 1. 중심 방향

**한옥의 공간에서 음악이 한 겹씩 쌓이고, 사용자의 Windows 작업실로 이어지는 경험**을 제안합니다.

처마의 곡선은 소리가 이어지는 선으로, 문살의 간격은 음표와 박자의 격자로, 마당의 여백은 여러 소리가 만나는 자리로 표현합니다. 빛, 재료의 질감, 간격, 주고받는 움직임은 이 기획에서 한국의 정서를 표현하는 디자인 선택입니다. 특정 공간이나 음악의 역사적 의미를 설명하는 주장으로 사용하지 않습니다.

첫 화면에서 제품의 이름·용도·Windows 지원 범위와 설치 파일 받기가 바로 보여야 합니다. 장면을 더 살펴보는 방문자에게는 **한 음 → 합주 → 편집 → 내 작업실**의 흐름을 제공합니다.

주 CTA는 페이지 전체에서 **Windows 설치 파일 받기 (.exe)**로 통일합니다. 설치 버튼 주변에는 같은 배포본의 **소스 다운로드 (GPLv3)** 보조 링크와 [라이선스 안내](LICENSING.md)를 함께 둡니다. 소스 ZIP은 개발·수정용 파일이며, 일반 설치 동작은 EXE 직접 다운로드로 구성합니다.

## 3. 다섯 장면의 구성

장면 이름은 내부 디자인 기준으로 사용합니다. 실제 상단 메뉴는 **소리 듣기 · 작업 화면 · 다운로드**처럼 목적이 분명한 표현으로 구성합니다.

| 장면 | 공간과 화면 | 음악·제품과의 연결 | 주요 동작 |
|---|---|---|---|
| ① 처마 아래, 열린 대문 | 먹빛 바탕 위에 처마의 일부가 넓게 걸리고, 열린 문 사이로 실제 작업 화면이 보입니다. | 음악 작업실의 첫인상과 제품의 용도를 함께 전달합니다. | EXE 다운로드, 소리 듣기, 작업 화면으로 이동 |
| ② 문살, 한 음을 놓는 자리 | 문살의 간격이 실제 피아노롤의 박자 격자와 시각적으로 맞물립니다. | 음표를 놓고 옮기며 리듬을 만드는 과정을 보여줍니다. | 실제 편집 장면 보기 |
| ③ 마당, 소리가 만나는 곳 | 중앙의 넓은 여백 주변에 악기 이름과 짧은 파형을 배치합니다. | 같은 편곡을 전체 합주·선율·리듬으로 들어봅니다. | 명시적인 듣기·정지·음량 조작 |
| ④ 대청, 펼쳐진 작업실 | 문틀의 여백이 넓어지고 실제 타임라인·피아노롤·믹서가 크게 펼쳐집니다. | 샘플에서 출발해 편집하고 저장하는 현재 작업 흐름을 보여줍니다. | 실제 작업 영상 보기, 화면 확대, 다운로드 |
| ⑤ 문턱을 넘어, 내 컴퓨터로 | 처음의 처마와 따뜻한 빛을 다시 사용하고 제품 이름과 설치 버튼에 시선을 모읍니다. | 사용자의 컴퓨터에서 이어갈 작업을 안내합니다. | EXE 다운로드, 대응 소스, 설치 안내, 변경 사항 |

### ① 처마 아래, 열린 대문

첫 화면은 처음부터 열린 상태로 구성합니다. 처마나 문이 움직여도 제목·설명·설치 버튼은 즉시 읽고 사용할 수 있어야 합니다.

- 화면 위: 폭이 넓은 처마 일부와 얕은 그림자.
- 화면 왼쪽: 두 줄 제목, 짧은 제품 설명, 설치 버튼, 배포 정보.
- 화면 오른쪽: 열린 문틀 안에 배치한 실제 편집 화면.
- 화면 아래: 다음 장면의 문살 일부가 자연스럽게 이어지는 경계.

데스크톱에서는 문구와 행동 영역을 약 40%, 공간과 제품 화면을 약 60%로 잡는 구성을 먼저 검토합니다. 전체 앱 화면을 너무 작게 줄여 읽기 어려워지면 공간 장식의 비중을 줄입니다.

첫 진입에는 빛과 가느다란 선이 짧게 자리 잡는 움직임을 제안합니다. 도입 애니메이션 완료를 기다리거나 문을 눌러야 본문으로 들어가는 과정은 두지 않습니다.

### ② 문살, 한 음을 놓는 자리

문살의 수직·수평 간격과 피아노롤 격자를 정렬하고, 한지 면이 옅어지며 실제 음표 편집 화면이 드러나는 장면입니다.

추천 문구는 **한 음을 놓고, 리듬을 만듭니다.**입니다. 실제 앱에서 음표를 놓거나 옮기는 짧은 장면과 리전의 구성을 보여줍니다. 악기 그림이나 가상의 편집 화면으로 실제 기능을 대신하지 않습니다.

### ③ 마당, 소리가 만나는 곳

추천 문구는 **가야금에 비트를. 대금에 나만의 박자를.**입니다.

넓은 중앙 여백과 주변의 악기 이름·파형으로 소리의 관계를 표현합니다. 오디오가 재생될 때만 실제 재생 위치와 준비된 파형에 맞춰 움직이고, 정지 상태에서는 함께 멈춥니다.

듣기 예시와 전환 규칙은 아래 음악 데모 범위를 따릅니다. 이 장면에서 보여주는 체험은 준비된 소리의 비교이며, 랜딩에 실제 편집기나 실시간 스템 합성 기능이 있는 것처럼 표현하지 않습니다.

### ④ 대청, 펼쳐진 작업실

추천 문구는 **떠오른 가락을, 끝까지 이어보세요.**입니다.

실제 작업 영상을 가장 크게 배치하는 구간입니다. 샘플 열기 → 리전·음표 편집 → 믹서 조절 → 파일 저장의 흐름을 20~30초 안팎의 짧은 영상으로 구성하는 것을 제안합니다. 중요한 메뉴와 타임라인을 읽을 수 있게 촬영·편집합니다.

동일 프로젝트의 새벽 한옥·백자와 수묵 화면을 보조 비교로 사용할 수 있습니다. 테마 비교는 첫 제작의 핵심 영상과 다운로드 동작이 준비된 뒤 추가합니다.

### ⑤ 문턱을 넘어, 내 컴퓨터로

추천 문구는 **이제, 당신의 작업실에서.**입니다.

설치 파일과 그 버전에 해당하는 정보를 명료하게 모읍니다. 설치 버튼 옆에 대응 소스 다운로드를 제공하고, 설치 안내·변경 사항·라이선스·크레딧으로 이어지는 링크를 배치합니다.

만든 작업을 `.garak`으로 보관하고 WAV로 내보내는 설명은 설치 버튼과 구분된 짧은 문장으로 제공합니다. 프로젝트 파일과 설치 파일의 다운로드가 혼동되지 않게 합니다.

## 4. 첫 화면의 문구와 탐색

### 주 제목

> 우리의 소리로,\
> 당신의 다음 곡을.

### 설명

> 가야금과 대금, 비트와 신스를 한 작업실에서.\
> 가락이음은 나만의 음악을 만들고 저장하는 Windows 음악 작업실입니다.

### 주요 동작

- **Windows 설치 파일 받기 (.exe)** — 실제 설치 파일에 직접 연결합니다.
- **소리 먼저 듣기** — 마당의 듣기 영역으로 이동합니다.
- **실제 작업 화면 보기** — 대청의 제품 화면 영역으로 이동합니다.
- **소스 다운로드 (GPLv3)** — 같은 배포본의 대응 소스에 연결하는 보조 동작입니다.

설치 버튼 아래에는 Windows x64, 공개 버전, 프리뷰 여부, 실제 EXE 용량을 표시합니다. 이 정보는 확정된 배포 메타데이터에서 함께 가져옵니다. 공개 파일이 준비되지 않은 상태에서는 확정되지 않은 주소를 다운로드 링크로 제시하지 않습니다.

기존 웹 작업실 접근 링크는 별도로 유지합니다. 랜딩 추가로 기존 웹 프로젝트에 접근하는 주소나 흐름을 임의로 바꾸지 않는 것을 요구사항으로 둡니다.

## 5. 음악 데모

### 첫 제작의 콘텐츠

〈마당의 결〉의 첫 훅인 13~20마디를 우선 후보로 삼습니다. 92 BPM에서 8마디는 약 21초이며, 실제 사용 구간과 앞뒤 여운은 청음 후 정합니다. 해당 프로젝트를 현재 앱에서 재생·내보내어 다음 세 예시를 준비합니다.

| 버튼 문구 | 예시 내용 |
|---|---|
| 전체 합주 듣기 | 같은 구간의 전체 편곡 |
| 선율 듣기 | 가야금·대금·해금 등 국악 선율 중심 |
| 리듬 듣기 | 타악·드럼·베이스 중심 |

최종 구간·음량·악기 균형은 실제로 들으며 확인합니다. 사용한 샘플의 출처와 조건은 [샘플 안내](SAMPLES.md), [샘플 프로젝트](SAMPLE_PROJECTS.md), [제3자 고지](../THIRD_PARTY_NOTICES.md)에 맞춰 크레딧으로 연결합니다.

### 재생과 전환 규칙

- 페이지는 무음으로 시작합니다.
- 각 듣기 버튼은 재생 의도를 명확히 표시합니다.
- 다른 예시를 클릭하면 **기존 예시를 정지하고 새 예시를 처음부터 재생**합니다.
- 동일한 시간 위치를 유지하는 전환이나 실시간 스템 합성은 첫 범위에 포함하지 않습니다.
- 재생·정지·음량 상태를 확인할 수 있게 합니다.
- 작업 영상을 재생하면 이전 오디오 예시는 정지합니다.
- 탭을 숨기거나 페이지를 떠나면 정지하고, 돌아왔다고 자동 재생하지 않습니다.
- 미디어 오류가 발생해도 본문·설치 버튼은 계속 사용할 수 있게 합니다.

오디오의 화면 표현은 실제 재생 위치와 준비된 파형을 사용합니다. 화면의 움직임을 현재 앱에 없는 연주·합성 기능의 시연으로 설명하지 않습니다.

### 서체와 재료 표현

- 덕온공주체 워드마크는 기존 윤곽 자산을 사용합니다. [글꼴 고지](../public/fonts/DeogonPrincess-LICENSE.txt)를 유지합니다.
- 본문과 버튼은 현재 소개 자료에서 사용한 Noto Sans KR 계열을 기준으로 검토합니다. 실제 웹폰트 추가 여부·범위는 자산과 성능 예산을 확인한 뒤 정합니다.
- 큰 제목은 짧은 두 줄 문장을 기본으로 하고, 본문은 익숙한 크기와 충분한 행간으로 구성합니다.
- 한지 질감은 넓은 배경에 옅게 사용하고, 작은 글자·파형·제품 화면 위에는 겹치지 않습니다.
- 나무의 느낌은 문틀의 두께, 얕은 그림자, 따뜻한 경계색으로 표현합니다.
- 다운로드 버튼은 읽기 쉬운 직사각형과 분명한 문구를 유지합니다.

## 7. 동작 제안

다음 수치는 시안과 구현에서 조정할 출발점이며, 이미 구현·측정한 결과가 아닙니다.

| 대상 | 제안 |
|---|---|
| 첫 화면 | 빛과 선이 자리 잡는 700~900ms 안팎의 한 번의 도입 |
| 장면 진입 | 문살·화면 일부가 360~650ms 동안 이동하거나 드러남 |
| 버튼·탭 | 150~220ms 안팎의 짧은 반응 |
| 음악 재생 | 실제 재생 위치와 준비된 파형에 맞춘 움직임 |
| 음악 정지 | 연결된 움직임도 함께 정지 |

첫 제작에서는 두세 장의 평면과 그림자를 겹쳐 공간의 깊이를 표현하는 방식을 제안합니다. 일반 세로 스크롤을 유지하며, 사용자의 스크롤 속도를 바꾸거나 장면 완주를 요구하지 않습니다.

`prefers-reduced-motion`을 따르는 상태에서는 이동·깊이 변화·문살 전환을 정지된 구성으로 바꾸는 동작을 제안합니다. 문구·제품 화면·다운로드·오디오 조작은 같은 순서로 사용할 수 있게 합니다.

## 8. 실제 화면과 제작 자산

| 필요한 자료 | 사용 위치와 내용 | 제작 조건 |
|---|---|---|
| 작업실 전체 화면 1장 | 첫 화면의 열린 문 안. 〈마당의 결〉 타임라인과 피아노롤 | 배포 후보와 같은 앱 버전에서 캡처 |
| 피아노롤 확대 화면 또는 짧은 영상 | 문살 장면의 음표 편집 | 실제 조작을 촬영하고 의미 있는 화면 크기 유지 |
| 20~30초 안팎의 작업 영상 1개 | 대청 장면의 샘플 열기·편집·저장 | 영상 내용과 현재 기능이 일치하는지 확인 |
| 중심 편곡의 듣기 예시 3개 | 마당의 전체 합주·선율·리듬 | 같은 구간에서 제작하고 청음·출처 확인 |
| 선택적인 다른 테마 화면 1장 | 동일 프로젝트의 두 테마 비교 | 핵심 콘텐츠 준비 이후 추가 |

캡션에는 프로젝트·테마·앱 버전을 기록합니다. 개인 경로·비공개 작업·연결 토큰이 노출되지 않는 자료를 준비합니다. 영상은 포스터를 먼저 보여주고 사용자가 눌러 재생하는 구성을 제안합니다.

ASIO·VST3는 현재 사용 가능한 기능처럼 화면이나 데모에 넣지 않습니다. 진행 상태는 [네이티브 오디오 계획](NATIVE_AUDIO.md)에 맞춰 별도로 안내합니다. GPL 전환은 기능 구현과 구분하고, 공개하는 배포본의 [라이선스·대응 소스 안내](LICENSING.md)를 연결합니다.

## 9. 모바일·접근성·성능 검증 목표

### 모바일과 접근성

- 모바일에서는 제목과 설치 버튼을 제품 이미지보다 먼저 보여줍니다.
- 공간은 세로로 다시 구성하고 처마·문살의 일부만 사용합니다.
- 듣기 예시는 터치와 키보드로 조작할 수 있게 하며, 호버가 있어야 이해되는 기능을 두지 않습니다.
- 설치 버튼에 Windows용이라는 점을 표시합니다. PC로 전달할 주소 복사를 보조 동작으로 검토합니다.
- 고정 설치 버튼을 사용하는 경우 영상·오디오 조작과 본문을 가리지 않도록 공간을 확보합니다.
- 본문 제목 순서, 링크 이름, 이미지 대체 텍스트, 명확한 포커스 표시를 검토합니다.
- 재생 상태를 색만으로 전달하지 않고 문구·아이콘과 함께 표시합니다.
- 동작 감소 상태에서도 같은 내용과 기능에 도달할 수 있는지 확인합니다.

### 성능

랜딩 번들은 편집기 엔진과 내장 샘플 전체에서 분리하는 것을 제안합니다. 오디오·영상은 사용자가 선택할 때 불러오고, 첫 화면은 최적화된 이미지와 가벼운 벡터 중심으로 구성합니다.

**첫 화면 리소스 약 1MB는 예산 검토의 출발점입니다.** 이미지·웹폰트·JavaScript·스타일을 포함해 실제로 무엇을 먼저 내려받는지 측정한 뒤 예산을 확정합니다. 현재 달성한 용량이나 로딩 속도로 표시하지 않습니다. 모바일에서 첫 문구·설치 버튼·주요 이미지가 보이는 시점, 레이아웃 변화, 미디어 요청 시점을 함께 확인합니다.

## 10. EXE 다운로드와 공개 정보

기존 Cloudflare의 정적 랜딩과 공개 GitHub Releases의 설치 자산을 연결하는 구성을 제안합니다. R2 같은 별도 파일 저장소는 이후 필요가 생길 때 검토합니다.

주 버튼은 공개된 버전의 EXE 자산에 직접 연결합니다. 설치 파일과 대응 소스가 준비된 동일 릴리스의 메타데이터에서 아래 정보를 함께 가져옵니다.

| 메타데이터 | 화면·동작에서의 용도 |
|---|---|
| 공개 버전·채널 | 버전과 프리뷰 여부 |
| 태그·전체 커밋 | 검증한 코드와 배포본의 대응 관계 |
| 실제 EXE 파일명·바이트 크기·URL | 설치 버튼과 용량 표시 |
| EXE SHA-256 | 체크섬 확인 링크 |
| 같은 버전의 소스 파일명·URL·SHA-256 | 소스 다운로드 보조 링크 |
| 공개일·변경 사항 URL | 배포 정보와 변경 내역 |
| 현재 지원 범위·필요한 설치 안내 | Windows x64 표기와 사용 안내 |

이 문서에는 확정되지 않은 실제 파일명·용량·릴리스 주소를 기입하지 않습니다. 다운로드 주소는 특정 릴리스에 대응하는 값으로 고정하고, 화면의 버전만 바뀌거나 이전 파일을 가리키지 않도록 함께 갱신합니다. 프런트엔드에 GitHub 인증 토큰을 넣지 않는 구성을 요구사항으로 둡니다.

공개 작업을 구현할 때에는 **해당 Windows 배포본 검증 → EXE·대응 소스·체크섬 준비 → 릴리스 공개 → 랜딩 메타데이터 갱신** 순서를 기준으로 삼습니다. 상세 소스 제공 조건은 [라이선스와 소스 배포](LICENSING.md)를 따르고, 설치 안내는 [데스크톱 문서](DESKTOP.md)와 맞춥니다.

## 11. 첫 제작 범위와 우선순위

첫 제작은 다섯 장면, 중심 편곡 하나의 듣기 예시, 실제 작업 영상 하나, 직접 EXE 다운로드와 대응 소스 링크로 완결하는 구성을 권합니다.

1. **다운로드 정보:** 실제 공개 자산과 일치하는 EXE·대응 소스·버전·용량·체크섬을 준비합니다.
2. **첫 화면의 정지된 구성:** 기존 브랜드, 처마·문틀, 문구, 실제 편집 화면의 비례부터 맞춥니다.
3. **제품 자료:** 〈마당의 결〉 예시와 실제 작업 영상·캡처를 확보합니다.
4. **핵심 움직임:** 첫 화면의 빛, 문살과 격자의 연결, 음악의 진행 표현을 순서대로 추가합니다.
5. **사용·성능 확인:** 모바일, 키보드, 동작 감소, 미디어 오류, 다운로드 연결, 초기 로딩을 확인합니다.

테마 비교 확대, 다른 샘플의 추가 듣기, 더 세밀한 공간 표현은 첫 흐름이 완성된 뒤의 확장 후보로 둡니다.

## 12. 출시 콘텐츠의 완료 조건

- 첫 화면에서 제품의 용도, Windows용이라는 점, EXE 설치 버튼을 바로 확인할 수 있습니다.
- 표시 버전·파일명·용량·체크섬·다운로드 주소가 같은 검증된 배포본을 가리킵니다.
- EXE 옆에서 같은 배포본의 GPLv3 대응 소스와 [라이선스 안내](LICENSING.md)에 접근할 수 있습니다.
- 해당 릴리스의 Windows 설치·파일 연결·앱 실행·MCP 검증 결과를 확인하고 실제 지원 범위를 반영합니다.
- 제품 화면은 같은 배포 버전에서 확보했으며, 개념 이미지와 구분되어 있습니다.
- 듣기 예시는 실제 앱의 현재 소리로 준비했고, 구간·전환·음량·출처를 확인했습니다.
- 페이지 진입·복귀·스크롤로 소리가 자동 재생되지 않습니다.
- 일반 스크롤, 키보드, 모바일, 동작 감소 상태에서 설치와 콘텐츠 접근이 가능합니다.
- ASIO·VST3 등 계획 단계의 기능을 현재 기능으로 표시하지 않습니다.
- 기존 웹 작업실에 접근하는 링크와 흐름을 확인합니다.
- 실제 이미지·폰트·미디어가 포함된 상태에서 초기 요청과 로딩을 측정하고 결과를 기록합니다.

이 조건은 앞으로 구현·공개할 때 확인할 기준입니다. 본 기획 문서의 작성만으로 사이트 구현이나 출시 검증이 완료된 것은 아닙니다.
