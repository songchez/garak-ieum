# 서스테인 페달 (MIDI CC64)

피아노를 칠 때 페달을 밟으면 건반에서 손을 떼도 소리가 계속 울립니다. MIDI에서는 이 페달이 **컨트롤 체인지 64번(CC64)** 으로 전달됩니다. 값이 64 이상이면 밟은 상태, 63 이하면 뗀 상태입니다. 가락이음은 페달을 음 길이로 바꾸지 않고 **리전 안의 컨트롤러 데이터**로 그대로 보관하며, 재생할 때 두 엔진이 페달을 해석합니다.

## 다른 DAW는 어떻게 하나

| | Logic Pro | Ableton Live | Cubase | 가락이음 |
| --- | --- | --- | --- | --- |
| 저장 위치 | 리전의 CC64 이벤트. 피아노롤 아래 MIDI Draw/Step Editor의 Sustain 레인 | 클립 엔벨로프 `MIDI Ctrl › 64-Sustain` | 키 에디터 컨트롤러 레인 `Sustain (64)` | 리전의 `sustain` 레인(CC64), 피아노롤 아래 **SUSTAIN** 레인 |
| 재생 | 페달을 밟은 동안 악기가 노트 오프를 미룸 | 같음 | 같음 | 같음. 내장 악기는 엔진이, VST3는 플러그인이 처리 |
| 재생 위치 이동 | Chase 설정에 따라 페달 상태를 재전송 | 클립 엔벨로프 값을 재전송 | Chase Events(컨트롤러) | 재생 시작·이동·루프 반복 때 그 위치의 페달 상태를 다시 적용 |
| MIDI 파일 가져오기 | CC64를 그대로 유지 | CC를 엔벨로프로 유지 | CC를 그대로 유지 | **CC64를 그대로 유지** (이전 버전은 음 길이로 바꿨음) |
| 음 길이로 굳히기 | `Sustain Pedal to Note Length` 기능(선택 명령) | 없음 | `Pedals to Note Length`(선택 명령) | **서스테인을 음 길이로 굳히기**(선택 명령), 가져오기 옵션 |
| 반 페달 | 값 0–127 보관, 악기에 따라 지원 | 같음 | 같음 | 값 0–127 보관. 내장 악기는 현재 켬/끔(64 기준)으로 해석 |

공통점은 세 가지입니다. 페달은 음표가 아니라 **컨트롤러 데이터**이고, 밟은 동안에는 **노트 오프를 페달을 뗄 때까지 미루며**, 음 길이로 바꾸는 일은 사용자가 고르는 **별도 명령**입니다. 가락이음도 같은 방식을 따릅니다.

## 사용법

### 보기와 편집

- MIDI 리전을 열면 피아노롤 맨 아래에 **SUSTAIN** 레인이 있습니다. 페달을 밟은 구간은 `Ped.` 막대로 보입니다. 레인 왼쪽 위 **×**로 숨기고 머리글의 **+ 레인 → 서스테인**으로 다시 보입니다. SUSTAIN 레인은 피치 벤드·모듈레이션 같은 다른 컨트롤러 레인과 같은 목록에 쌓입니다([MIDI_CONTROLLERS.md](MIDI_CONTROLLERS.md)). 드럼 에디터는 페달 데이터가 있을 때만 레인을 보여줍니다.
- 빈 곳을 **드래그**하면 페달 구간을 그립니다. 기존 구간 위에서 시작해 드래그하면 그 범위만 지웁니다.
- **더블 클릭**: 구간 위에서는 그 구간을 지우고, 빈 곳에서는 다음 마디선(또는 다음 구간)까지 새 구간을 만듭니다.
- 피아노롤 스냅 격자를 따르며, Ctrl을 누르고 있으면 격자를 무시합니다.
- 타임라인의 MIDI 리전 아래쪽에 얇은 막대로 페달 구간이 표시됩니다.
- 피아노롤에서 마우스 오른쪽 버튼 → **서스테인을 음 길이로 굳히기**: 페달 때문에 울리던 길이만큼 음표를 늘리고 페달 데이터를 지웁니다. 실행 취소로 되돌릴 수 있습니다.

### 가져오기와 내보내기

- **파일 → 오디오·MIDI 가져오기…**: CC64를 페달 레인으로 가져옵니다. 같은 포트·채널의 페달은 그 채널의 모든 파트에 적용됩니다. Reset All Controllers(CC121)는 페달 뗌으로 처리합니다.
- **파일 → MIDI 가져오기 · 서스테인을 음 길이로 변환…**: 이전 버전 방식입니다. 페달을 음 길이에 반영하고 페달 데이터는 남기지 않습니다.
- **파일 → MIDI 내보내기…**: 모든 MIDI 리전을 Type 1 SMF(960 PPQ)로 저장합니다. 루프 반복, 리전 퀀타이즈·트랜스포즈·벨로시티·딜레이를 반영하고, 페달은 CC64 이벤트로 씁니다. 리전 끝까지 페달이 밟혀 있으면 리전 끝에 페달 뗌(CC64 = 0)을 씁니다. 악기 트랙마다 MTrk 하나, 드럼 키트는 채널 10을 씁니다.

## 동작 규칙

- **노트 오프 지연**: 페달을 밟은 동안 끝난 음은 페달을 뗄 때 끝납니다. 이미 페달 전에 끝난 음은 그대로입니다. 페달을 뗄 때 아직 누르고 있는 음도 그대로입니다.
- **같은 위치의 순서**: 페달을 밟는 순간에 끝나는 음은 페달에 잡힙니다. 페달을 떼는 순간에 끝나는 음은 늘어나지 않습니다(같은 샘플에서는 페달 → 노트 오프 → 노트 온 순서).
- **다시 치기**: 페달로만 울리고 있는 음을 다시 치면 앞의 음은 새 음이 시작될 때 끝나고, 새 음이 이어서 울립니다. 피아노 현을 다시 치는 것과 같습니다.
- **리전 단위**: 페달 상태는 리전 반복 하나에 속합니다. 리전 왼쪽을 잘라낸 경우 잘린 지점의 페달 상태를 이어받고, 리전 끝과 루프 반복 경계에서 페달을 뗍니다. 음표가 리전 끝에서 잘리는 것과 같은 규칙입니다.
- **편집 안전성**: 자르기·나누기·복제·합치기는 페달을 음표와 함께 옮깁니다. 합칠 때는 각 리전에서 실제로 들리던 페달 구간만 남깁니다. 트랜스포즈와 퀀타이즈는 페달에 영향을 주지 않습니다.
- **보이스 수**: 페달로 늘어난 음도 일반 음과 같은 보이스 한도와 보이스 훔치기 규칙을 따릅니다.

## 엔진별 구현

| 소스 | 웹 | 네이티브 |
| --- | --- | --- |
| 내장 신스·샘플 피아노/건반 | `playbackNotes`가 페달을 적용한 노트 오프로 스케줄 | 타임라인 컴파일러가 같은 함수로 노트 오프 프레임을 계산. 엔진은 그 프레임에 정확히 릴리즈 |
| 이음웨이브 | (웹은 네이티브 DSP 없음) | 내장 악기와 같이 노트 오프 프레임에 반영 |
| VST3 악기 | 해당 없음 | 원래 노트와 CC64 이벤트를 샘플 단위로 전달. 플러그인의 `IMidiMapping`이 CC64에 연결한 파라미터 포인트로 들어가므로, 반 페달·페달 공명은 플러그인이 처리 |

- 재생 시작·탐색 때 VST3 트랙은 그 위치의 페달 값을 먼저 보내고(chase), 정지·일시정지 때는 CC64 = 0을 보내 페달을 뗍니다. 페달 데이터가 없는 트랙에는 컨트롤러 이벤트를 보내지 않습니다.
- 내장 악기는 페달이 노트 오프 위치에 이미 반영되어 있으므로, 탐색할 때 페달 때문에 울리고 있어야 하는 음도 다시 이어서 재생됩니다.
- 실시간 입력: 네이티브 엔진에 `note.control`(CC) 명령이 있습니다. 내장 악기와 이음웨이브는 페달을 밟은 동안 실시간 노트 오프를 미루고, 다시 치기와 패닉(모든 음 끄기)을 처리합니다. VST3에는 CC를 그대로 전달합니다. MIDI 입력([MIDI_RECORDING.md](MIDI_RECORDING.md))에서는 호스트가 장치의 CC64를 오디오 스레드에서 같은 경로(`controlChange`)로 바로 전달합니다. 브라우저 엔진의 실시간 음도 같은 규칙으로 페달을 따르고, 녹음·캡처한 CC64는 리전의 `sustain`이 됩니다.

## 저장 형식

프로젝트 스키마 13에서 `MidiClip.sustain`이 추가되었습니다. `{ beat, value }` 배열이며 `beat`는 음표 `start`와 같은 원본 박 좌표, `value`는 0–127 정수입니다. 박 위치는 순서대로 하나씩만 있어야 합니다. 스키마 12 이하 프로젝트는 그대로 열리며 페달이 없는 상태입니다. 스키마 12 이하 파일에 페달 데이터가 있으면 거부합니다.

## 코드와 테스트

- `src/core/sustain.ts`: 페달 구간, 노트 오프 지연, 화면 창 편집, 굳히기, 합치기
- `src/core/playback.ts`: `playbackNotes`(페달 적용), `playbackSustain`(VST3·내보내기용 CC64 이벤트)
- `src/core/midiImport.ts`, `src/core/midiExport.ts`: CC64 가져오기/내보내기, `sustainToLength` 옵션
- `src/audio/native/timeline.ts`: 소스별 페달 처리(`controls`)
- `rust/garak-engine/src/instrument.rs`: 통합 Rust 엔진(0.3.2부터 데스크톱·웹 공통)의 내장 악기 페달·탐색 추적·라이브 페달
- `native/src/engine.cpp`: 셸의 VST3 컨트롤러 이벤트 순서·chase/정지와 이전 C++ 경로의 실시간 페달 지연
- `native/src/vst3.cpp`: `IMidiMapping`으로 CC → 파라미터 포인트
- `src/components/SustainLane.tsx`, `PianoRoll.tsx`, `TimelineClip.tsx`: 레인, 굳히기 명령, 리전 표시

```sh
pnpm exec vitest run src/core/sustain.test.ts src/core/midiImport.test.ts
cmake --build build/native-mingw --target garak-engine-test && build/native-mingw/garak-engine-test.exe
```

네이티브 테스트는 결과 PCM의 해시 대신 동작을 비교합니다. 페달을 밟은 채 노트 오프를 보낸 엔진의 출력이 노트를 계속 누른 엔진과 같고, 페달을 뗀 순간부터는 그 프레임에 노트 오프를 보낸 엔진과 같은지 확인합니다. VST3 테스트는 실제 VST3 테스트 플러그인으로 CC64가 정확한 샘플 위치의 파라미터 포인트로 들어가는지 확인합니다.
