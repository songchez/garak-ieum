1. 합의된 방향과 이 문서의 상태

화면 배치는 왼쪽 라이브러리, 그 옆 인스펙터와 두 채널 스트립, 중앙 트랙 영역, 하단 편집기·믹서, 오른쪽 보조 브라우저를 기준으로 합니다. 다크 테마를 사용하며 시각 표현은 자체 디자인으로 만듭니다. Logic Pro for Mac의 익숙한 작업 흐름을 참고하고, 1.0은 웹과 오디오 엔진, 2.0은 로컬 호스트와 VST 연결입니다. USB MIDI 키보드와 브라우저에 노출되는 오디오 입출력은 1.0 설계 범위입니다.

이 문서는 구현할 동작 계약입니다. 여기에 적힌 기능이 모두 구현되었다는 뜻이 아닙니다. 승인된 배치 시안, 현재 React 개발 코드, 앞으로 구현할 동작을 구분합니다. 각 기능의 완료 판정은 마지막의 검증 표를 사용합니다. 기능·화면 일치율을 측정하지 않았으므로 ‘98% 완성’으로 표시하지 않습니다.

Logic 비교 기준은 Apple의 U.S. default key command preset입니다. 주요 키 명령 페이지는 12.3을 표시하며, 포인터·보조 문서는 지역별 접근 경로에 따라 12.0·12.2 또는 명시된 이전 버전을 참고했습니다. 이것을 Logic 최신 릴리스 번호라고 단정하지 않습니다. 한국어 배열, 사용자 지정 키맵, 이전 버전은 결과가 다를 수 있습니다. 아래에서 ‘Logic 참고’와 ‘우리 웹 기본안’을 분리합니다. 임계값·최소 길이·Undo 단위·오류 처리는 별도로 표시하지 않아도 우리 제품의 설계 선택입니다. 2. 반드시 지킬 여덟 가지 규칙

  1. 현재 작업 영역의 명령만 실행합니다. 음표를 선택하지 않았다고 같은 Delete가 리전이나 트랙을 대신 삭제하지 않습니다.
  2. 텍스트 입력과 한글 조합을 먼저 보호합니다. 이름을 입력하는 동안 R, S, Space, Delete가 녹음·솔로·재생·객체 삭제를 실행하지 않습니다.
  3. 한 입력은 한 동작입니다. 자식 편집기가 처리한 이벤트를 전역 리스너가 다시 처리하지 않습니다.
  4. 드래그는 놓을 때 한 번 확정합니다. 미리보기 프레임은 문서 Undo와 자동 저장에 들어가지 않습니다.
  5. 취소하면 원본이 돌아옵니다. Escape, 포인터 취소, 창 전환, 화면 숨김, 편집기 해제에 같은 취소 규칙을 적용합니다.
  6. 원본 오디오는 편집으로 지우지 않습니다. 리전 삭제·트림은 참조와 재생 범위를 바꿉니다. 영구 파일 정리는 별도 작업입니다.
  7. 명령 이름·메뉴·도움말·단축키는 하나의 정의를 공유합니다. 같은 기능에 서로 다른 이름이나 키 안내를 만들지 않습니다.
  8. 미구현 명령은 실행된 것처럼 보이지 않습니다. 기능 상태를 명령 목록에서 표시하며, 연결되지 않은 단축키는 등록하지 않습니다.

3. 키보드 표기와 처리 순서

Mod는 macOS의 Command, Windows/Linux의 Control입니다. Alt는 macOS의 Option, Windows/Linux의 Alt입니다. 모든 Logic의 Control을 Mod로 치환하지 않습니다. 예를 들어 macOS Control+M과 Command+M은 다릅니다. Return과 숫자패드 Enter도 별도 키입니다.

입력 처리 순서는 다음과 같습니다.

  1. 이벤트가 이미 처리되었는지, 한글 등 IME 조합 중인지, 해당 환경의 AltGraph 문자 입력인지 검사합니다.
  2. 열린 메뉴·모달·명령 검색이 입력을 소유하면 그 안에서 처리합니다.
  3. 진행 중인 드래그·숫자 편집은 자신의 취소·확정·수정키를 먼저 받습니다. 드래그 중 Undo는 현재 미확정 제스처만 취소하고, 같은 입력으로 이전 확정 편집을 추가 취소하지 않습니다. Mod+S는 마지막 확정 revision만 저장하며 드래그를 확정하지 않습니다. 이 두 예외 외의 문서 편집 명령은 제스처가 끝날 때까지 실행하지 않습니다.
  4. 텍스트 입력, 숫자 입력, 선택 상자, 슬라이더 등 네이티브 컨트롤이 필요한 키를 먼저 받습니다.
  5. 포커스를 가진 어레인지먼트·피아노롤·믹서·브라우저가 문맥 명령을 해석합니다.
  6. 마지막으로 허용된 전역 명령을 처리합니다. 문맥 명령이 ‘대상 없음’으로 끝나면 다른 객체 종류로 대체하지 않습니다.

isComposing, 조합 시작·종료 상태, 필요한 호환 보조값을 함께 고려합니다. 한국어 입력기의 조합 종료 Return이 프로젝트 처음 이동으로 재실행되지 않아야 합니다. 문자 조합이 실제 시작된 동안에는 물리 키 단축키도 실행하지 않습니다. [W1]

한/영 전환 상태에서도 작업 영역의 Y/I/X 같은 단축키 위치는 유지하도록 기본 키맵은 물리 code 기준으로 해석합니다. 그러나 단축키 표시에는 사용자가 보는 키 이름을 씁니다. QWERTZ·Dvorak 등에서는 물리 위치 방식과 문자 방식 중 선택할 수 있게 설계하고, 가져온 키맵에 그 방식을 포함합니다. code와 key를 임의로 번갈아 쓰지 않습니다. [W1]

AltGraph 검사는 운영체제별로 다르게 합니다. 일부 macOS 브라우저가 Option에 AltGraph 상태를 보고할 수 있으므로, Option 조작 전체를 문자 입력으로 차단하는 구현은 금지합니다. 실제 AltGr 문자 입력과 등록된 Option 조작을 구분해야 합니다. [W2]

자동 반복은 명령마다 지정합니다. 재생·녹음·패널·삭제·복제·파일 열기는 처음 한 번만 실행합니다. 선택 이동·시간 이동·값 조절은 반복을 허용하되 한 번의 키 누름에서 시작한 연속 편집을 한 Undo로 묶습니다. Undo/Redo 자체는 초깃값으로 반복을 차단하고, 반복을 허용할 경우 별도 속도 제한과 테스트를 요구합니다.

Space로 정지할 때는 현재 위치를 유지합니다. Return으로 처음으로 갑니다. 사이클이 켜져 있는 일반 재생은 사이클 시작점에서 시작하도록 정의하고, 선택 재생은 사용자가 지정한 선택 시작점을 우선합니다. 사이클·선택 재생의 우선순위는 UI에 표시하고 설정값으로 무질서하게 갈라놓지 않습니다.

Shift+D를 복제로 사용하지 않습니다. Logic의 선택 해제와 충돌하기 때문입니다. S를 분할로 사용하지 않습니다. 채널 솔로와 도구 메뉴 안의 솔로 도구가 다른 문맥에서 사용됩니다. 채널 M/S는 선택 트랙·채널을 대상으로 하며, 리전/음표 뮤트와 별도 명령입니다.

우리의 반복 명령은 선택 묶음의 시작부터 가장 늦은 끝까지를 한 단위로 보고, 그 뒤에 사본 한 묶음을 만드는 것으로 정의합니다. 여러 번 반복할 때는 반복 횟수 대화상자를 사용합니다. 이것은 Apple의 명령 이름을 확인한 뒤 정한 우리 동작이며, Logic의 모든 반복 설정까지 같다고 주장하지 않습니다.

웹의 Alt+쉼표/마침표 이동 단위는 화면의 Nudge 설정을 따릅니다. 기본값은 현재 고정 격자이며 Smart일 때는 현재 확대에서 계산한 격자를 표시합니다. 수정키 조합은 완전히 일치해야 합니다. Alt+Shift+쉼표가 일반 Shift+쉼표 transport 이동과 동시에 실행되면 안 됩니다.

5.4 도구 메뉴

T는 도구 메뉴입니다. 메뉴가 열린 동안 다음 키를 해석합니다. 도구를 정한 뒤 메뉴를 닫고 원래 편집 영역에 포커스를 돌려줍니다. 입력 필드에서는 T를 문자로 처리합니다. T→P 같은 시퀀스는 두 키를 동시에 누르는 조합이 아닙니다. [A4]

6. 브라우저와 충돌하는 키의 정책

Chrome은 새 탭·새로고침·북마크·뒤로 가기 등 자체 단축키를 가집니다. 예를 들어 Mod+T, Mod+R, Mod+D, Windows의 Alt+←/→, macOS의 Mod+←/→가 DAW 명령과 겹칩니다. 일부 조합은 페이지에서 취소할 수 있는 환경도 있지만, 모든 환경에서 앱이 받을 수 있다고 보장하지 않습니다. [W3]

웹 기본 프리셋은 다음 정책을 사용합니다.

  • 새 탭·탭 닫기·창 열기·주소창·탭 이동·운영체제 명령은 등록하지 않습니다.
  • 리전 반복, 설정 복제 트랙, 재생 위치 분할은 메뉴·명령 검색·포인터 도구로 제공하고, 브라우저 충돌 원래 키를 기본으로 강제하지 않습니다.
  • Mod+S는 사용자가 앱 안에서 작업할 때 프로젝트 저장 명령으로 사용하는 명시적 예외입니다. 현재 개발 코드의 파일 내려받기와 최종 ‘로컬 저장’은 다른 동작이므로 아래 저장 계약으로 정리합니다.
  • Alt+쉼표/마침표를 웹 이동 기본키로 두며, 브라우저가 선점하지 않는 macOS Option+화살표는 별도 호환 별칭으로 제공할 수 있습니다.
  • 어떤 키를 바꾸더라도 메뉴·도움말·툴팁을 같은 등록 정보에서 갱신합니다. 기능 이름만 원래 키로 남겨 두지 않습니다.
  • 로컬 VST 호스트를 붙여도 브라우저가 UI를 표시하는 한 브라우저 키 충돌은 남습니다. 네이티브 앱 창을 도입하는 것은 별도 결정입니다.

명령 검색은 ? 또는 도움말 버튼에서 엽니다. 입력하기 전의 편집 영역과 선택 대상을 보관합니다. ‘분할’을 검색하고 Return으로 실행하면 검색 입력 필드가 아닌 원래 리전이 대상입니다. 대상이 사라졌거나 현재 실행할 수 없다면 실행하지 않고 이유를 표시합니다. Escape로 닫으면 원래 위치에 포커스를 돌려줍니다.

사용자 지정 키맵에는 OS, 물리키/문자키 방식, 명령 ID, 문맥, 수정키, 반복 정책, 스키마 버전을 저장합니다. 같은 문맥에서 중복된 조합은 저장을 막습니다. 서로 배타적인 문맥이면 같은 키를 허용하되 현재 의미를 명령 목록에서 확인할 수 있어야 합니다. 키 입력 수집 중에는 프로젝트 명령을 실행하지 않습니다. 키맵 파일을 가져올 때 알 수 없는 명령은 비활성 목록으로 보존하며, 실행 코드나 임의 스크립트를 읽지 않습니다.

특히 Alt+Shift+MIDI 리전 드래그는 alias용으로 예약하고, alias가 없는 1.0에서는 그 조합으로 편집을 확정하지 않습니다. 일반 복제는 Alt만 사용합니다. 음표 문맥의 복제·길이 조절은 리전 alias 규칙과 구분합니다. 보조 도구는 제스처 시작 시 결정하고 드래그 중 바뀌지 않습니다. 복제 의도·스냅 해제·축 고정은 진행 중 수정키 변화에 반응합니다.

수정키 해석은 예약 조합 → 플랫폼별 임시 스냅 해제 → 나머지 Shift 축 고정 → 일반 복제 의도 순서로 계산합니다. Windows/Linux의 Control+Shift 동안에는 스냅 해제만 적용하고 축 고정을 동시에 켜지 않습니다. MIDI 리전에서 Alt+Shift가 되면 ‘alias 미지원’ 미리보기로 바꾸며, 그 상태에서 놓으면 원본 복원·새 ID 없음·Undo 없음으로 끝냅니다. Shift를 놓아 Alt만 남으면 일반 복제로 돌아갈 수 있습니다. 이 예외가 아래 부록의 일반 복제 규칙보다 우선합니다.

8. 저장·파일·클립보드 계약

자동 저장은 마지막으로 확정된 프로젝트와 원본 자산 참조를 저장합니다. 진행 중 드래그 미리보기·선택 변경·패널 토글은 저장하지 않습니다. ‘저장됨’ 표시는 마지막 저장 요청이 실제로 완료된 후에만 표시합니다. 요청을 직렬화하고 과거 저장 완료가 최신 변경의 상태를 덮어쓰지 않게 버전을 확인합니다.

최종 제품의 Mod+S는 로컬 프로젝트 체크포인트를 확정하는 동작입니다. ‘프로젝트 파일 내려받기’와 ‘WAV 내보내기’는 별도 메뉴로 둡니다. 아직 현재 개발 코드에서는 Mod+S가 프로젝트 묶음 내려받기이므로 완료 판정 전에 바꿔야 합니다. 새 프로젝트·파일 열기에서는 현재 복구 가능한 저장이 확보되었는지 확인하고, 저장 실패가 있으면 새 작업이 기존 저장본을 덮어쓰지 않게 합니다.

객체 복사는 앱 내부의 형식 있는 클립보드를 기본으로 합니다. 리전·음표·자동화의 복사를 구분하고 객체 ID는 붙여넣을 때 새로 만듭니다. 붙여넣기 시작점은 현재 재생 위치, 트랙 기준은 현재 선택 트랙이며 상대 시간·트랙 간격을 보존합니다. 맞지 않는 트랙 종류가 있으면 일괄 거부합니다. 원본 오디오 자산을 찾을 수 없으면 ‘완료’로 표시하지 않습니다.

잘라내기는 내부 복사 데이터가 확보된 뒤 한 문서 편집으로 삭제합니다. 다른 프로젝트로 붙여넣을 때는 필요한 자산을 함께 이전한 뒤 확정합니다. 시스템 클립보드 접근은 브라우저 권한·포맷 지원 차이가 있으므로 별도 기능으로 구현합니다. 텍스트 입력에서는 브라우저의 평범한 복사·붙여넣기를 우선합니다.

외부 파일을 드래그하면 삽입될 트랙·위치를 먼저 표시합니다. 디코드 성공 전에는 문서에 완성된 리전을 만들지 않습니다. 한 번에 여러 파일을 넣는 작업은 1회 Undo로 되돌립니다. 실패한 파일의 이름과 이유를 표시하고, 성공한 파일을 일부만 확정하는 경우 사용자가 그 목록을 확인할 수 있어야 합니다. 입력 대화상자를 닫거나 새 프로젝트로 전환했을 때 이전 비동기 결과가 새 프로젝트에 삽입되지 않아야 합니다.

9. 오디오·MIDI 장치 상호작용

설정의 오디오와 MIDI 탭을 분리합니다. 장치의 연결 상태, 권한 상태, 선택 상태를 구분하고, 물리적으로 연결되었다는 사실만으로 입력이 준비되었다고 표시하지 않습니다. 오디오 입력에는 입력 미터를, MIDI 입력에는 최근 메시지 표시등을 제공합니다. 브라우저가 제공한 채널만 선택 목록에 표시합니다.

장치를 선택하면 연결을 시도하는 동안 상태를 표시하고, 성공한 후 활성 장치를 바꿉니다. 실패하면 기존 정상 장치를 유지하거나 명확한 무음 상태로 전환합니다. 녹음 중 입력 장치를 바꾸는 경우 현재 테이크를 먼저 마감하는 흐름으로 처리합니다. 녹음 중 조용히 다른 입력으로 전환하지 않습니다.

장치가 분리되면 모니터링과 그 장치의 녹음을 마감하고, 이미 녹음한 자료를 보존합니다. 단순한 브라우저 포커스 이탈을 물리 장치 분리와 혼동하지 않습니다. USB MIDI 포트 재연결 시 이름만 같다는 이유로 임의의 다른 포트를 선택하지 않고 포트 정보와 사용자의 선택을 다시 확인합니다.

음표 수명은 장치·채널·음높이·노트 인스턴스에 따라 추적합니다. 서스테인(CC64), Note Off, 장치 분리, 오디오 엔진 중지, 프로젝트 전환 때 남은 음을 정리합니다. 건반을 누른 채 트랙을 바꾸더라도 기존 Note Off가 원래 연주한 악기로 전달되어야 합니다. ‘모든 음 끄기’ 버튼은 항상 접근 가능한 위치에 두며, 단축키는 명령 검색에서 지정할 수 있습니다. 노트 꺼짐 처리와 녹음된 MIDI 데이터의 삭제를 혼동하지 않습니다.

녹음된 노트 위치는 이벤트 타임스탬프와 오디오 시계를 연결해 계산합니다. React 렌더 시점이나 UI 프레임 시간으로 기록하지 않습니다. 오디오 드라이버·브라우저 지연을 고려한 기록 보정은 실기기 측정으로 검증하고, 측정 전 임의 수치를 ‘실제 레이턴시’라고 표시하지 않습니다. MIDI 녹음 퀀타이즈는 원본 타이밍과 편집 적용값을 구분합니다.

10. 숫자·접근성·상태 피드백 보완

주요 단위는 BPM, dB, 팬, 마디·박·틱, 초, MIDI 음높이, 벨로시티입니다. 단위 없는 숫자를 필드마다 다르게 추측하지 않습니다. BPM은 허용 범위를 명시하고, 팬은 중앙 C와 좌우 비율을 함께 표시합니다. dB 입력의 −∞는 무음 값으로 정규화합니다. 표시 반올림과 저장 정밀도를 분리합니다.

표준 Tab/Shift+Tab 탐색을 유지하고 트랙·리전·음표 전체를 수천 개의 Tab 항목으로 만들지 않습니다. 편집 영역 진입 후에는 방향키·선택 명령으로 내부 객체를 탐색합니다. 선택·녹음 대기·뮤트·솔로를 색상만으로 구분하지 않습니다. 컨텍스트 메뉴는 키보드 메뉴 키 또는 Shift+F10으로도 열 수 있게 하되, 플랫폼에서 전달되는 경우에만 처리합니다.

모달은 배경 편집을 막고 포커스를 안에 유지합니다. 닫으면 실행 버튼 또는 원래 편집 영역으로 돌아갑니다. 작업 중 창을 여는 명령은 먼저 드래그를 취소하거나 현재 필드를 확정하며, 프로젝트 편집 제스처와 모달을 동시에 활성화하지 않습니다. Escape 한 번은 가장 가까운 작업 하나만 취소합니다.

상태 표시에는 현재 도구, 선택 수, 이동량·길이, 스냅 상태, 녹음 입력과 연결 상태를 필요한 때만 보여줍니다. 잘못된 드롭은 금지 커서와 이유를, 클리핑은 미터와 텍스트를 함께 표시합니다. 반복되는 포인터 이동마다 알림이나 스크린리더 발표를 만들지 않습니다. 긴 작업에는 취소 가능 여부와 진행 상태를 표시합니다.

11. 구현 구조

명령은 id / label / scope / binding / capability / canExecute / execute / repeatPolicy / undoPolicy로 정의합니다. UI 버튼과 키보드가 같은 명령을 호출합니다. 원래 Logic 키는 설명용 메타데이터이고 웹에서 실제 등록하는 키와 구분합니다.

입력 컨텍스트는 text, dialog, menu, gesture, track-list, arrangement, piano-roll, mixer, browser, transport로 나눕니다. 대상 DOM 이름을 여러 컴포넌트에서 따로 추측하는 구현을 줄이고 편집 영역의 명시적인 범위를 사용합니다. React 이벤트와 window 이벤트를 동시에 쓸 때는 defaultPrevented와 스코프 처리를 확인합니다.

제스처는 문서 원본, 미리보기, 확정 명령을 분리합니다. 포인터마다 전역 리스너를 남기지 않고 AbortController 또는 대칭 cleanup으로 정리합니다. 정상 pointerup 이후 캡처 해제가 다시 취소를 호출하지 않도록 활성 상태를 먼저 종료합니다. 프로젝트 전환·Undo·비동기 자산 로드와의 경쟁 상태도 테스트합니다.

편집의 실행 취소 기록은 가능하면 의미 있는 명령 이름과 before/after 선택 상태를 포함합니다. 일정 시간 안에 들어온 업데이트를 무조건 합치는 방식은 초깃값으로 사용하지 않습니다. 페이더 한 번, 음표 드래그 한 번, 다중 리전 이동 한 번을 각각 하나의 명령으로 기록합니다.

13. 승인된 화면의 영역별 세부 동작

13.1 패널 열기·닫기와 크기

패널은 겹치는 팝업 대신 승인된 도킹 영역을 사용합니다. 왼쪽 라이브러리·인스펙터, 오른쪽 브라우저는 각각 독립적으로 열고 닫습니다. 하단은 편집기 또는 믹서 중 하나를 표시하며 각각의 높이·스크롤·확대 상태를 기억합니다. X로 믹서를 닫으면 하단을 닫고, 이전 편집기를 임의로 다시 열지는 않습니다. E는 문맥 편집기를, P는 MIDI 편집기를 명시적으로 엽니다.

구분선 드래그는 작업 공간 설정이며 문서 Undo에 들어가지 않습니다. Escape는 드래그 시작 크기로 되돌립니다. 구분선은 키보드로 선택할 수 있고 방향키는 8 CSS px, Shift+방향키는 32 CSS px씩 조절하는 초기값을 사용합니다. 패널은 자신의 최소 콘텐츠 폭 아래로 찌그러뜨리지 않습니다. 화면 폭이 부족하면 오른쪽 보조 브라우저, 라이브러리 순으로 접을 수 있는 제안을 표시하며 사용자의 명시적 패널 선택을 덮어쓰지 않습니다. 편집 캔버스의 최소 가시 폭은 480 CSS px를 초기 목표로 검증합니다.

인스펙터는 선택 수가 여러 개면 공통값과 혼합값을 구분합니다. 서로 다른 값을 빈 값이나 0으로 위장하지 않습니다. 혼합값에서 절대 숫자를 입력하면 선택 전체에 그 값을 적용하고, 상대 이동 명령은 기존 차이를 보존합니다. 현재 선택 채널과 출력 채널 스트립을 구분하고 출력 스트립을 선택 트랙의 효과와 혼동하지 않게 합니다.

13.2 트랙 헤더와 믹서 채널

헤더의 빈 부분은 선택, 이름 더블클릭은 이름 편집, 번호·전용 손잡이 드래그는 트랙 순서 변경입니다. 순서 변경은 삽입선을 먼저 보여주고 pointerup에서 한 번 확정합니다. 리전의 절대 시간과 라우팅은 유지하고 믹서의 트랙 순서는 같은 모델을 따릅니다. 마스터 출력은 일반 트랙 재정렬 대상으로 넣지 않습니다.

컨트롤 명시적 동작 다중 선택·주의점
M 해당 채널 뮤트 선택 집합의 M 명령은 하나라도 꺼져 있으면 모두 켜고, 모두 켜져 있으면 모두 끔
S 해당 채널 솔로 솔로 채널은 더할 수 있음; ‘이 채널만 솔로’는 별도 메뉴 명령
R 버튼 해당 트랙 녹음 대기 선택과 대기는 별도; 키보드 R의 전체 녹음 시작과 구분
I 버튼 해당 오디오 트랙 입력 모니터링 키보드 I의 인스펙터 토글과 구분; 입력 준비·권한 상태 표시
볼륨·팬 해당 파라미터 편집 채널을 여러 개 선택했다는 이유만으로 모든 페이더를 암묵적으로 연동하지 않음
입력·출력 슬롯 지원하는 입력·버스·출력 선택 메뉴에서 현재 선택과 불가능한 경로를 구분
효과 슬롯 클릭해 해당 효과 편집 바이패스 버튼은 편집창 열기와 다른 hit target

M/S 키는 트랙 목록·어레인지먼트·믹서 문맥에서 선택한 채널 집합에 적용하는 웹 기본안입니다. 피아노롤에서 plain M/S를 음표 삭제나 분할로 해석하지 않습니다. 개별 M/S 버튼은 클릭한 채널 하나에만 적용하고, 여러 채널 동시 토글은 명령 메뉴 또는 해당 영역의 키보드 명령으로 수행합니다. 뮤트·솔로·값 변경은 Undo 대상이며 녹음 대기·입력 모니터링은 세션 상태로 분리합니다. 나중에 프로젝트를 다시 열 때 마이크 모니터링을 자동으로 켜지 않습니다.

솔로된 채널만 들릴 때도 그 채널의 명시적 뮤트는 유지합니다. 솔로 때문에 들리지 않는 상태와 사용자가 M으로 끈 상태는 다르게 표시합니다. 전송 버스와 리턴이 추가되면 솔로 경로가 필요한 리턴을 함께 열도록 별도 라우팅 검증을 요구합니다. 아직 버스를 지원하지 않는 엔진에 슬롯만 작동하는 것처럼 노출하지 않습니다.

효과의 순서 변경은 신호 순서 변경이므로 한 번의 Undo 대상입니다. 드래그 중에는 삽입 위치만 보여주고 기존 체인을 반복 생성하지 않습니다. 효과를 로드하거나 교체하지 못하면 기존 체인을 유지합니다. 1.0의 효과 메뉴에는 실제 구현한 내장·웹 효과만 나타내며, 네이티브 VST 목록은 2.0 호스트가 연결되었을 때 제공하도록 설계합니다.

13.3 눈금자·재생 헤드·사이클·마키

눈금자는 재생 위치 행과 사이클 행의 hit area를 구분합니다. 아래쪽 위치 행 클릭은 해당 위치로 이동하되 리전 선택을 해제하지 않습니다. 재생 헤드 드래그는 위치만 미리 표시하고 놓을 때 한 번 seek합니다. Escape는 원래 위치로 되돌립니다. 연속 스크러빙 오디오는 별도 지원 기능으로 두며 드래그만으로 자동 활성화하지 않습니다.

사이클 행의 빈 부분을 끌면 시작·끝 범위를 만듭니다. 본문 드래그는 길이를 유지한 범위 이동, 양쪽 손잡이는 각 경계 변경입니다. 경계를 교차하면 시작·끝을 정렬하며 최소 1틱 길이를 지킵니다. 일반 생성은 마디 격자에 맞추고 임시 스냅 해제는 §7을 따릅니다. C는 범위를 지우지 않고 활성 상태만 바꿉니다. 마지막 범위가 없는 경우 선택 범위를 감싸고, 선택도 없으면 현재 마디의 1마디를 새 기본 범위로 잡아 표시합니다. 범위 편집과 토글은 프로젝트 상태로 저장하며 한 동작당 한 Undo입니다.

마키는 객체를 모으는 사각형 선택과 구분되는 시간 범위 선택입니다. 시간 구간과 대상 트랙 집합을 보관하고, 처음 클릭이 리전을 실제로 자르지는 않습니다. 선택 범위 삭제·분할·바운스는 별도 명령으로 수행합니다. 이번 단계에서는 마키 시간 범위 안의 Delete를 일반 리전 전체 삭제로 넘기지 않습니다. 시간 범위 삭제가 구현되기 전에는 해당 명령을 비활성화합니다.

녹음 중 재생 위치·사이클·템포를 변경하는 명령은 1.0 초기 정책으로 잠급니다. 버튼·메뉴에 이유를 표시하며 녹음 자료를 조용히 폐기하거나 이전 테이크를 덮어쓰지 않습니다. 기본 녹음 방식은 기존 자료를 보존하는 새 테이크이며, 컴핑·펀치·파괴적 덮어쓰기를 지원한다고 표시하지 않습니다.

13.4 오토메이션과 오디오 편집

A는 표시 상태만 바꿉니다. 선이나 포인트 편집이 구현되면 포인트 클릭은 선택, 연필 또는 선 더블클릭은 포인트 생성, 포인트 드래그는 시간·값 이동, Shift는 축 고정, Delete는 선택 포인트만 삭제하도록 같은 입력 계약을 사용합니다. 최소 한 개의 포인트를 남겨야 한다는 숨은 규칙을 두지 않고, 마지막 포인트를 삭제했을 때의 기본 파라미터 값을 명시합니다. Read·Touch·Latch·Write는 엔진 지원 상태가 확인된 모드만 활성화하며 미구현 Write를 선택 가능하게 만들지 않습니다.

오디오 편집기의 단일 클릭·범위 드래그는 파형 선택입니다. Delete는 파형 원본 파일을 지우지 않습니다. 1.0 초기 편집은 리전 범위·게인·페이드 같은 비파괴 편집이며, 원본 샘플 재작성은 별도 기능입니다. 페이드 손잡이는 길이와 곡선 모양을 구분하고, 서로 겹칠 때의 합성 규칙을 엔진과 같은 함수로 계산합니다. 스테레오를 한 채널로 보이는 파형 요약과 실제 재생 채널 수를 혼동하지 않게 표시합니다.

13.5 수백 트랙에서도 유지할 입력 규칙

선택·드래그·검색은 렌더링된 DOM 개수와 무관한 프로젝트 모델을 사용합니다. 화면 밖 객체도 동일한 선택 규칙을 따릅니다. 포인터 미리보기와 재생 헤드는 매 프레임 전체 React 트리를 갱신하지 않도록 분리하고, 미터는 표시 중인 채널을 중심으로 갱신합니다. 이는 구현 방향이며 현재 수백 트랙 성능이 검증되었다는 뜻이 아닙니다. 체감 반응, 오디오 끊김, 메모리 사용을 각각 측정해야 합니다.

A.1. 공통 입력 상태와 우선순위

편집 영역의 상태는 대기 → 누름 대기 → 드래그 미리보기 → 확정 또는 취소로 정의합니다. 누름 대기에서는 문서 데이터를 변경하지 않습니다. 우선순위는 열린 모달/메뉴 → 진행 중인 제스처 → 텍스트·숫자 입력 → 포커스 편집기 → 전역 명령입니다. 앞 단계에서 처리한 이벤트는 뒤 단계에서 다시 처리하지 않습니다.

마우스·펜의 시작점에서 4 CSS px 이상 이동했을 때 드래그를 시작합니다. 터치는 8 CSS px를 초깃값으로 둡니다. 두 축 절대 이동량 중 큰 값으로 판정하며 화면 배율·기기 픽셀 수와 혼동하지 않습니다. 이동했다가 원점으로 돌아와도 이미 시작한 드래그가 클릭으로 변하지는 않습니다. 최종 값이 원본과 같으면 확정 단계에서 변경 없음으로 종료합니다.

클릭은 같은 포인터의 누름·놓음으로 구성합니다. 다른 손가락이나 다른 포인터의 놓음이 현재 작업을 확정해서는 안 됩니다. 편집 중 새 터치는 기존 작업을 대체하지 않습니다. 기본 지원 범위 밖의 다중 터치 확대는 별도 기능으로 분리합니다.

사각형 선택

기본 선택 도구로 빈 그리드를 끌면 사각형 선택을 시작합니다. 선택 사각형과 객체의 표시 영역이 교차하면 포함합니다. 점 또는 0폭 영역은 사각형 선택으로 확정하지 않습니다. 드래그 시작 시의 선택 집합을 기준으로, 기본은 교체, Shift는 추가입니다. 제외 선택은 명시적인 제외 선택 명령에 연결하며 복제 수정키와 같은 문맥에서 충돌시키지 않습니다.

사각형 선택의 미리보기 집합과 확정 집합을 나눕니다. Escape로 취소하면 시작 전 선택을 복원합니다. 선택 변경은 프로젝트 실행 취소 기록이나 자동 저장을 발생시키지 않습니다. 스크롤 밖에 있는 객체도 프로젝트 좌표로 판정하며, 렌더링된 DOM에 존재하는 객체만 선택하는 구현을 피합니다.

A.3. 클릭·더블클릭·도구의 구분

기본 선택 도구에서 첫 클릭은 선택만 합니다. 타임라인의 기존 MIDI 리전 더블클릭은 해당 리전의 피아노롤을 열고, 오디오 리전 더블클릭은 오디오 편집기를 엽니다. 재생 위치나 리전 위치를 바꾸지 않습니다. 편집기가 이미 열려 있으면 내용과 포커스만 바꾸고 창을 다시 만들지 않습니다.

빈 MIDI 트랙의 더블클릭은 해당 지점에 빈 MIDI 리전을 만드는 제안입니다. 시작점은 현재 스냅 규칙을 적용하고 기본 길이는 1마디로 둡니다. 빈 오디오 트랙 더블클릭은 음원 가져오기 동작으로 별도 정의합니다. MIDI 빈 그리드의 더블클릭은 음표를 하나 만듭니다. 연필 도구에서는 한 번 누르거나 누른 채 끌어 음표를 만듭니다. 기본 선택 도구의 빈칸 단일 클릭은 음표를 만들지 않습니다.

더블클릭은 브라우저가 판정한 dblclick을 기준으로 삼아 운영체제의 더블클릭 설정을 존중합니다. 자체 200ms 타이머로 클릭을 지연시키지 않습니다. 첫 클릭은 비파괴 선택 동작이므로 더블클릭을 기다리느라 선택 반응을 늦출 필요가 없습니다. 두 클릭 사이에 실제 드래그가 시작되거나, 포인터 캡처 해제 후 이벤트가 다른 표면으로 재지정되면 더블클릭 편집을 실행하지 않습니다.

트랙·믹서 채널의 이름 영역 더블클릭은 이름 입력을 엽니다. 리전은 제목과 몸체의 더블클릭을 모두 편집기 열기로 통일합니다. 리전 이름 변경은 이름 변경 명령 또는 인스펙터에서 제공합니다. 이름 입력 중에는 일반 텍스트 편집이 우선하며, 이름 필드의 더블클릭이 편집기 열기로 전파되지 않습니다.

A.4. 타임라인 이동과 복제

리전 이동은 눌렀던 위치와 리전 시작점 사이의 간격을 보존합니다. 리전의 오른쪽을 잡아 끌었다고 시작점이 포인터 아래로 점프하지 않습니다. 다중 선택은 원본의 시간 간격과 트랙 간격을 유지하며, 활성 리전 하나를 스냅 기준 객체로 사용합니다.

여러 리전 중 가장 이른 시작점이 프로젝트 0보다 앞서지 않도록 선택 전체의 이동량을 함께 제한합니다. 각 객체를 따로 0으로 자르면 서로 겹치거나 간격이 무너지므로 허용하지 않습니다. 세로 이동 역시 선택 묶음의 상대 트랙 순서를 보존합니다. 오디오 리전은 오디오 트랙, MIDI 리전은 악기/MIDI 트랙으로 이동할 수 있습니다. 목적지 중 하나라도 부적합하면 전체 드롭을 거부하며, 일부만 옮기지 않습니다. 트랙 자동 생성은 명시적인 새 트랙 드롭 영역에서만 수행합니다.

Alt/Option 복제는 누르는 시점에 따라 미리보기 의도를 바꿀 수 있는 제안입니다. 드래그 중 수정키가 켜지면 원본을 보존한 복제 미리보기와 ‘복제 N개’를, 꺼지면 이동 미리보기와 ‘이동 N개’를 보여줍니다. 최종 의도는 해당 pointerup의 수정키 상태로 결정합니다. 키 변화만으로 프로젝트를 수정하지 않습니다. 포커스를 잃으면 확정하지 않고 취소하므로 놓친 키 해제 이벤트가 잘못된 편집으로 이어지지 않습니다.

복제 객체 ID는 유효한 드롭이 확정될 때 한 번만 만듭니다. MIDI 음표와 자동화 등 자식 객체에도 새 ID를 부여합니다. 오디오 원본 파일은 복사하지 않고 같은 음원 자산을 참조합니다. 복제·이동 모두 한 번의 실행 취소로 전체를 되돌립니다. 복제 후 선택은 새 객체 집합으로 바뀌며, 원본은 선택 해제합니다.

A.5. 스냅·경계·트림

내부 음악 시간은 4분음표당 960틱을 기준으로 정수 계산하는 제안입니다. 화면에서는 마디·박·분할 값으로 보여줍니다. 스냅을 끄더라도 내부 최소 단위보다 더 작은 시간을 저장하지 않습니다. 타임라인과 피아노롤에서 같은 격자를 선택하면 같은 틱 값으로 계산해야 합니다.

기본 이동은 상대 스냅입니다. 원래 격자에서 조금 벗어난 리전을 한 박 옮기면 그 미세한 차이를 유지합니다. 절대 스냅 모드에서는 활성 객체의 시작점을 격자에 맞춥니다. 임시 스냅 해제 수정키는 드래그 중 즉시 적용되며, 놓으면 현재 위치를 다시 스냅합니다. 복제, 스냅 해제, 축 고정은 본문 §7의 예약 조합과 플랫폼 우선순위를 적용한 뒤 각각 계산합니다. Windows/Linux Control+Shift에서는 축 고정을 함께 켜지 않습니다.

우측 트림은 시작점과 원본 오프셋을 유지하고 길이만 바꿉니다. 좌측 트림은 시작점·길이·내용 오프셋을 함께 바꿔서 기존 내용의 절대 재생 위치를 보존합니다. 트림은 음원이나 음표를 파괴적으로 삭제하지 않습니다. 다시 늘리면 허용된 원본 범위 안의 내용이 돌아와야 합니다.

고정 템포이며 타임 스트레칭을 하지 않는 오디오 리전에서 좌측 경계를 δ beat 옮길 때 계산은 다음과 같습니다.

  • newStartBeat = oldStartBeat + δ
  • newLengthBeats = oldLengthBeats − δ
  • newOffsetSeconds = oldOffsetSeconds + δ × 60 / BPM

오프셋은 0 이상, 오프셋과 재생 길이의 합은 원본 음원 길이 이하로 제한합니다. 경계는 최종적으로 원본 샘플 프레임에 맞추고, 확정 표시 값도 그 결과로 갱신합니다. 템포 맵·타임 스트레칭이 추가되면 고정 BPM 공식을 재사용하지 않고 해당 시간 변환을 사용합니다.

MIDI 좌측 트림을 비파괴적으로 지원하려면 보이지 않는 음표를 보존할 내용 오프셋 또는 원본 패턴 참조가 필요합니다. 현재 리전 길이에 맞춰 음표를 잘라 버리는 구현은 이 명세를 충족하지 않습니다. 데이터 모델 확장 없이 가능한 것처럼 표시하지 않습니다.

선택한 여러 객체의 같은 쪽 경계를 함께 늘릴 때는 각 객체에 동일한 길이 변화량을 적용합니다. 가장 짧은 객체의 최소 길이와 모든 원본 범위가 허용하는 변화량만 사용합니다. 개별 객체별 제한 때문에 길이가 서로 다르게 변하면, 공통 한계에서 전체를 멈춥니다. 트림과 반복 생성은 별도 손잡이·커서·명령으로 구분합니다.

작은 리전의 손잡이

미세한 경계 손잡이는 마우스 기준 6 CSS px를 초깃값으로 둡니다. 양쪽 손잡이가 겹치는 폭의 리전에서는 몸체 이동을 우선하고, 선택 후 경계 손잡이를 바깥으로 노출합니다. 반복 손잡이·페이드·좌우 트림을 하나의 겹친 히트 영역으로 두지 않습니다. 우선순위는 명시적 손잡이 → 제목/컨트롤 → 몸체 → 빈 그리드입니다. 작은 객체의 정확한 길이는 인스펙터 숫자 입력으로도 바꿀 수 있어야 합니다.

A.6. 피아노롤

음표 이동은 시간과 음높이를 독립적으로 계산합니다. 다중 선택의 시간 간격과 음정 간격을 유지하고, MIDI 음높이 0–127을 넘는 경우 전체의 음높이 변화량을 함께 제한합니다. 시간도 가장 이른 음표가 0을 넘지 않도록 묶어서 제한합니다. 드래그 중에는 원래 음표와 임시 위치를 구분하고, 놓을 때 한 번만 데이터에 반영합니다.

기본 음표 길이는 이 편집기에서 마지막으로 확정한 생성 길이를 기억하며, 초기값은 1박입니다. 생성 위치에서 리전 끝까지 남은 길이가 짧으면 그 길이로 제한합니다. 새 음표가 들어갈 최소 공간이 없으면 만들지 않습니다. 스냅 켜짐의 최소 생성·리사이즈 길이는 선택 격자 한 칸, 스냅 꺼짐은 1틱입니다. 이미 존재하는 더 짧은 음표를 단순 이동했다고 자동으로 늘리지 않습니다.

음표의 벨로시티는 UI에서 1–127, 저장에서 정규화된 값 또는 정수 중 하나로 명시하고 왕복 변환을 일관되게 유지합니다. 화면에서 84로 확정한 값이 다시 열었을 때 83으로 바뀌지 않아야 합니다. 벨로시티 0을 음표 삭제와 혼용하지 않습니다. 여러 음표는 상대 변화량을 기본으로 하고, ‘같은 값으로 설정’은 명시적 숫자 입력으로 구분합니다. 범위 끝에서 개별 클램프를 허용한다면 사용자가 볼 수 있는 선택 상태와 값 표시를 유지합니다.

드래그 미리 듣기는 음높이가 바뀔 때만 갱신하고 같은 행 안의 모든 포인터 이벤트마다 음을 재생하지 않습니다. 취소·포커스 이탈·음표 삭제·편집기 닫힘 시 미리 듣기를 종료합니다. 재생 중 오디션 사용 여부는 설정으로 분리합니다. 우클릭은 음표 메뉴를 열며 삭제는 명시적인 메뉴 항목이나 편집기 범위의 삭제 명령으로 수행합니다.

A.7. 스크롤·자동 스크롤·확대

일반 휠은 세로 스크롤, 가로 트랙패드 입력은 가로 스크롤, Shift+휠은 가로 스크롤로 처리하는 제안입니다. 표준 Ctrl/Cmd+휠 브라우저 확대는 침범하지 않습니다. 앱 확대는 앱의 명시적 제어와 검증된 단축키를 사용합니다. 휠을 페이더 위에 올려두었다는 이유만으로 볼륨을 바꾸지 않습니다.

타임라인 좌우 가장자리 24px에 포인터가 들어오면 자동 스크롤합니다. 거리 d에 대해 속도는 600 × (1 − d/24)² px/s를 초깃값으로 사용하며, 범위를 벗어나면 0입니다. 위아래도 같은 규칙으로 적용하되 해당 편집 영역만 스크롤합니다. 프로젝트 시작, 마지막 트랙, 최저·최고 음높이에서는 멈춥니다. 시간 기반으로 계산해 화면 재생률이 달라도 같은 속도가 되게 합니다.

포인터가 움직이지 않아도 자동 스크롤 중에는 매 프레임 문서 좌표와 미리보기를 다시 계산합니다. 사이드바나 화면 전체를 자동 스크롤시키지 않습니다. 포인터 캡처 상태를 유지하며 편집기 밖에서 버튼을 놓아도 확정·취소를 정확히 마칩니다. 편집기 내부를 벗어나 허용하지 않은 목적지에 놓으면 원상 복구합니다.

확대 중심은 포인터가 작업 그리드 위에 있을 때 그 지점, 키보드·툴바 조작에서는 현재 보이는 작업 영역의 중앙입니다. 확대 전후 같은 음악 시간이 그 중심 위치에 남습니다. 확대·스크롤은 프로젝트 Undo에 넣지 않습니다. 진행 중인 편집 제스처에서는 확대를 시작하지 않으며, 이동의 좌표 기준을 중간에 바꾸지 않습니다.

A.8. 숫자·페이더·노브

숫자 입력은 포커스에서 편집 초안을 만들고 Enter로 확정, Escape로 취소합니다. 유효한 값을 입력한 채 다른 컨트롤로 이동하면 확정합니다. 비어 있거나 범위·형식이 잘못된 값은 Enter에서 확정하지 않고 해당 필드에 오류를 보여줍니다. 잘못된 상태로 포커스를 잃으면 기존 확정 값으로 복원합니다. 1.5, −6 dB, 1 bar처럼 허용할 단위와 소수점 규칙은 필드별로 명시합니다. 화면에 표시하는 단위와 실제 계산 단위가 다르면 변환 결과를 확정 전에 확인할 수 있어야 합니다.

페이더·노브는 누름부터 놓음까지 한 제스처입니다. 드래그 값은 즉시 미리 듣기에 반영할 수 있지만 Escape·취소 시 음향 값도 복원합니다. 키보드 방향키로 연속 조절할 때는 키 누름부터 해제까지 한 묶음으로 기록합니다. 서로 다른 컨트롤의 조작을 단순히 450ms 안에 일어났다는 이유로 합치지 않습니다. 미세 조정 수정키는 현재 드래그 구간의 감도만 바꾸고, 켜거나 끄는 순간 값이 점프하지 않게 기준점을 다시 잡습니다.

A.9. 취소와 실행 취소의 계약

Escape는 가장 가까운 활성 작업 하나를 취소합니다. 순서는 팝업/모달, 진행 중인 편집 제스처, 필드 편집, 현재 영역의 선택 해제입니다. 한 번 누른 Escape가 이 단계를 연달아 통과하지 않습니다. pointercancel, 예기치 않은 포인터 캡처 상실, 창의 blur, 문서 숨김, 컴포넌트 해제는 진행 중 제스처를 취소하고 원본·선택·오디션을 복원합니다. 정상적인 pointerup 이후 포인터 캡처를 해제할 때는 취소가 다시 실행되지 않도록 상태를 먼저 종료합니다.

이동·트림·복제·다중 음표 편집은 한 동작당 한 Undo입니다. 미리보기 중간 프레임은 Undo나 자동 저장에 들어가지 않습니다. 취소, 유효하지 않은 드롭, 결과가 원본과 같은 조작은 기록하지 않습니다. 취소·선택·스크롤만으로 Redo를 지우지 않습니다. 새로 확정한 문서 편집만 Redo 분기를 지웁니다.

Undo와 Redo는 문서뿐 아니라 가능한 범위에서 그 작업의 선택·활성 객체를 복원합니다. 이미 존재하지 않는 ID는 제거합니다. 작업 중 Undo를 요청하면 현재 미확정 제스처부터 취소하고, 같은 키 이벤트로 그 이전 작업까지 추가 취소하지 않습니다. 드래그 도중 자동 저장이 실행되어도 마지막으로 확정된 문서만 저장합니다.

A.10. 필수 QA 시나리오

  1. 리전을 3px 움직였다 놓아도 위치·선택의 드래그 처리·Undo 수가 바뀌지 않습니다.
  2. 격자에서 7틱 벗어난 리전을 상대 스냅으로 한 박 옮기면 7틱 차이가 유지됩니다.
  3. 다중 선택의 가운데 객체를 끌면 전부 움직이고 상대 간격이 유지됩니다.
  4. 선택 집합의 첫 리전이 0에 닿으면 전체가 함께 멈춥니다.
  5. Alt/Option을 드래그 도중 켜고 끌 때 미리보기만 바뀌며 확정 전 새 ID가 생기지 않습니다.
  6. 복제 확정 후 모든 리전·자식 음표 ID가 고유하고 원본 오디오 자산 참조는 재사용됩니다.
  7. MIDI와 오디오가 섞인 선택을 부적합한 트랙 묶음에 놓으면 아무 객체도 이동하지 않습니다.
  8. 오디오 좌측 트림 후 같은 소리가 같은 절대 시점에 재생되며, 다시 확장하면 원본 범위가 돌아옵니다.
  9. 리전을 누른 채 Escape를 누르면 원본으로 돌아가고 이후 pointerup이 확정하지 않습니다.
  10. 창 전환·탭 숨김·편집기 닫기·pointercancel 모두 같은 취소 결과를 냅니다.
  11. 정상 드롭 뒤 lostpointercapture가 발생해도 확정한 변경이 취소되지 않습니다.
  12. 음표 삭제 키를 길게 눌러도 빈 음표 선택에서 리전이나 트랙이 삭제되지 않습니다.
  13. 오른쪽 클릭으로 음표나 리전이 삭제되지 않고 올바른 선택 범위의 메뉴가 열립니다.
  14. 빈 그리드 단일 클릭은 선택만 해제하며, 더블클릭 한 번은 음표를 정확히 한 개 만듭니다.
  15. 음표 드래그 후 발생한 후행 click이 빈칸 음표 추가로 처리되지 않습니다.
  16. 다중 음표를 위로 끌 때 최고 음이 127에 닿으면 모든 음정 간격이 유지된 채 멈춥니다.
  17. 가장자리에서 포인터를 정지해도 자동 스크롤과 미리보기가 함께 이어집니다.
  18. 페이더를 연속 조절한 후 Undo 한 번으로 시작 값이 돌아오고 다른 페이더의 이전 작업은 남습니다.
  19. 숫자 입력에서 한글 조합·소수점 입력·Escape·잘못된 단위가 전역 재생/삭제를 호출하지 않습니다.
  20. 취소·선택·확대·스크롤 뒤에도 기존 Redo가 유지됩니다.
  21. Undo 뒤 선택한 ID가 유효하며, 선택 없음이 다른 편집 영역의 객체를 대신 가리키지 않습니다.
  22. 확대 전 포인터 아래의 박자가 확대 후에도 같은 위치에 남고 눈금·클립·재생 커서가 정렬됩니다.
  23. 작은 리전에서 몸체·좌우 경계·반복·페이드가 겹쳐 엉뚱한 편집을 시작하지 않습니다.
  24. 텍스트 입력, 파일 선택 대화상자, 메뉴가 열린 동안 캔버스 편집 명령이 실행되지 않습니다.
