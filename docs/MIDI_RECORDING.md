# MIDI 입력·녹음·캡처

[MIDI 리전 벤치마크](MIDI_REGION_BENCHMARK.md) 1단계(P0)를 구현한 문서입니다. 외부 MIDI 키보드나 컴퓨터 키보드로 악기 트랙을 연주하고, 녹음하거나 녹음하지 않은 마지막 연주를 캡처해 MIDI 리전으로 만듭니다. 서스테인 페달(CC64)의 저장·재생 규칙은 [SUSTAIN_PEDAL.md](SUSTAIN_PEDAL.md)를 따릅니다.

## 한눈에

| 기능 | 사용법 |
| --- | --- |
| MIDI 장치 | 설정 › 오디오 장치 › **MIDI 입력**. 브라우저는 처음에 `MIDI 장치 사용 허용`을 눌러 권한을 줍니다. 장치마다 사용 켬/끔(기본 켬)을 고르며, 선택은 이 컴퓨터에 장치 이름으로 저장됩니다. 꽂거나 뽑으면 목록이 바뀝니다. |
| 트랙 MIDI 입력 | 악기 트랙 인스펙터 › **MIDI 입력**: `모든 MIDI 입력`(기본) / 장치 하나 / `없음`, 옆 메뉴에서 `모든 채널` 또는 채널 1–16. 저장되고 Undo됩니다. 컴퓨터 키보드는 `모든 MIDI 입력`에 포함됩니다. |
| 실시간 연주 | 악기 트랙에서 **I(입력 모니터링 켬)** 이거나, 녹음 활성화(R 버튼)했거나, 녹음 활성화된 악기 트랙이 하나도 없을 때 **선택한(포커스) 악기 트랙**(로직 자동 활성)으로 갑니다. 인스펙터의 모니터 `끔`은 연주를 받지 않습니다. 트랙 트랜스포즈·벨로시티 오프셋·키/벨로시티 제한이 적용되고 벨로시티에 반응합니다. |
| 컴퓨터 키보드 연주 | `⌘K`(Windows `Ctrl+K`) 또는 머리말의 키보드 버튼. A S D F G H J K = 흰 건반(C3부터), W E T Y U = 검은 건반, O L P ; ' = 다음 옥타브 위쪽, Z/X = 옥타브 내림/올림, C/V = 벨로시티 20씩(1·127 끝값 포함). 켜져 있으면 머리말에 `C3 · 100`처럼 표시됩니다. |
| MIDI 녹음 | 녹음 활성화된 악기 트랙(없으면 포커스 악기 트랙)에서 `R` 또는 녹음 버튼. 카운트인(메트로놈 설정)이 끝나면 빨간 임시 리전이 자라며 음표가 바로 그려지고, `R`·`Space`·정지·프로젝트 끝에서 MIDI 리전으로 확정됩니다. Undo 한 단계(`MIDI 녹음`). |
| 녹음 모드 | 머리말의 `합치기`(기본) / `대체`. 합치기는 겹치는 MIDI 리전과 새 음표를 한 리전으로 합칩니다(Ableton 오버더브, Logic Merge). 대체는 녹음한 구간의 기존 리전 부분을 잘라내고 새 연주로 바꿉니다(Logic Replace). |
| 사이클 녹음 | 반복 구간(C)을 켠 채 녹음하면 리전은 사이클 구간이 되고, 매 회차의 연주가 한 리전에 합쳐집니다. MIDI 테이크 폴더는 아직 없으므로 회차는 항상 합칩니다. |
| 동시 녹음 | 녹음 활성화된 악기 트랙 전부가 한 번에 녹음되고 한 번의 Undo로 되돌아갑니다. 각 트랙은 자기 MIDI 입력/채널 필터에 맞는 음만 받습니다. 녹음 활성화된 오디오 트랙이 있으면 오디오 녹음과 함께 진행되고, 이때는 녹음 활성화된 악기 트랙만 MIDI를 녹음합니다. |
| 캡처 | `⇧R` 또는 머리말의 캡처 버튼. 녹음하지 않는 동안 최근 5분의 입력을 기억해 두었다가, 마지막 연주(4초 이상 아무 음도 누르지 않은 쉼 뒤의 연주)를 녹음 대상 트랙의 리전으로 만듭니다. 재생 중에 연주했으면 연주한 박 위치에, 정지 중이면 프로젝트 템포로 재생 커서에서 시작합니다(템포 추정 없음). 사이클 재생 중이면 마지막 한 바퀴만 가져옵니다. |
| 퀀타이즈 | 피아노롤 머리말 `Q` 버튼: 격자(스냅 따라가기/1/4…1/64/셋잇단), 강도 0–100%, 스윙 0–100%, 음 시작/음 끝. `Q`는 마지막 설정으로, `⇧Q`는 음 끝도 함께 퀀타이즈합니다. 리전 인스펙터에는 비파괴 `Q-강도`(기본 100%)가 퀀타이즈·Q-스윙 아래에 있습니다. |
| 패닉 | 재생을 멈추면 실시간 음과 페달이 모두 해제됩니다(All Notes Off). CC123/CC120을 보내는 키보드도 같은 처리를 받습니다. |

## 단축키 우선순위

- 컴퓨터 키보드 연주가 켜져 있으면 **수식키 없는** A–' 행·W E T Y U O P·Z X C V가 음/옥타브/벨로시티가 되고, 그 키의 앱 단축키(S 솔로, M 음소거, K 메트로놈, C 사이클, Z 맞춰 보기, X 믹서, F 라이브러리, G 글로벌 트랙, H 가리기, T…)는 쉬어 갑니다. Logic Musical Typing과 같습니다.
- `Space`, `R`, 방향키, `Enter`, `Delete`, `Esc`와 수식키가 붙은 모든 단축키(`⌘Z`, `⌘K`로 끄기, `⇧R` 캡처 등)는 그대로 동작합니다. Shift를 누른 문자는 음을 내지 않습니다.
- 텍스트 입력칸과 대화상자 안에서는 연주하지 않습니다. 창이 포커스를 잃으면 누르고 있던 음을 모두 놓습니다.
- `⌘K`/`Ctrl+K`는 브라우저 주소창 검색보다 앱이 먼저 받습니다.

## 타이밍과 지연 보정

녹음 위치는 React 렌더나 UI 시간이 아니라 이벤트 시각과 오디오 시계로 계산합니다(`core/midiRecording.ts`, `audio/liveMidi.ts`).

- **브라우저(Web Audio)**: Web MIDI 이벤트의 `timeStamp`(키보드는 `KeyboardEvent.timeStamp`)를 `AudioContext.getOutputTimestamp()`로 오디오 시계에 옮깁니다. 출력 타임스탬프는 "지금 스피커에서 나오는 시점"이므로 출력 지연(`outputLatency`)이 자동으로 빠지고, 결과는 연주자가 그 순간 들은 편곡 위치입니다(`heardTransportBeat`). `getOutputTimestamp`가 없으면 `currentTime − baseLatency − outputLatency`로 대신합니다. 실시간 음은 받는 즉시 발음합니다(입력→소리 지연 ≈ 오디오 렌더 블록 + 출력 지연).
- **데스크톱(네이티브)**: 호스트가 WinMM(macOS는 CoreMIDI)으로 장치를 직접 열고, 콜백 스레드의 시각을 붙여 락프리·할당 없는 큐로 오디오 스레드에 넘깁니다. 오디오 콜백은 "직전 콜백 시작 후 t초에 도착한 이벤트를 이번 블록의 t초 위치"에 놓아(블록 하나만큼 일정한 지연, 지터 없음) 샘플 단위로 재생합니다. 녹음 위치 `frame` = 그 이벤트가 렌더된 트랜스포트 frame − 블록 지연 − 드라이버가 보고한 출력 지연입니다. 플러그인 지연 보정(PDC)은 빼지 않습니다.
- **컴퓨터 키보드(데스크톱)**: `midi.inject`로 같은 호스트 큐에 들어가므로 라우팅·스탬프가 같습니다. IPC 몇 ms만큼 늦게 기록될 수 있습니다.
- **카운트인**: 카운트인 중 연주는 녹음하지 않습니다. 단 카운트인에서 누른 채 다운비트를 넘긴 음과 페달은 녹음 시작 박에서 시작합니다. 지연 보정으로 시작 박보다 조금 앞에 찍힌 음도 시작 박으로 당깁니다.
- **사이클**: 박이 뒤로 크게 뛰면 회차가 바뀐 것으로 봅니다(UI 시계로도 확인). 회차 경계를 넘어 누르고 있던 음은 사이클 끝에서 끝나고, 페달은 사이클 끝에서 닫힌 뒤 사이클 시작부터 다시 이어집니다.
- 기록되는 음은 입력 원래의 음높이·벨로시티입니다. 트랙 트랜스포즈 등은 재생 때 적용되므로 두 번 적용되지 않습니다.

## 서스테인 페달(CC64)

- 실시간: 두 엔진 모두 페달을 밟은 동안 노트 오프를 미루고, 페달을 떼면 놓습니다. 같은 음을 다시 치면 이어지던 음을 그 자리에서 끝냅니다. 드럼 킷은 페달을 무시합니다. 데스크톱은 호스트 오디오 스레드에서 처리하며 VST3에는 모든 CC를 그대로 넘깁니다. 트랙을 바꾸면(라우트가 없어지면) 그 트랙의 페달도 떼어집니다.
- 녹음: 트랙마다 페달 구간으로 모아 리전의 `sustain`(스키마 13)에 저장합니다. 합치기는 기존 리전의 페달과 합집합, 대체는 녹음 구간의 페달을 새 것으로 바꿉니다. 사이클 회차의 페달은 합집합입니다. 캡처도 연주 구간 안의 페달을 함께 가져옵니다.
- 다른 CC·피치 벤드·채널 애프터터치·프로그램 체인지는 자동 감량을 거쳐 리전의 컨트롤러 레인이 되고, 캡처에도 들어갑니다. 실시간 입력도 두 엔진에서 바로 소리에 반영됩니다([MIDI_CONTROLLERS.md](MIDI_CONTROLLERS.md)).

## 실기기에서 확인할 것

자동 테스트는 가짜 MIDI 접근·주입 이벤트·네이티브 단위 테스트로 검증했습니다. 다음은 실제 장치로 확인해야 합니다.

- Windows WinMM으로 실제 키보드 음 수신(장치 열기까지는 확인), macOS CoreMIDI 경로 빌드·수신·핫플러그.
- 체감 입력 지연과 ASIO/WASAPI/Core Audio가 보고하는 출력 지연 값의 정확도(녹음 위치가 메트로놈에 맞는지).
- VST3 악기의 실시간 음·CC64(이 빌드는 VST3를 끈 상태로 검증).
- 브라우저 Web MIDI 권한 거부·재허용 흐름, 장치 이름이 같은 장치 두 대.
- 연주 중 출력 장치·샘플레이트 변경 시 음이 남지 않는지.
