# Logic Pro 오디오 설정 벤치마크와 구현 계약

2026-11-02 · 작업 시작 기준: [`a589cf21`](https://github.com/songchez/garak-ieum/tree/a589cf2174a9674d4b0b219a989a9a2d4ebeb6ef) · 아래 연결 범위는 이 기준 위에 추가한 오디오 설정 소스와 대조했습니다.

## 1. 목적과 근거의 수준

마이크·오디오 인터페이스·출력 장치·샘플레이트를 한 설정 창에서 확인하고 변경할 수 있게 합니다. Logic Pro의 설정 구조와 작업 흐름을 참고하되, 실제로 제어하는 값과 운영체제·브라우저가 결정하는 값을 구별합니다. 한옥 디자인과 통합 상단 바는 유지합니다.

이 문서는 **벤치마크의 구현 계약, 현재 코드 연결 범위와 합격 기준**을 함께 기록합니다. 구현 목표 표와 현재 연결 표를 구분하며, 코드에 연결돼 있다는 이유로 실제 장치 검증 통과 또는 Logic과의 기능 동등성을 뜻하지 않습니다. 소스·테스트의 상태는 [구현 상태](IMPLEMENTATION_STATUS.md)에 기록합니다. 임의의 기능 개수로 일치율을 계산하지 않습니다. 실제 브라우저에서의 설정 조작과 오디오 인터페이스를 사용한 녹음·청음·왕복 지연은 아직 검증하지 않았습니다.

| 근거 구분 | 이번 조사에서 확인한 범위 |
|---|---|
| 공식 12.3 | 현재 Mac용 가이드 목차, 설정 개요, 채널 스트립 입력/출력 제어, 출력 매핑의 12.3 페이지를 확인했습니다. iPad 설정과 혼용하지 않습니다. [A1][A2][A7][A8] |

| 웹 API | 표준 문서와 브라우저 제공자 문서를 기준으로 기능을 탐지합니다. 출시 문서가 있어도 사용자의 브라우저·권한·장치에서 지원된다는 뜻은 아닙니다. [W1–W9] |
| 제품 기준 | 변경 적용·취소·복구, 입력 테스트, 실패 안내, 자동 저장·Undo 범위는 가락이음의 동작 계약입니다. Apple의 내부 구현으로 설명하지 않습니다. |

## 2. 설정의 소유 범위를 나눕니다

Logic의 앱 설정은 모든 프로젝트에 공통 적용되며, 프로젝트 설정은 별도 창으로 구분됩니다. 기본 설정 열기 키는 macOS `⌘,`입니다. 샘플레이트는 프로젝트 오디오 설정의 속성입니다. [A2][A4]

| 범위 | 구현 대상 | 저장·이력 기준 |
|---|---|---|
| 이 브라우저의 장치 설정 | 입력/출력 장치 ID, 지연 요청, 지원 시 렌더 블록 요청, 소프트웨어 모니터링, 입력 채널 수 요청, 입력 처리 옵션, 수동 녹음 정렬 보정 | 로컬 설정에 저장합니다. 프로젝트 파일로 다른 컴퓨터의 장치 ID를 강제하지 않으며 프로젝트 Undo와 분리합니다. |
| 프로젝트 오디오 | 프로젝트 샘플레이트 | 프로젝트 모델·자동 저장·`.garak`에 포함합니다. 명시적 변경은 프로젝트 Undo/Redo 대상으로 연결합니다. |
| 현재 실행 상태 | 엔진 샘플레이트·상태, 사용 중인 입력/출력, 입력 스트림 설정, 렌더 블록·지연 정보 | 읽기 전용 진단입니다. 저장된 요청값을 현재 측정/보고값으로 대신 표시하지 않습니다. |
| 오디오 하드웨어/운영체제 | 드라이버 버퍼, 클록, 프리앰프 게인, 팬텀 파워, 직접 모니터링, 물리 포트 라우팅 | 현재 웹 엔진의 설정 범위 밖입니다. 지원되는 장치 제어처럼 활성 버튼을 제공하지 않습니다. |

로고 메뉴의 **설정…**, 하단 오디오 상태 버튼과 macOS `⌘,`를 제공합니다. Windows/Linux `Ctrl+,`는 가락이음의 대응 키입니다. 이 앱 명령은 입력 필드·일반 버튼에도 적용되지만 다른 모달이 열린 동안에는 실행하지 않습니다. 기존 48px 통합 헤더를 유지합니다. 설정이 열려 있는 동안 텍스트 입력·키보드 탐색이 편집기의 재생/삭제 명령을 실행하지 않아야 합니다.

## 3. Logic 항목과 구현 목표의 매핑

상태는 **구현 대상**, **조건부 구현 대상**, **명시적 미지원**으로만 표시합니다. 정확한 하드웨어 I/O 버퍼 선택지 전체와 녹음 지연의 최신 최소·최대 범위는 이번 공식 문서 조사로 확정하지 못했습니다.

아래의 **연결**은 UI·모델·엔진에 코드 경로가 존재한다는 뜻입니다. 모의 API 테스트와 실제 브라우저/장치 검증은 별도이며, 위 구현 목표나 아래 QA를 모두 통과한 것으로 취급하지 않습니다.

## 4. 값과 표시의 의미

### 4.1 요청한 값과 현재 보고값

설정 창은 `요청`, `현재`, `지원 안 함`, `정보 없음`, `연결 끊김`을 구별해야 합니다. `getSupportedConstraints()`가 알려주는 이름 지원과 특정 장치의 `getCapabilities()` 범위, 현재 `getSettings()` 값은 서로 다른 정보입니다. 값이 누락됐다는 이유로 `false`, `0`, 기본 장치명으로 채워 현재 상태처럼 표시하지 않습니다. [W6][W7]

엔진의 `sampleRate`는 그 오디오 그래프의 처리율입니다. 이를 읽었다는 이유만으로 인터페이스의 물리 클록이 같은 값으로 설정됐다고 설명하지 않습니다. 입력의 샘플레이트와 채널 수는 실제 입력 스트림이 보고할 때만 표시합니다. [W1][W6]

`latencyHint`는 요청이며 브라우저가 따르지 않을 수 있습니다. `interactive`는 낮은 지연, `balanced`는 지연과 전력의 균형, `playback`은 지연을 허용한 재생 전력 효율을 뜻합니다. 이를 Logic의 처리 버퍼나 플러그인 저지연 모드와 같은 기능으로 설명하지 않습니다. `baseLatency`와 `outputLatency`는 서로 다른 구간의 정보이고, 이를 합쳐도 마이크 입력·변환·장치 전체를 실측한 왕복 지연이 되지 않습니다. 표시 단위는 ms로 통일하고 원 API의 초 값을 올바르게 변환합니다. [W3–W5]

Chrome 153은 설정 가능한 렌더 퀀텀을 출시 항목으로 설명합니다. 구현은 브라우저 이름/버전 추측에 의존하지 않고 `renderQuantumSize` 등 실제 기능을 확인해야 합니다. `renderSizeHint`의 숫자·기본·하드웨어 힌트는 **웹 오디오 처리 블록**의 의미입니다. 보고값이 없거나 아직 확정되지 않은 상태는 그대로 표시합니다. [W1][W2]

### 4.2 프로젝트 샘플레이트

프로젝트 값은 편집 데이터에 속합니다. 새 프로젝트·데모·기존 파일 열기·자동 복원·다른 프로젝트로 전환·Undo/Redo 모두 같은 정규화와 엔진 적용 경로를 사용합니다. 현재 호환 기본값은 **48kHz**이며, 필드가 누락된 경우에만 적용합니다. 명시적으로 잘못된 값은 조용히 기본값으로 바꾸지 않고 거부합니다. 녹음·녹음 준비 중에는 레이트를 바꾸는 Undo/Redo도 차단합니다.

샘플레이트를 바꿨다고 기존 리전의 박 위치, 원본 오디오의 초 단위 오프셋·길이, MIDI 음높이·템포를 바꾸지 않습니다. 기존 오디오와 샘플 악기는 올바른 시간과 음높이로 재생돼야 합니다. WAV는 프로젝트의 선택값으로 렌더링하고 파일 헤더에도 같은 값을 기록합니다. 장치/브라우저가 지원하지 않으면 요청값을 저장해 성공처럼 표시하지 않습니다.

프로젝트를 열었을 때 필요한 레이트를 엔진이 지원하지 못하는 상황은 새 값을 적용하는 실패와 구분합니다. 파일의 원래 설정을 조용히 덮어쓰거나 다른 값을 같은 값처럼 표시하지 말고, 재생 상태와 선택 가능한 복구 경로를 알려야 합니다. 이는 Logic의 실시간 변환 설명을 그대로 구현했다고 주장하는 항목이 아니라 가락이음의 실패 처리 기준입니다. [A4]

### 4.3 입력·모니터링·녹음 보정

입력 장치와 테스트는 사용자의 명시적 조작으로 사용합니다. 설정 창을 열거나 장치 목록을 새로고침하는 것만으로 마이크를 켜지 않습니다. 선택된 장치가 사라지면 다른 마이크로 조용히 바꾸지 않으며, 시스템 기본 장치를 사용하겠다는 선택과 특정 장치 선택을 구별합니다.

`channelCount`의 1/2 요청은 모노/스테레오 스트림 수에 관한 것입니다. 오인페의 물리적인 1번 또는 2번 단자를 고르는 기능이 아닙니다. 입력 전처리 옵션도 요청대로 실제 적용됐는지 진단에서 확인할 수 있어야 합니다.

수동 녹음 보정의 양수/음수는 클립을 뒤/앞으로 배치하는 의미이며 범위는 **-1000~1000ms 정수**입니다. 자동 레이턴시 측정값으로 소개하지 않습니다. 녹음 시작 시 현재 적용값을 읽어 새 리전의 배치에 사용하고 기존 리전·녹음 파일을 재작성하지 않습니다. 시작점이 0 이전이면 타임라인 시작을 0으로 두고 그만큼 소스 오프셋을 늘려 남은 내용의 시간 관계를 유지합니다. 제외된 구간을 0으로 밀어 넣지 않습니다. 전체 녹음이 0 이전이면 빈 리전을 만들지 않고 알립니다.

소프트웨어 모니터링을 끄면 트랙의 I가 켜져 있더라도 라이브 입력이 출력으로 흐르지 않아야 합니다. 입력 테스트는 기본적으로 레벨만 확인합니다. 실제 모니터링 청음은 헤드폰을 사용해 확인하고 인터페이스의 직접 모니터링과 이중으로 들리지 않는지도 기록합니다.

## 5. 변경 적용·취소·복구 계약

이 절은 가락이음의 제품 기준입니다.

1. 창을 열면 현재 적용된 설정에서 편집 초안을 만듭니다. 선택 상자 변경만으로 장치·컨텍스트·프로젝트 저장값을 확정하지 않습니다.
2. **적용**은 한 번에 한 작업만 수행하고 적용 중 닫기를 막습니다. 녹음/녹음 준비/파일 처리 중에는 적용을 차단하고 이유를 표시합니다. 레이트를 바꾸는 Undo/Redo도 녹음 중에는 차단합니다.
3. 전환이 성공한 뒤에만 적용된 설정과 저장값을 갱신합니다. 프로젝트 샘플레이트는 성공한 변경 한 번을 한 프로젝트 편집으로 기록합니다. 장치 옵션은 프로젝트 이력을 만들지 않습니다. 로컬 저장만 실패한 경우에는 적용된 현재 세션 상태와 저장 실패를 구분해 알립니다.
4. 전환 일부가 실패하면 가능한 기존 엔진·장치 경로를 복원합니다. 복구도 실패하면 실제 사용 불가 상태를 표시하며 “이전 설정으로 복구됨”이라고 잘못 알리지 않습니다.
5. **취소/Escape/닫기**는 미적용 초안을 버립니다. 이미 성공한 적용은 유지합니다. 허용 여부를 기다리던 권한 요청이 늦게 끝나더라도 닫힌 창의 테스트가 다시 시작되지 않습니다.
6. 창을 닫거나 테스트를 중지할 때 테스트가 소유한 스트림/미리듣기를 정리합니다. 다른 녹음·모니터링 사용자가 같은 입력을 필요로 한다면 그 입력까지 끊지 않습니다.
7. 입력/출력 테스트는 초안 장치를 테스트하는지 현재 적용 장치를 테스트하는지 화면에 명시합니다. 테스트 성공을 설정 저장 성공으로 혼용하지 않습니다.
8. 출력 선택 API가 사용자 동작·권한을 요구하는 경우 해당 버튼에서 처리합니다. 저장된 장치 ID는 재검증이 필요할 수 있습니다. 미지원 환경에서는 운영체제 기본 출력을 사용하는 상태를 명시합니다. [W8][W9]
9. 브라우저가 출력 오류나 장치 변경을 보고했을 때 특정 출력의 ID를 확인할 수 없거나 실제 출력이 다르면 재생·모니터링 출력을 중지하고 ID를 유지합니다. 장치 목록 제한을 물리 분리로 단정하거나 다른 출력으로 자동 전환하지 않습니다. 사용자에게 연결·권한 확인 후 재적용 또는 명시적인 기본 출력 선택을 안내합니다.

## 7. 범위 밖 항목과 완료 보고

현재 구현 계약은 브라우저에서 제공되는 장치·처리 설정을 정확히 연결하는 데 초점을 둡니다. 다음 항목은 명시적으로 미지원입니다.

- ASIO/Core Audio 드라이버 제어판의 정확한 하드웨어 버퍼·클록·스레드 설정
- 인터페이스 프리앰프 게인·팬텀 파워·입력 타입·하드웨어 직접 모니터링 제어
- 물리 다중 입력/출력 채널 라우팅, 동시 다중 입력 녹음, 서라운드 출력·미러링
- 플러그인 지연 보상·저지연 모드의 자동 우회·전송별 예외
- AIFF/CAF 또는 24비트·32비트 float 직접 녹음/출력, 드라이버 지연 자동 보정

완료 보고에는 **연결된 기능**, **조건부 브라우저 지원**, **명시적 미지원**, **자동화 검증**, **실제 장치 검증**을 구분합니다. 이 문서의 구현 대상을 최종 코드와 대조하기 전에는 구현 완료 상태로 바꾸지 않습니다.
